## Publish and verify

Prefer `release:publish` for an authorized public release. It reads the version from root package.json; optional --version only asserts that identity. It refuses unrelated worktree changes, runs source checks before committing, waits for CI on the exact pushed source, and calls `release:preflight` immediately before creating a missing tag. Rerunning it resumes from remote CI, tag, or Release state only when the existing identity still matches. It never replaces a tag or published asset. Use the lower-level entries only for diagnosis, candidate-only work, or recovery that the primary path explicitly requests.

Before publication, review both root READMEs in a first-time user's reading order. Require the exact release stage and version link, the shortest supported install-and-open command, an observable first result and usable recovery, current update commands, necessary limits, and detailed platform support later in the page. Remove internal process links and implementation details that users do not need. Compare commands and claims with the installers, version manifests, current implementation, and exact-source acceptance. Review Chinese and English together. Check that the repository About, Topics, and package description describe the same current scope; planned agents and unsupported behavior are not release keywords. Local copy does not prove remote metadata, so inspect and report the actual GitHub state. Automate mechanical version, command, link, and platform checks in the primary TypeScript release entries; reserve manual review for meaning, ordering, and user clarity.

The tag workflow independently checks that the tagged commit belongs to the default branch and already passed CI. It selects the successful push CI run and an unexpired github-candidate by immutable artifact ID. CI already ran the five platform gates, archive assembly, final installation and preceding-release upgrade acceptance. The tag workflow downloads those exact archives, checks source/version and every size/hash, generates English notes, creates provenance, uploads all assets to a draft and publishes it. It does not rebuild or repeat platform acceptance. The primary script then requires an immutable complete Release, verifies its release and archive attestations, checks the signed whole-release asset manifest, downloads and hashes only the operator-platform archive with verified cache reuse, compares every target’s size/digest with the release set, and exercises the published installer and public update check on the operator's platform.

Before publication present version, tag, commit, archives/hashes, verification, and coverage gaps. Without publication authorization stop at the candidate. Upload the exact validated files, not manually repacked variants. Do not bypass failed tagged workflows with replacement tags; fix and issue a new version without overwriting a published one.

After publication download only the installers, manifests, and operator-platform archive missing from the external cache; revalidate every selected cached asset against GitHub size/digest and signed Release evidence. Keep all five target identities and remote size/digest checks; CI owns their installation and upgrade acceptance. Do not download foreign-platform archives for a host that cannot run them. Install the verified archive in a clean prefix; verify installed identity and run its update --check against the public endpoint. Confirm documented raw URLs work without login and match the clean, pushed verification source. Public-route acceptance executes those maintained installers; cached acceptance executes the signed release installers. Maintained installers may change after publication, but installed archives must still match the immutable Release. The exact-source CI owns CLI/Web and all target acceptance. If remote state is uncertain, inspect Release assets and hashes before uploading again.

## Finish

Read supported targets and runtime prerequisites from the versioned source; do not infer musl, Windows ARM64, or old-system acceptance. Report version, commit, platforms, gates, archive hashes, installation/update evidence, whether publication actually occurred, and the user's installation command. Candidates in dist/github are not externally installable Releases. Finish with [artifact cleanup](../../wombat-verify/references/cleanup.md).

The preflight follows GitHub's secure-use guidance: third-party Actions remain pinned to full commit SHAs, job permissions stay minimal, and verified assets are attached before a draft becomes public. GitHub artifact attestations bind archives to the hosted build, while SLSA recommends publishing and verifying provenance alongside release artifacts. Repository settings should enable immutable Releases and protect release tags when available; those server-side controls are inspected separately because the local preflight does not change GitHub settings.

## Recovery

After a repository rename, obtain archive attestation bundles from the current repository. Verify the exact signer workflow, tag, and commit against the package metadata at the immutable release source; historical signing identities do not change with the current namespace. Keep the current repository's signed release manifest and all size/hash checks. Never rewrite certificates or accept a broader owner identity to bypass a mismatch.

Use `corepack pnpm release:publish -- --status` to inspect remote state without mutation, then rerun `release:publish` to resume. A matching local tag whose push was interrupted can be pushed after preflight. Existing remote tags must match HEAD; active workflows can finish, complete immutable Releases proceed to verification, and failed tagged workflows require a new version. Draft or missing assets do not count as publication. Expired CI artifacts must be renewed for the same source before tagging. Authentication, network and unknown API failures stop the current stage; they are never treated as missing Releases or successful checks. Keep complete verified cache files across failures; temporary downloads and isolated installs are cleaned.

To rerun only post-publication acceptance, use `corepack pnpm release:publish -- --verify-published`. It requires the immutable published tag to be an ancestor of the checkout and uses the public latest-stable installer route, then checks installed identity and public updates. It never commits, tags, or republishes. When local GitHub transport is unavailable, add `--hosted`: the same entry dispatches the free public CI `published-release` scope on the exact pushed source and requires its dedicated installation/update job to succeed. This scope performs no builds or platform-suite reruns.
