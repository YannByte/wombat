# Review work over a period

Keep the requested dates, timezone, projects and model filters. Resolve relative dates once and state the resulting interval. Use [usage](usage.md) and [bounded selection](query-flow.md) for complete-scope totals and requested rankings. Batch these reads. Do not reconstruct the ledger from raw logs unless an audit or discrepancy requires it.

For what was done, use [conversation](conversation.md) to select relevant work and delivery evidence at the same usage view. Group only with explicit or reviewed work links. Separate requests, recorded activity and independently verified outcomes. A task ranking page is not the full statistical population.

Use [statistics](statistics.md) for distributions or contribution comparisons. For semantic review, disclose selected examples and coverage. Do not claim to have read every task from a sample.

Investigate only signals that can change the user's decision. Use [diagnose](diagnose.md) for the selected obstacle. Stop when the requested supported findings are available. If no actionable issue has evidence, say so. Omit cosmetic reminders and issues already fixed unless a regression check is needed.

Give the work, usage and most useful next action. Each recommendation needs a concrete target, action and observable recheck. Include cost only when useful or requested, with unpriced usage separate. A report request does not schedule future runs. Later comparisons need comparable workload and quality evidence, not just lower Token totals.
