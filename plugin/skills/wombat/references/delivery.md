# Verify a delivery

Keep the requested work and its acceptance criteria. Recover criteria from the user's request or governing project instructions. Do not invent requirements to make the review broader.

Use [conversation](conversation.md) only for missing intent, decisions or delivery locations. Read the current artifact and its actual version. Map each relevant requirement to an artifact and a check. Record missing, unrun, unavailable, failed and passed checks separately.

Prefer the existing project's validation entry. Run only the checks needed for the acceptance question, including required prerequisites. Source changes after a check require checking the affected result again. A successful edit, build or tool exit alone does not prove delivery.

For a discrepancy, show the requirement, actual behavior, location and smallest repair. After an authorized change, repeat the same acceptance case and relevant regression checks through [process and recheck](processing.md).

Conclude which criteria have evidence, which gaps affect acceptance and the exact next check. Do not turn this into a universal audit or infer correctness from the assistant's completion message.
