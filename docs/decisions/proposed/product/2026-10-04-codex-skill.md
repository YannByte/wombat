# 决策记录：Codex Skill 的任务入口与分发

中文 | [English](2026-10-04-codex-skill.en.md)

Status: proposed

当前精简范围替代本页的任务发送、多安装模式、自动检查历史与采用跟踪；保留其余证据约束和未完成事项。见[只读检查与单插件](../../implemented/architecture/2026-10-31-on-demand-checks.md)。

[CLI 与任务主 Skill 决策](../../implemented/architecture/2026-10-31-cli-task-skill.md)已取代此方案中的 Web、多入口和强制准备流程。下文采集与证据要求仅在存在当前 CLI 消费者时保留。

## 问题

旧技术草稿把已移除的 Wombat 内部生成、应用与恢复流程写入用户 Skill，并另行复制运行资产；没有区分 Web 浏览与 Codex 对话处理，也未覆盖当前账户和原生交接能力。用户要求删除旧草稿并基于 main 重新设计。

## 方案

本机此前已实现双入口、根级唯一 Skill 源码、插件资源与受管独立副本；已核验 Codex 0.160.0 发现及持久 Skill 队列接收、合成跨模块测试和中英文浏览器流程。这不代表已完成约定的真实任务和平台验收。当前操作归属 [CLI 指南](../../../guides/cli.md)与[用户 Skill](../../../development/plugin.md)；本提案承载理由与未完成验收。当前交付收敛为日志与 Hooks 采集、Skill 对话处理及 Web 展示解释。Web 选中对象后交给 Codex 的扩展与完整验收暂缓，不阻塞交付；已有实现和技术证据保留，后续评估是否取消支持。

### 产品定位

产品主线是后台采集、Skill 对话处理与 Web 展示。用户从 `$wombat` 对话进入，由 Skill 编排查询、解释、授权处理和复查；也可直接打开 Web 查看采集状态、趋势、任务及证据。两种查看方式共享内核数据，处理主线延续当前 Codex 对话。

Skill 入口的主线是用户目标。Web 支持浏览筛选、详情下钻和图表解释，Skill 可打开对应视图辅助说明；页面选择不作为本次任务派发入口，不改变对话的处理目标或授权范围。Web 选中后交接需要额外同步上下文并切换任务，当前先简化主流程，后续评估其保留价值。

五项任务为查看用量、定位任务、查看账户额度、检查配置、处理与复查建议。简单问题直接回答；较复杂问题先给结论，再提供依据和下一步。首次进入不展示功能菜单，也不默认执行全量体检。

Wombat 提供数据、证据、用户决定和检查结果；当前 Codex 负责理解问题、改写文件、审阅和恢复。Skill 只编排这两个职责。首版不增加 MCP 服务、模型 API 或独立执行作业。

### 当前交付的收敛顺序

围绕「提问 → 发现和建议 → 当前对话处理 → 查看变化」交付。先完善 Skill 对已有用量调查、输入轨迹、资源热点、周期复盘和配置检查的查询路由，再将少量发现与具体下一步组织成回答，最后按问题选择配置复查或用量对比。当前可用的部分事实也可以支持分析与建议；Codex 分开说明观察事实、可能原因和建议，相关限制随结论说明，不要求先完成全部连续观察。

复用 Rust 事实、生成契约和现有证据定位。用量候选与配置建议可以在一次回答中呈现，仍各自保留身份和验证方式；不为统一展示新增问题存储、资源实体、通用规则框架或执行服务。Web 复用既有详情与页头 Skill 使用说明，将概览、建议列表和详情中的派发按钮移出主要界面，保留既有接口与记录。

首批验收从一个用量问题定位任务，继续检查其项目，按授权处理具体对象并复查。核对连续提问保留目标与范围，数据部分可用时仍给出有依据的回答，并测量实际查询次数、响应量及首个有用结果时间。连续覆盖、闲置判断、资源清理和历史内容采用仍由[优化提案](2026-10-03-optimization-lifecycle.md)拥有，后续分别验收，不阻塞这条常用路径，也不因本批通过而宣称完整范围完成。

### 日志与 Hooks 采集

采集属于本次落地范围，与 Skill 和 Web 共享 Rust 内核。现有日志适配器负责历史补采、用量和安全操作信息；新增 Hooks 接收宿主实际提供的运行事件，改善实时性并补充日志缺失的观察。当前原生 Hook 注册观察只能证明注册、启用和信任，不能代替运行事件接收；参见[注册观察决定](../../implemented/architecture/2026-10-04-hook-registry-observation.md)。Skill 和 Web 不另建解析器、数据库或计量规则。

Hooks 接入优先使用已核验的插件能力；独立接入须明确用户选择，并保护已有配置。安装向导统一检查运行时、采集接入、宿主信任、历史数据准备和实际接收结果。Skill 只调用确定性接口与解释结果，事件接收不依赖模型对话持续运行。接收入口有超时、输入预算和私有存储；服务暂停时使用有界安全缓冲及重放，超限或缺失事件公开覆盖缺口。采集失败不修改提示词、工具输入或权限决定，不阻断用户任务。

日志和 Hooks 按来源、会话及原生事件身份关联；无可靠身份时保留关联未知，不能按文本或时间邻近强行合并。重放、补采、乱序和重复事件不能增加规范 Token 账本；工具事件不分摊成本。只保留产品需要的安全观察，不复制完整对话、工具输出、凭据或任意参数正文；沿用[隐私边界](../../../reference/privacy.md)。注册、实际接收、历史覆盖和数据新鲜度分别报告，收到工具事件不能证明某个 Skill 或规则已加载。

采集接收、暂停缓冲、状态查询与精确日志关联已有本地实现；macOS 上的隔离原生安装、发现、10 条未信任声明与卸载已核验。当前用户 profile 已通过 Codex 0.160.1 原生审核，10 条采集声明可信，其他插件声明保持原状；只读任务实际收到 SessionStart、UserPromptSubmit、PreToolUse、PostToolUse 和 Stop，并通过同一会话、已提供轮次身份、来源版本及固定 Token 账本复查。未执行的生命周期、完整真实项目场景与其他平台仍待验收。验收覆盖目标 Codex 的事件支持及信任、重复与乱序、并发和重启、暂停重放、缓冲超限、历史补采、卸载保留其他 hooks 与数据，以及中英文 Skill/CLI/Web 对同一观察的查询。单一平台或合成输入不能证明全部宿主支持。

### Skill 处理与 Web 查看

处理路径为明确用户目标 → 查询同一范围的数据与证据 → 当前 Codex 按授权处理 → Wombat 复查。复杂问题可打开对应 Web 视图，继续在原对话中解释和追问。

例如：“今天为什么消耗高？”Skill 先回答主要任务和模型，再打开相同日期与项目的用量图表，定位最耗任务及其轮次，并解释哪些操作与消耗有关、哪些无法归因。用户继续说“检查这个任务所在项目”时，复用已定位的项目，而非回到全局重新选择。

Web 可独立查看采集状态、用量、任务和配置证据。暂停的是选中对象后向 Codex 派发处理任务的扩展，不影响页面内的筛选、详情选择和 Skill 打开上下文视图。

### Skill 结合 Web 的详细解释

Web 是 Skill 可调用的解释视图。简单数字或单个问题直接在对话回答；趋势、多个贡献者比较、长任务逐轮查看、指令层级和复杂建议证据适合结合 Web。用户要求看详情时可直接打开对应视图；有助于理解的复杂问题可同时提供对话结论和本机页面入口，不要求用户重新导航。

打开时必须保持项目、来源、日期/时区、筛选、选中任务/轮次或配置/建议及版本。说明页面应看什么、对应哪个结论。页面关闭或浏览器无法打开时，对话仍给出可用结论；浏览器选择不自动回写对话，继续处理前核对新的明确选择。

本分支已实现 `web --context FILE --json` 和宿主 openView：按生成契约验证来源、项目及版本，并返回有效上下文。中英文合成任务已通过真实 Codex 连续对话、同版本 Web 核对和授权修改复查；完整真实项目与其他平台仍待验收。不能仅拼接 URL 就声称同版本跨入口已打通；CLI 日期截止不包含、Web 日期截止显示包含的转换复用产品实现。

已实现的受限打开视图操作接受页面类型、来源/项目、查询条件、选中 ID 及读取版本；宿主验证授权范围与版本，通过共享客户端初始化对应视图，再返回本机 URL 与有效上下文。字段由生成契约定义，不把前端内部 Route 作为公共接口，不接受任意路径、shell 或外部 URL。

版本过期时重新读取原范围并明确标记数据变化；固定版本无法在当前宿主授权范围确认时说明原因，不能静默显示最新结果。使用本机服务当前会话的访问链接，不公开连接令牌、不复用失效链接。由发起会话管理服务的启动和停止，既有服务只有在来源与项目范围匹配时才可复用。

### Web 接入与 Skill 配合体验设计

用户已授权进入开发。接入面板、状态接口与本地采集插件已有本地实现；以下内容仍是完整体验与验收要求，不能用局部实现代替验收。保留既有改动与用户数据。

#### 参考与取舍

参考 COT 的“选择采集方式 → 接入 → 历史准备 → 开始查看”流程。COT 当前源码同时提供 Hooks 和只读日志两种路径，安装后可复用已发现的接入；见[接入向导](https://github.com/cot-intelligence/cot/blob/6b51be8943371d20c45d71bff9cf13ebd3461605/src/components/onboarding/Onboarding.tsx)。Wombat 采用统一向导与针对失败步骤的恢复，保留既有数据可用时直接查看的路径。Skill 与实时采集分别判断，不把安装成功当作数据就绪。

COT 的接入界面将 no_events 和 stale 也归为 installed，随后显示 Connected；见[状态映射](https://github.com/cot-intelligence/cot/blob/6b51be8943371d20c45d71bff9cf13ebd3461605/src/components/onboarding/steps/ConnectHooks.tsx)。Wombat 分别报告声明、信任、实际接收和历史覆盖。源头没有提供的事件、历史内容与资源加载仍保持未知，不采用完整会话正文存储。

#### 页面结构与视觉

保留概览、任务、指令、扩展和建议的工作区结构。页头增加“接入与采集”和“配合 Skill 使用”入口；前者查看本机服务、采集接入与历史准备，后者解释安装、调用及连续提问。概览在需要准备或恢复时展示一条可关闭的提示，数据可用时直接显示分析内容。关闭提示只影响展示，不能改变接入和数据状态。

采用现有工具界面风格：白色背景 #ffffff、正文 #0d0d0d、次要文字 #6b6b6b、分隔线 #e6e6e6、信息色 #507e95、提醒色 #875925。字体沿用系统中文和英文字体；页面标题 27px、区块标题 17px、正文 14px。桌面向导左侧显示步骤，右侧使用纵向状态列表与一个主操作；窄屏改为单列，长路径和状态说明换行。深色模式复用现有语义变量，不固定浅色背景。交互保留键盘焦点、可读状态文字和减少动态效果偏好。

#### 首次接入

Web 打开前，本机 Wombat 运行时须已安装并能启动；安装说明串联到同一向导，不假设一个尚未运行的页面能安装自己的服务。首次进入以实际状态提示缺失步骤；已有可用历史不强制重跑向导，也不依赖浏览器中的首次运行标记。

| 步骤 | 用户看到什么 | 操作与完成依据 |
|---|---|---|
| 选择采集方式 | “实时采集与历史补采”或“只读日志采集”；说明各自可观察范围 | 支持的宿主推荐前者；不支持 Hooks 时明确受限。只读模式保持原生 Agent 配置，仍可使用 Skill |
| 完成接入 | 本机服务、Skill 发现/启用、Hooks 声明/信任分项状态 | 展示受审接入方法、具体变更和版本；已有有效接入复用。用户在 Codex 完成原生信任后重新检查；Skill 缺失不阻断数据查看 |
| 准备历史 | 来源、授权项目、已可查看结果与失败项 | 复用现有增量索引和来源同步，不另建导入数据库。只处理明确范围，已有结果先可用；无历史与读取失败分别说明 |
| 开始使用 | “查看数据”、已确认的 Skill 调用方式、自然语言示例 | 查看不等待一次额外模型任务；Skill 使用与事件接收独立确认，尚无运行事件显示“等待首个事件” |

只读日志采集同时读取历史和后续追加，实时性以实际同步状态为准。

本机接入由一个拟新增的确定性入口协调检查、安装准备和恢复，复用已有安装与采集模块；命令名和协议字段在能力核验后冻结。Web 提供步骤说明与复制操作，浏览器不执行任意命令。插件管理仍由 Codex 负责，Hooks 信任仍由原生宿主负责，不能通过复制命令或打开页面认定接入成功。公开基础插件与本机采集版的渠道限制沿用安装方案。

#### 日常状态与恢复

| 观察项 | 必须分开的状态 | 页面动作 |
|---|---|---|
| Skill | 未检查、未发现、禁用、可用、多个实例、检查失败 | 针对当前项目重新检查、查看安装说明；调用名采用原生发现结果，不能固定假设为 $wombat |
| 实时采集 | 未接入、待信任、已注册且等待事件、已接收、暂停、失败或检查未知 | 展示检查时间与实际最近接收时间；按具体原因修复或恢复，不能从暂时无事件推断断开 |
| 历史数据 | 准备中、可用、部分可用、确实无日志、读取失败 | 查看已有结果、查看失败来源、重试对应范围；等待上限到达仍说明准备状态，不改称没有历史 |
| 当前视图 | 固定或当前、更新中、有新版、旧结果、版本过期 | 显示来源范围和实际数据截止时间；显式应用新版，保留原问题与对象位置 |

配置状态、事件接收、覆盖与新鲜度由共享接口提供，页面不组合出一个泛化的“已连接”标签。未来持续采集有自己的生命周期：关闭页面不宣称停止采集；暂停采集时历史仍可查看，缓冲重放和缺口独立显示。状态刷新有界，离开页面停止该页面的请求，后台采集不依赖持续运行的模型对话。

#### Skill 与 Web 的往返

从 Skill 开始时，Codex 先回答原问题；需要图表或长任务证据时，打开对应 Web 视图。页面清楚显示当前项目、来源、日期/时区、定位对象和数据时间；版本等技术信息放入可展开依据。浏览器可继续查看，处理与追问延续原 Codex 对话。切换 Web 筛选只改变浏览，不能自动改写对话授权。

从 Web 开始时，用户可直接查看数据，也可打开“配合 Skill 使用”学习调用方式。提供按当前页面主题组织的通用问题，例如“解释今天用量的主要贡献者”“检查当前项目的配置建议并说明依据”。只有确认可用实例后才展示其准确调用名。可复制通用示例，不生成绑定页面选中对象的处理任务，不发送到 Codex，也不创建新对话。

建议页的当前操作与展示由 [UI README](../../../development/architecture.md)维护。处理主线使用当前对话，Web 保留查看与复查；旧派发接口与记录暂时保留，是否删除支持另行评估。详情继续展示问题、位置、证据、检查口径、用户决定和复查结果，不推定已经修改成功。指令和扩展页保留筛选与详情，任务页保留轮次、事件和同版本下钻。

#### 中英文、失败与设计验收

接入步骤、状态、错误恢复、Skill 示例及页面说明同时提供中文和英文。语言切换保留采集方式、步骤位置、项目、来源和读取版本；来源原文、模型名、稳定 ID、路径和协议值不翻译。示例区按实际实例给出调用方式，不能把插件名与独立 Skill 名混为一谈。

验收至少覆盖首次无数据、已有历史直接查看、只读模式、Hooks 待信任、已注册无事件、首个真实事件、服务暂停/恢复、来源部分失败、Skill 缺失或多个实例、浏览器失败及版本过期。中英文分别完成“Skill 提问 → Web 查看 → 原对话继续 → 复查”，并核对页面筛选未扩大授权。验证窄屏、深色模式、键盘与状态变化；复制示例不触发扫描、安装、任务派发或模型请求。状态接口与安全 Hooks 接收已有本地实现。上述常用原生事件已通过实际执行验收；其他生命周期和完整真实项目对话场景仍待验收，设计或合成测试不作为完整交付的证据。

### 中英文与跨入口语言

Web 当前已支持中文和英文，并使用共享文案服务与本机语言偏好；现有 Web 交接请求携带页面 language，用于选择交接提示模板。这不证明 Codex 后续回答已按该语言完成验收。现行优先级和翻译边界以[产品语言](../../../i18n/product.md)为准，Skill 复用现有能力。

Skill 的解释语言优先遵循用户明确要求，否则跟随当前对话；若接收已有 Web 交接且没有新的明确要求，承接任务仍以交接时的页面语言作为回答偏好；该路径暂缓扩展，不属于本次完整验收。中文和英文共用一个 Skill、同一组查询与处理流程，不能分别维护两套业务指令，也不能由界面语言推断时区、来源或项目。

Skill 打开 Web 时默认沿用 Web 既有语言偏好。用户明确要求中文或英文页面时，使用已支持的 web --lang zh|en；拟新增的受限上下文打开接口也应支持同一语言选择。复用已打开页面时保留用户当前选择，不因继续对话或重新定位对象强制切换语言。页面切换语言不重新初始化数据、不改变筛选、选择、证据版本或授权范围。

新增页面、初始化提示、错误恢复和交接文案通过 @wombat/client/locale 同时提供中英文；Skill 的自然语言解释由 Codex 按回答偏好生成。JSON 字段、状态码、稳定 ID、模型名称、路径及来源原文保留原值，引用用户内容时不隐式翻译。中英文验收分别覆盖首次初始化、详细解释、语言切换后连续追问及当前 Codex 对话的处理与复查，并核对数据与对象一致。

### Skill 入口与数据初始化

初始化是执行用户任务时的准备步骤。Skill 调用当前 CLI，复用 Rust 内核的来源发现、索引恢复和增量同步；不另建数据库、首次运行标记或日志解析器。完整产品流程见[初始化与持续发现](../../rejected/product/2026-10-02-progressive-initialization.md)。

进入时先确定意图与所需数据，再核对运行入口和对应能力。仅提到 Skill 名称而未给任务时，可以说明运行入口是否可用并给一个自然语言示例，不启动完整历史扫描。同一对话已有成功核验时复用入口信息，能力或路径变化后再检查。

| 请求 | 初始化动作 | 不应依赖的准备 |
|---|---|---|
| 用量、任务、关联历史 | 对原问题执行一次小分页实时查询，自动发现来源、恢复索引并同步 | 不先强制 refresh 保存快照，不扫描全盘找项目 |
| 当前配置与静态建议 | 按当前或明确项目读取清单/建议；历史尚未齐全时先解释静态事实 | 不把全部历史读完作为静态检查前提，不把关联未知当作零次使用 |
| 账户额度 | 独立 account read，按用户要求 refresh | 不等待日志同步、项目发现或索引初始化 |
| 既有 Web 交接处理（暂缓扩展） | 先核对传入目标、范围与内容版本，再按需查询和复查 | 不从全局重新选对象，不因初始化失效而扩大范围 |
| 离线或固定快照 | 使用已有缓存/指定快照，保留原版本 | 没有缓存时不能隐式启动扫描或下载价表 |

用量查询由真实返回状态决定后续动作：

| 可观察状态 | 对话行为 |
|---|---|
| 完整 current 或 fixed | 回答原问题，保留版本以继续下钻 |
| 首次临时结果，initialScan=true 或覆盖未完整 | 可先定位已有任务，明确总量暂不完整；不输出全局排名结论或“未使用”判断 |
| SYNC_PENDING，无可用结果 | 说明首次历史正在准备；对同一问题最多再等待一次 fresh，之后结束等待并保留原问题 |
| 有已提交结果但 syncing/stale | 先回答可确定部分，给出数据时间与更新状态；需要最新结果时再有界等待 |
| failed 或 partial | 区分可用来源、旧结果与失败项，保留有效事实；给出对应错误的恢复方式 |
| 已完成同步但无数据 | 分清没有支持的日志与当前筛选无匹配，再决定是否调整日期或由用户指定来源 |
| 版本过期或格式未知 | 过期重读原范围并说明变化；未知格式保留数据并报告，不能自动清空或迁移 |

当前普通查询最多等待约 2 秒，fresh 最长约 10 秒且可能返回 SYNC_TIMEOUT；一次超时不代表扫描停止或已失败。没有提交索引时 --cached 返回 NO_SNAPSHOT，不能建议用户依靠空缓存完成任务。默认不会在聊天中无限跟进；用户明确要求继续等待或监控时再另行定义有界持续行为。

首次等待结束后可提供本机 Web 入口，继续显示已有的同步状态和临时任务；用户下一轮“继续”时复用原问题、来源、日期和选择，再查询即可。打开页面不额外重建索引，停止页面等待或取消一次 CLI 请求也不宣称取消共享服务。项目级进度事件尚未实现，不编造百分比、剩余时间或项目完成数量。

状态判断只消费产品 JSON。若试用证明组合状态难以可靠解释，才在共享接口补窄的就绪投影并同步 CLI/Web；不新增由 Skill 自行检查数据库、索引文件或服务进程的“初始化完成”规则。

### 用户任务与回答

| 用户表达 | 默认行动 | 用户得到什么 |
|---|---|---|
| “今天用了多少，主要花在哪里” | 按用户当地日期与时区查询汇总，再按问题选择任务、模型或项目排行 | 总 Token、官方标准 API 等价金额、主要贡献者、未计价与覆盖缺口 |
| “找昨天那个任务，看看最耗的一轮” | 搜索或按完整 ID 定位，再在同一读取版本下查轮次与操作记录 | 准确任务和轮次、匹配范围、相关操作；无正文证据时说明限制 |
| “Codex 额度还剩多少，何时重置” | 独立读取账户；用户要求最新时刷新 | 账户读取状态与时间、实际窗口和重置时间、余额及限制；缺失或过期保持未知 |
| “检查这个项目的 AGENTS 和扩展” | 默认当前工作目录，读取配置清单、建议及选中对象证据 | 问题、位置、依据、建议处理顺序和无法判断项 |
| “处理第一项，再检查” | 复用上文对象与范围，由当前 Codex 修改，再逐规则复查 | 实际文件变化、复查结果、残留问题；后续使用观察另行说明 |
| “这项保留，不再提示” | 确认指向的建议，记录符合接口的原因 | 明确的用户决定；检查事实仍独立保存 |

默认回答采用“结论、依据、下一步”的自然语言段落。只在需要比较时用表格，只有任务数量超出展示范围时说明分页。所有汇总使用内核返回的完整范围结果，不能从前几条排行重新求和。

“第一项”“继续”“刚才的项目”沿用本轮对话的完整 ID、范围和版本；不能重新排序后猜测对象。可推断的日期、时区和当前项目直接采用并简要说明。范围歧义会改变结论或写入目标时才追问；额度查询无需询问项目。

### 与 Web 的分工

| 场景 | Web | Skill |
|---|---|---|
| 了解使用情况 | 趋势、筛选、构成、列表和详情 | 根据问题选切面，解释主要贡献者，必要时继续下钻 |
| 配置检查 | 浏览指令树、扩展、建议和处理记录 | 围绕当前项目或指定对象串联证据与建议 |
| 发起处理 | 展示 Skill 使用说明与复查入口；派发接口与记录保留待评估 | 在当前 Codex 对话处理已授权对象；显式要求新任务时才交接 |
| 判断解决 | 显示逐规则复查与后续观察 | 改动后调用同口径复查，解释通过、残留与无法检查 |
| 查看额度 | 常驻摘要与详情窗口 | 按问题解释账户状态、窗口及限制 |
| 持续浏览 | 保留筛选、展开、语言和页面状态 | 保留当前对话所需的对象与证据上下文 |

Web 已发送的任务应继续在接收的 Codex 任务中处理。Skill 不再次发送给自己，也不增加额外生成步骤。发送模板携带目标、证据版本、回答语言及原生 Skill 名称；队列同时传入具体 Skill 引用。接受请求只证明绑定的请求已被接收，不证明模型已使用或处理完成。

### 复用当前能力

现有业务入口和限制以 [CLI 指南](../../../guides/cli.md)为准。方案串联已有事实与规则，不另建计量 DTO、执行服务或日志解析器；Web 上下文打开复用这些契约，既有交接暂缓扩展。

### 共同的处理与复查流程

直接检查：确定当前项目与来源 → 读取清单和建议 → 按需核对位置与证据 → 给出可处理顺序。仅请求检查时，到结论即可完成。

当前对话处理：复用选中建议 → 核对适用项目约定、当前内容及共享文件范围 → 当前 Codex 完成授权修改与相应验证 → Wombat 逐规则复查 → 报告修改、复查和残留。用户已经明确要求处理时，不为同一范围重复索要批准；需要扩大目标或改变行为时，先给出具体可审阅的选择。

既有 Web 交接（暂缓扩展，保留安全约束）：读取传入的项目 cwd、目标、内容指纹和证据版本 → 核对当前目标 → 在接收任务中处理 → 复查。版本失效或文件变化时重读原范围并说明变化，不沿用过期依据。未修改项也说明原因；不能用“请求已接受”证明处理完成。

用户明确要求另起任务时，使用现有 preview/send。展示项目、文件、共享影响和实际额度检查后绑定 `selectionVersion`。省略 suggestion 会包含所选范围的全部待处理建议，而非当前页面，所以批量操作必须保留明确选择。送达未知时先查已有任务，不能自动重发；关闭 Wombat 不代表取消 Codex 任务。

撤销修改由当前 Codex 依据实际差异和现有内容处理，保留用户后来改动。Wombat 的历史和用户决定用于解释与复查，不承担文件备份、回滚或执行回执。

### 证据与状态

用量链保留来源、日期、时区、筛选、snapshot ID 和完整任务/轮次 ID；配置链保留项目、readView、decisionRevision、规则参数和建议 ID。普通查询返回的短期版本也可用于连续下钻；固定快照查询不混入来源根或刷新选项。版本过期后重查原范围并说明变化。

配置当前文件不能解释未知版本的历史任务。AGENTS 原生加载、Skill 可用目录、近似观察使用、定向文件读取、MCP 调用结果、Hook 注册分别描述；未观察到不能证明闲置，可用不能证明已使用，注册不能证明已执行。关联轮次的 Token 不能宣称某个扩展独占的成本。

退出码 2 且有有效结果时输出受限结论，披露部分来源失败或同步状态；首次 `SYNC_PENDING` 可进行一次有界等待，之后保留状态并给出重试方式，不无限轮询。缺失、零、未计价、未知和隐藏分开。用户要求离线时使用已有缓存/固定快照或关闭自动补价；普通实时查询可能下载官方缺价表。

账户身份、额度和活动各有状态及读取时间。保留实际多窗口、多桶、原精度余额和限额，不固定为五小时/七天。窗口 model 是展示信息，发送适用性依据已有交接检查；低余额提示与明确阻止区分，未知状态不新增阻止条件。重置时间经过不证明额度已恢复，只读权益不提供重置操作。

复查通过只证明当前可检查规则不再命中。之后自然任务中的近似使用观察与是否遵循内容、质量改善和费用节省分开；不能为“验证采用”自动创建额外消耗任务。

### Skill 结构与安装方案

研究后的建议是“用 Skill 编写任务流程，用仅含 Skill 的插件正式分发”。官方支持这种最小插件形态，MCP 仍按需求评估。本机采集版另增加已核验的 Hooks 资源；当前官方仅支持手动安装的 Codex 桌面 Hooks 插件，含 Hooks 的插件不具备公开目录资格，不能宣称两种包可用同一发布渠道。用户本机安装 Wombat 发行包，随后通过 Codex 插件安装界面安装轻量工作流包；本地 marketplace 用于首版试用，公开目录需要后续提交与审查。[官方插件打包](https://developers.openai.com/plugins/build/plugins)

用户插件资源的唯一源码归属为根级 [plugin/](../../../development/plugin.md)，Wombat Skill 放在 plugin/skills/wombat/。仓库 .agents/skills/ 继续只放开发工作流。独立安装和插件打包复用该源码，插件生成宿主标准的 skills/wombat/ 资源布局，不另维护一份 Skill。构建已从该源码生成独立资源、插件及本地 marketplace。按当前标准使用根 plugin.json；所支持的 Codex 版本若需要 .codex-plugin/plugin.json，构建从同一元数据生成兼容清单，不能手工维护两套描述。[官方格式](https://developers.openai.com/plugins/build/plugins)

Skill 使用短入口加按需参考：入口负责意图、运行入口和必要上下文；启动/初始化、用量/任务、账户、配置证据、处理/复查及 Web 解释有对应参考，相关任务才读取。辅助脚本只用于可重复且需要确定性的机械步骤；正文不复制整个 CLI 手册。[官方 Skill 组织](https://learn.chatgpt.com/docs/build-skills)

基础插件仅包含 manifest、Skill 资源、必要图标与许可；本机采集版另包含受审 Hooks 声明及最小接入脚本，复用同一运行时，不复制日志解析器。复用同机 Wombat 的 CLI、Rust 内核及内置 Node；安装插件并不安装本机产品。发行包与插件各有明确版本及所需能力，运行通过协议和功能检查匹配，不要求永远同版本，也不把当前能安装等同于已可查询本机数据。

可发布的插件不嵌入某台机器的绝对路径。运行优先使用用户明确指定的入口，其次发现已安装稳定启动器；通过能力核对后在当前对话固定该路径。找不到或版本不满足时解释缺少的能力并给出安装/升级方法，不自动下载、升级、读取登录凭据或切换数据范围。远程宿主没有该机器的日志时明确说明本机能力不可用。

正式插件的安装、启用、更新与卸载由 Codex 插件管理器负责，Wombat 不改插件缓存或重复维护其安装记录。Wombat 更新其产品运行时，不自动覆盖宿主管理的插件；双方版本不同按能力判断，缺能力时明确受限。

本机离线与开发试用使用 wombat skill install / status / uninstall 窄接口。install 只从已安装发行包的受审资源注册独立 Skill，不重做 GitHub 克隆、市场发现或跨 Agent 安装器。默认用户路径改为 ~/.agents/skills/wombat；显式自定义路径需验证目标宿主发现。[官方发现目录](https://learn.chatgpt.com/docs/build-skills)

目录存在差异：openai/skills 中的安装器和 vercel-labs/skills 仍可使用 ~/.codex/skills，不能据此认定它已失效，也不能把它当作所有新宿主唯一默认。status 或交接应通过按 cwd 查询 skills/list 确认实际 enabled 实例、路径、重复同名和解析错误；目标本机协议是否支持这些操作须单独验证。

本机安装保存来源、固定版本、内容哈希和管理标记，记录位于受管副本内的 .wombat-install.json；不改第三方管理器锁文件。仅使用受管理副本，不提供开发链接模式；链接目录及链接目标均受保护。自定义同名 Skill 不覆盖；明确替换受管理安装时先暂存校验再原子切换，失败保留上一安装。

status 分别报告文件已安装、宿主已发现/启用、CLI 能力匹配和数据可用状态，这四项不能合并为“安装成功”。uninstall 只移除本入口拥有且未被改动的 Skill 副本，不删链接目标、产品数据或其他管理器安装。插件和独立安装同时出现时说明重复，保留用户配置，并在交接中绑定具体 enabled 实例。

### 暂缓的 Web 选中后交接

本节保留既有技术依据与安全约束，不代表本次交付要求。正式取消支持前需单独评估入口、契约和已有记录，不以本次范围收敛删除用户数据。

官方 App Server 推荐在文字包含 Skill 调用标记的同时，传入带 name/path 的 skill input item，让宿主直接注入指令；先通过 skills/list 取得目标 cwd 下实际启用的实例，名称/路径以返回值为准，不从插件缓存猜测。[官方接口](https://learn.chatgpt.com/docs/app-server)

持久交接继续使用 thread/queue/add。Codex 0.160.0 的隔离原生探针已确认队列接受 text 与 skill 引用；插件实例的实际名称为 wombat:wombat，独立实例为 wombat。发现和发送采用返回名称/路径，未以 turn/start 替换持久链路。探针没有执行模型任务，不证明修改完成。

Skill 缺失、禁用、同名冲突或协议不支持时，在发送前公开“可交接，但不能确认采用此 Skill”，提供安装或选择实例的具体入口。用户选择沿用现有 Codex 交接时保留原目标与证据，并明确受限；不能自动安装、启用或发送第二个任务。明确支持后才宣称接收任务采用了 Skill。

### 实施任务拆分

以下工作包划分实现与验收责任；本机已交付范围及未验证边界以任务证据为准。沿用独立 worktree；实施前重新获取 main 并核对基线差异，保留本分支已有设计和用户改动。推荐每个工作包形成一个可独立审阅的 PR；跨模块接口与对应入口在同一工作包交付。

|---|---|---|---|
| S1 | 核实宿主与冻结最小契约：检查目标 Codex 的插件格式、实际 Skill 发现目录及按 cwd 的 skills/list；核对 CLI JSON 状态、运行入口及采集事件能力 | 无 | 合成目标下的版本/能力记录；定义受限打开视图所需字段与降级边界，不猜测缓存路径；保留已有队列探针，新增交接验收不阻塞交付 |
| S2 | 编写 plugin/skills/wombat/：短 SKILL.md、宿主元数据及按需参考，覆盖启动/初始化、用量/任务、账户、配置、处理/复查和 Web 解释 | S1 的 CLI 能力核对 | 直接调用、间接触发、误触发与连续追问；中英回答；空索引、临时/部分结果、账户独立读取、离线无缓存和有界等待。每项声明都对应可执行 CLI，不恢复旧执行流程 |

S2 的 Web 参考先写清当前可用能力和限制，S5 落地后同步更新，避免 Skill 提前承诺接口。S6 暂缓，不新增 Web 选中后交接的完成门槛；已有链路保留原目标、证据及失败约束，不能据此宣称完整行为已验收。

建议按三个里程碑收口：A 为 S1—S3，获得可实际安装、查询和解释的 Skill 插件；B 为 S5，完成 Skill 结合 Web 的详细解释；C 为 S4、S8、S7，完成独立离线试用安装、日志与 Hooks 采集及当前主线验收。S4 不阻塞插件试用，但完整安装验收前必须完成。S6 不阻塞任一里程碑。

改动归属保持现有边界：Skill 内容在 plugin/skills/；参数与展示装配在 cli/；本机 Codex 发现/队列通信和进程生命周期在 client/src/node/codex/；Web 授权与连接在 web/；页面选择和翻译在 ui/ 与 client/src/locale/。公共 DTO/状态按现有生成链路维护，涉及核心业务校验时归 core/；协议命令、输入 JSON 及不支持情况由 S1 证据约束，不由页面自行猜测。

初始化和语言是每个相关工作包的完成条件。优先复用已有状态；只有试用表明无法可靠解释时才补共享就绪投影，并同步无交互 CLI/Web。CLI 安装与发送采用独立失败/取消语义，浏览器语言不改变扫描范围，未知额度与临时历史不作为扩大权限或自动安装的理由。

验证按工作包选择：S2 做元数据、引用和自然语言行为评测；S3/S4 做隔离安装、更新归属和归档资源验证；S5/S8 涉及共享接口时先构建，再做类型/契约、定向跨模块测试与真实浏览器/原生 Codex 验收。S7 对最终构建运行完整测试和对应发行检查；Rust 或依赖实际变化时增加相应格式、clippy、许可检查。每个 PR 记录已测范围、证据位置及未完成边界，静态检查不代替宿主与真人验收。

### 交付顺序与验收

| 阶段 | 交付 | 完成证据 |
|---|---|---|
| 本轮设计 | 清除旧草稿与失效入口，完成能力对照、交互流程和安装提案 | 双语、链接、仓库检查；不等于行为验收 |
| 首版实施 | 短 Skill、按需初始化、仅含 Skill 的插件与本机试用安装 | 宿主实际发现、目录冲突保护、入口能力匹配、各管理器更新归属、卸载保留数据 |
| 采集与 Web 解释 | 日志补采与 Hooks 接收共享内核；Skill 按上下文打开 Web | 事件关联不重复计量、失败恢复、实际接收状态；查看保持范围与版本，当前对话继续处理与复查 |
| 真人试用 | 分别用中文、英文完成五项任务和连续追问 | 实际结果、错误恢复、调用次数与输出体积记录；只收集合成或审查后的材料 |

真人验收必须覆盖空索引与临时结果、旧结果更新、账户不等待日志、配置历史未齐、离线无缓存、首次等待后继续原问题、未安装或能力不匹配、重复同名/禁用 Skill，以及 Skill 打开指定 Web 视图并继续原对话、浏览器失败时的对话回答、两边版本不一致提示、当地跨日查询、同版本排行下钻、过期读取恢复、账户多窗口与读取失败、当前项目与日志根不同、共享配置、用户保留/不适用、修改后仍命中和无法检查，以及同名自定义 Skill 的安装保护。

若试用发现重复查询带来明显上下文或耗时开销，再设计共享的有界汇总接口，并同步 CLI/Web；不能在 Skill 内新增统计或建议规则。检查覆盖与实际结果分别记录，不宣称优化节省、平台支持或自动加载已经验收。

## 考虑过的方案

- 复制 Web 页面导航：对话需要先判断目标，逐页遍历增加无关查询，因此采用任务组织。
- 延用旧草稿并复制运行资产：业务职责已变化，重复运行资产增加版本维护，改用已安装产品。
- 自有安装器承担正式分发：本机试用可行，但当前官方推荐可复用 Skill 用插件分发，因此宿主拥有正式安装生命周期；不重建跨 Agent 包管理器。
- 立即加入 MCP：目前 CLI 已覆盖业务查询，插件可只含 Skill；MCP 待多宿主或实测开销依据。

## 验收条件

当前交付按 S1—S5、S8、S7 的职责与验收条件执行；S6 暂缓，不作为完成门槛。真实对话试用须分别以中英文覆盖用量/任务连续追问、独立账户、配置证据、授权处理复查及 Web 上下文解释；触发行为、部分/空/离线结果、有界等待、改动安装、原生接受、实际修改和复查分别记录。本机 macOS 证据不证明其他平台或公开 marketplace 发行，部分交付仍保留 proposed。
