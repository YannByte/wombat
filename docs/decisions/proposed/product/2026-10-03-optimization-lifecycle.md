# 决策记录：完整优化闭环与运行证据

中文 | [English](2026-10-03-optimization-lifecycle.en.md)

Status: proposed

当前精简范围替代本页的任务发送、多安装模式、自动检查历史与采用跟踪；保留其余证据约束和未完成事项。见[只读检查与单插件](../../implemented/architecture/2026-10-31-on-demand-checks.md)。

## 问题

静态配置事实和局部界面测试不能证明完整优化闭环。尚缺运行事件、连续覆盖、可靠历史版本与完整跨平台旅程，不能把不可判断当作无问题，也不能把关联用量或文本变化当作节省。本提案统一拥有原五入口规格和状态表中尚未完成的要求；整理文档不缩减已确认范围，也不表示重新启动产品实施。

## 方案

沿用共享 Rust 事实与生成契约，在 Web 和无交互接口共同补齐以下能力。当前界面、字段和操作分别由 [UI README](../../../development/architecture.md)、[契约](../../../development/contracts.md)和 [CLI 指南](../../../guides/cli.md)维护；发送与执行的职责由[原生交接决定](../../implemented/architecture/2026-10-03-native-codex-handoff.md)维护，不在此复制已交付机制。

### 运行观察与内容依据

G01：补齐可靠 Skill 调用、Hook 运行及 MCP 提示词事件。调用、读取、加载、连接分别表达；独立失败与重试各计一次，稳定事件重放去重，不合并父子任务的独立活动。完整覆盖无事件才显示0；不完整覆盖只能显示已观察次数，无依据显示未知。现有工具/资源事件及 Skill 观察子集不代表全部完成。

G02：从可信完整定义取得 MCP 文本，记录版本和测量方法；不得为取得定义启动服务。缺失、截断、超限或解析失败保留未知。AGENTS/Skill 现有阈值与分词字段只由契约维护，不再建一份规则表。

G03：提供“自动加入的上下文”盘点入口，展示可靠来源、实际内容版本、范围、体量和已记录次数。盘点本身不是缺陷，不能从次数或体量预测节省。

G04：同请求重复注入必须有 request/context、压缩代次、来源历史内容版本和两个实际纳入位置；去除事件重放，不混合父子、新请求或压缩代次。完整静态块、共同目录、当前文件或重复读取不能替代这些证据；修正后用可比真实上下文复验。

### 连续观察与资源候选

G05：Skill/MCP 闲置需要稳定身份、连续启用、至少30个连续24小时的完整观察（含边界）且无使用，涵盖全部适用项目和客户端及失败尝试。可靠 Skill 读取也阻止判为完全闲置，但不计为调用。安装日期、文件日期、导入历史及筛选窗口内零次不能建立连续覆盖。

G06：worktree、临时文件和缓存候选需至少14天完整观察、无活动、任务结束且无运行任务。排除主目录、固定或锁定工作树及保护对象，核对未跟踪/忽略材料、修改、提交与恢复条件；缓存还需可信归属和可再生成依据。移入可恢复区不等于释放空间，清理与恢复仍由用户在 Codex 决定。

G07：连续快速检查初始参数为同一运行任务至少5次、间隔不超过2秒、无新输出且无输入或及时响应要求。整体至少5个可分析任务、3个命中任务、2个命中日期，观察终点前最近7天仍有命中。排除必要保活、交互、长等待和证据缺口；没有可修改位置只展示依据。规则参数须版本化并覆盖边界反例。

### 自然采用与用量对账

G08：可靠历史版本下区分未观察到、版本未知、确认采用和同类问题再现；不为验证收益额外运行模型。优化任务实际用量按稳定计量身份与历史去重，不把任务总量、关联用量重复相加，未知不补零。前后文本比较只在同范围、同方法下成立，不宣称因果收益。检查事实与用户决定保持独立，复查不撤销保留或不适用决定，文件消失或不可读不自动解决。

### 完整产品旅程

G09：补齐 Windows Hook、跨平台安装和完整故障旅程；发行操作由[发行 Skill](../../../../.agents/skills/wombat-release/SKILL.md)维护，目标平台的长期取舍由 [GitHub 分发决策](../../implemented/architecture/2026-10-04-github-release-distribution.md)维护；桌面范围及取舍由[本机 Web 决定](../../implemented/architecture/2026-10-01-local-web.md)维护，不将 Tauri 并入本轮 Web/CLI 修复。首次读取和项目级进度归[初始化提案](../../rejected/product/2026-10-02-progressive-initialization.md)，规模目标归[实时提案](../architecture/2026-09-30-live-usage.md)。

五页连续跨项目操作须保留范围、筛选、准确轮次、列表、焦点与查看位置；迟到响应、刷新和语言切换不能覆盖新选择。中文/英文、320/390/1280/1440px、原生下拉键盘、取消/关闭、未知送达、并发和版本变化均需实际浏览器旅程。补齐账户摘要、真实耗尽、过期限制和各分区独立降级验证，不从本机用量推导额度。

帮助覆盖 Token/金额、使用次数、文本体量/预估 Token、关联用量和常见问题；全局默认收起，局部解释直接可达并恢复焦点，不向普通用户要求内部开发标识。金额精度、日期语义和查询守恒遵循现有契约与 UI 说明。

本机 Codex Skill 复用现有 CLI，不复制页面、计量或执行服务。隔离安装在仓库外运行，保留自定义同名 Skill、权限和独立用户数据；查询、排行、固定版本下钻及建议对照独立真值。自然语言路由、连续对话、授权后编辑和复查需要真人任务验收，不能从安装测试推断。公开插件、持久对话工作区与持续监控不属于本机安装交付。

### 有证据的用量检查与复盘

提供检查候选、上下文轨迹、资源热点和周期复盘，按 Wombat 的领域边界实现。现有周期贡献、任务及后代对比、刷新变化摘要的行为由[核心参考](../../../reference/core.md)维护；以下 G10—G16 保留新增优化的目标与完整验收要求；当前实现与限制由上述核心参考维护，局部实现不代表全部验收完成。

G10：提供可检查的候选，组合高用量、低缓存复用、重复操作、失败和输入增长等已有事实。Rust 返回有界候选及其指标、分母、基准、阈值或统计方法版本、覆盖和证据入口；Codex 负责解释并选出最值得检查的少量对象。规则命中与解释保持独立，保留相互冲突的信号和缺口。部分证据可支持检查建议；Codex 可以提出明确标注的可能原因和验证方法。不能仅凭候选信号断言浪费、故障、质量差或保证节省，不改变既有用户决定，也不自动执行修改。缓存占比只使用可比较的输入与缓存读取记录，未知分母不生成比例。

G11：按可靠轮次或请求顺序提供输入增长、未缓存输入突增及压缩前后变化轨迹，明确前后对象、分析窗口和方法。记录输入用量不等于上下文占用；只有可靠上下文体量与匹配的容量证据才能计算压力比例。缺少容量时仍可展示已记录输入变化，不声称接近上限。压缩代次、模型变化、缺失计量和无法确定的顺序构成明确边界，不能跨边界生成无说明的趋势或把邻接工具操作当成原因；增长本身不建立拆分任务的收益。

G12：按可靠资源身份汇总读取、写入意图、测试及可计算耗时，并分别展示终态结果和独立观察到的实际变化。资源键保留来源与项目依据，不通过路径子串推定项目，不合并不同项目下的同名文件或未知目标。重复读取不能扣减账本，操作不分摊 Token 或金额；同一对象的重叠耗时采用明确的并集或累加口径。热点是活动分布，有时间和覆盖依据后才能进一步检查是否为瓶颈。此范围不替代 G06 的清理候选。

G13：提供一次查询的周期复盘，用同一视图、时区、筛选和明确周起点组织总量、集中度、变化贡献、主要任务、模型与工具分布及已支持的检查线索。复用已交付查询及 G10—G12，完整范围汇总不能从当前页推导，两侧重叠家族不可相加。尚未结束的周期、未计价与不可用分区分别说明，不因单个分区缺失丢弃其他有效事实。Web、CLI 和 Skill 使用同一结构化结果，叙述由 Codex 组织；不恢复 HTML 报告。持续监控的排除由[宿主驱动监控](../../implemented/product/2026-10-09-task-statistics-monitoring.md)部分替代；仍不安装后台调度。

G14：保留按授权读取取得的原生额度观察历史，按账户身份、额度桶、窗口长度和重置周期判断相邻观察是否可比较。换账户、重置、过期、缺失和不兼容边界不可拼成消费区间，历史缺口不能用当前值回填。同期本地活动只提供固定时间范围内的事实，不能证明额度下降属于某个项目、任务或模型，也不从本地 Token 估算订阅剩余额度或耗尽时间。普通查询只读已有观察；该范围不授权后台轮询、发送通知或执行额度重置。

### 共用证据入口与 Agent 验收

G15：候选、对比、轨迹、热点和复盘共用类型化证据定位，携带逻辑对象身份、查询范围、视图和分析方法版本，支持直接进入任务、轮次、操作或资源明细。显示标签与定位身份分开；相同来源重建时保持有效逻辑身份，不用页面序号或数据库行号定位。事实纠正导致语义拆分或合并时不得冒充原对象。固定视图过期必须显式失败；重新取得原范围后核对完整身份，不沿用旧排行位置。来源坐标只证明出处，不返回或保存原始对话和工具正文。继续只支持当前格式，不增加旧版本迁移或兼容层。

G16：对已安装 Skill 和实际 CLI/Web 入口建立可重复的 Agent 查询验收。使用隔离的合成来源及独立真值，记录宿主、模型、构建、冷暖状态、首个有用结果时间、调用与重试次数、响应字节和模型 Token。固定问题覆盖命名查询路由、后续证据读取、缺失与零、估价与事实、部分覆盖、过期视图和不支持的结论；禁止借助原始日志、直接数据库或其他旁路回答。先建立 Wombat 基线，再设定调用与资源预算。自动验收不能代替 G09 的真人效果判断，也不为证明优化收益额外运行模型。

实施顺序为：先交付 G10、G11 及其所需的 G15 最小证据闭环，再补 G12 和 G13，随后处理需要独立账户观察的 G14。G16 贯穿各批次；G01—G09 保持既有范围。查询和暂存规模仍由[实时提案](../architecture/2026-09-30-live-usage.md)拥有，不因输出分页而宣称计算有界，也不为新增查询默认复制完整事件或建立无消费者的投影。

当前批次先串联已经实现的调查、轨迹、热点、复盘与配置检查，落实[Skill 主流程](2026-10-04-codex-skill.md)的查询路由、当前对话处理及按问题验证。G01 的完整事件、G04 的重复注入、G05—G06 的连续闲置与清理、G08 的历史采用分别保留其证据门槛和后续验收；这些门槛不用于阻挡其他已有观察的展示与建议。用户看到发现、依据和下一步；检查身份、版本与覆盖保留在底层并按需展开。复用现有候选、配置建议、用户决定和证据类型，不因合并回答建立第二套领域模型。

### 借鉴 COT 的检查架构与规则方法

采用 COT 的共享统计输入、纯函数检查、规则参数集中管理和具体发现摘要，细化 G10—G13；协作摩擦的事件依据仍归 G01。参考固定版本的[检查快照](https://github.com/cot-intelligence/cot/blob/6b51be8943371d20c45d71bff9cf13ebd3461605/backend/app/insight_snapshot.py)、[规则实现](https://github.com/cot-intelligence/cot/blob/6b51be8943371d20c45d71bff9cf13ebd3461605/backend/app/insights.py)和[活动异常比较](https://github.com/cot-intelligence/cot/blob/6b51be8943371d20c45d71bff9cf13ebd3461605/backend/app/activity.py)。本节细化完整增量范围，已交付部分与当前限制由[核心参考](../../../reference/core.md)维护；源码参考不证明 Wombat 已交付全部对应能力。阈值须用 Codex 的独立真值验证，不直接继承 COT 的数值。

数据路径保持为安全采集 → 规范事实 → 同范围固定快照 → 共享统计切片 → 确定性检查 → 现有候选或建议 → Skill 解释与 Web 证据。复用当前 Rust 查询、活动检查函数和配置规则目录；一次查询内按需要聚合操作、终态、资源与耗时，供相关检查共用。检查函数接收明确输入、参数及观察截止时间，不自行访问数据库、读取原始来源、取当前时间或调用模型。只传本次所需的有界统计和证据引用，计算与内存预算沿用实时提案，不照搬全量事件驻留内存的方式。

规则由其所属 Rust 模块集中声明稳定身份、适用范围、所需证据、方法与参数版本。统计计算与判定分开，Web 和 Skill 消费生成契约，不另写阈值或计算失败率。失败率使用已判定终态的操作作为分母；开始与结束记录合成一次操作，重放去重，预期搜索无匹配不视为失败，父子任务的独立操作分别保留。每条检查独立返回事实与缺口，单条失败不影响无依赖的检查。复用现有结果类型，只有实际消费者需要的新统计才扩展 Rust DTO，不增加通用规则语言或第二套领域存储。

| 增量检查 | 统计与判定方法 | 可提出的下一步 |
|---|---|---|
| 失败率上升 | 在兼容的来源、项目与工具范围内比较本期与此前不重叠窗口；同时要求最低已判定样本数、失败数及绝对/相对变化阈值。保留两期分母、覆盖和窗口；历史不足时仍展示本期事实，不称为历史异常 | 检查失败集中的调用、环境或集成，并查看代表性操作证据 |
| 操作明显变慢 | 用此前同类操作的已知、无冲突耗时建立中位数基线，本期不混入基线；同时要求最低样本数、绝对耗时和相对增幅。耗时范围按实际观测说明，未记录的权限等待不能被推断或扣除 | 检查执行范围、依赖与等待来源，再比较后续同类操作 |
| 重复流程可固化 | 区分单轮失败重试与跨任务重复流程；仅在安全请求键具有跨任务可比依据时合并同一请求，否则只汇总已知工具或资源类别，不宣称命令相同 | 由 Codex 按授权核实流程，建议整理成项目命令、脚本、规则或 Skill；正常重复验证不判为浪费 |
| 权限与提问摩擦 | 先核验目标 Codex 是否提供明确的请求、响应及关联身份；次数与等待时长分别依赖对应观察。没有回答记录不等于已确认任务停滞；缺少支持只限制该检查 | 查看反复出现的确认，提前说明稳定约束或默认选择；权限调整仍由用户授权 |

活动摘要按已有操作类别、可靠资源身份及主要目标组织，并保留直接定位证据的入口。发现摘要采用「对象 + 窗口 + 实测值/比较 + 下一步」，同一问题的多个信号合并展示，底层检查事实不删除；优先展示可定位、可行动的少量问题，保留其余结果和完整范围总量。用量候选继续是查询结果，配置建议、用户决定和复查保留各自语义；不因统一摘要新建持久问题实体，也不采用 COT 按数日未命中自动解决的方式。部分事实足以支持建议时立即给出，可能原因由 Codex 明确说明，并提供验证动作。

当前已通过现有规范操作交付重复慢请求、历史失败率与耗时比较、跨任务相同请求，以及同一任务反复失败和被拒绝的请求；当前行为与预算归[核心参考](../../../reference/core.md)。协作摩擦中的未回答问题和完整授权往返仍需宿主安全事件，不能从调用名称或缺少结果推断。借鉴 COT [活动测试](https://github.com/cot-intelligence/cot/blob/6b51be8943371d20c45d71bff9cf13ebd3461605/backend/tests/test_activity.py)的命中/不命中成对用例，使用独立合成真值覆盖阈值两侧、最低样本边界、历史不足、本期离群值不污染基线、零与未知分母、重复与乱序、跨项目同名、预期非零退出、局部失败及固定时间重放。共享聚合另验收计算预算和结果一致性；实际 CLI、Web 与 Skill 路径按 G15—G16 验收，不用纯函数测试代替入口效果。

## 考虑过的方案

只根据静态体量、读取次数或缺少事件直接判浪费、闲置及节省，证据不足，因此保留明确未知并先补适配。用演示或测试数量代替完整旅程不能覆盖故障与交互边界。Wombat 自建生成、应用、执行回执和恢复服务已被原生交接决定取代，不因完善验收而恢复。

Skill 新增 MCP 包装会重复生命周期与契约；只有多宿主工具发现需求或 CLI 开销有实测依据时再评估，包装本身不是性能改进。

仅按总量排序不能提供可复查的检查路径；把规则命中直接写成诊断又超出了证据。采用有界事实候选与 Codex 解释的分工，复用现有 Rust 查询和原生交接。

## 验收条件

G01—G09 保持完整产品的既有范围，按能力分别交付和验收，不作为每个常用问题批次的共同前置条件，也不因部分交付宣称全部完成。各规则以独立真值覆盖阈值、失败、重试、父子重放、不同版本与不可判断结果；Web/CLI 使用同一事实，逐规则部分失败不得阻止其余可执行检查。静态完整块、声明副本和 Hook 引用的回归依据由[有界规则决定](../../implemented/architecture/2026-10-02-startup-static-rules.md)及[复查完整性决定](../../implemented/architecture/2026-10-02-rule-review-integrity.md)拥有。

G10—G16 按上述顺序交付，每批均须具备生成契约、Web 与无交互入口、Skill 查询路径和独立真值。检查候选覆盖无命中、零或未知分母、低覆盖、冲突信号与主导异常值；轨迹覆盖恒定、增长、单次异常、计量缺失、压缩、模型变化、时间并列和迟到记录。测试直接核对预设事实与指标，不把生产结果保存后再当预期答案。

资源热点覆盖跨项目同名路径、别名、未知目标、写入成功但无实际变化、重叠耗时和父子重放。周期复盘覆盖日期边界、夏令时、未结束周期、分页贡献守恒、家族重叠与分区独立降级。额度历史覆盖重复观察、账户切换、重置周期、过期、缺失及不兼容区间，不从本机用量反推账户消费。

证据跳转需在实际浏览器和 CLI 中验证同视图、同筛选、完整身份、取消、刷新、重建、过期与当前未知版本拒绝；保留用户决定和处理记录。Agent 验收保留实际调用、字节、Token 和延迟证据，准确性与资源预算分别判定。只通过 API、安装或模拟传输不能宣称自然语言路由和真人任务效果完成；未测的平台、模型和长历史范围保留限制。

2026-10-04 [产品验收证据](../../../benchmarks/2026-10-04-product-acceptance-feedback.json)的完整验收未通过；后续[修复证据](../../../benchmarks/2026-10-04-product-acceptance-fixes.json)不取代产品复验。F01须复验发送专用错误标题、安装恢复说明和未知送达不自动重发；F02须复验指令/扩展用途及预估 Token 文案；F03须复验任务用途、筛选汇总、可靠轮次和建议关联、按需身份详情及最近/全部/最高用量入口，完整视觉验收仍需补齐。具体构建和场景结果只保存在上述证据中，不再复制一张状态表。

验证真实组装入口的单项与全范围批量选择、共享文件、逐项目 cwd、内容/依据变化拒绝、接受请求后断开和重新检测。接受请求不等于解决，不维护历史发送查重或 Wombat 执行回执。实际界面和真人任务效果不能由构建或原型检查替代。

## 风险

来源或宿主没有完整事件与连续覆盖时，上述能力可能继续不可判断；不得降低门槛以制造完成状态。真实账户、运行观察、跨平台与长时间验收需要不同条件，局部通过不能推广。资源目标仍待验证，功能优先并不撤销性能要求。
