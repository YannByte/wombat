# 决策记录：为 Codex 提供有界对话读取

[English](2026-10-14-conversation-access.en.md) | 中文

Status: proposed

## 问题

每日工作报告和后续追问需要对话内容及用量事实。现有查询能在 Wombat 中定位任务、轮次和操作。内部事件保留来源、文件、代次和字节位置，但公开查询尚未提供原文读取接口。没有用量记录时，按用量筛选的任务列表也不能证明活动清单完整。

## 方案

在 Rust 中复用现有安全事件位置和来源归属。分别提供活动发现、候选消息定位和显式、有界的原文读取。无需新增计量账本、将对话正文复制到索引，或为此能力增加调度器。本提案补充 [Codex Skill 提案](2026-10-04-codex-skill.md)，不取代现有用量、隐私或存储决策。

筛选条件应能组合来源、项目、任务、轮次、消息类型和日历范围。来源原生身份与内部身份保持区分。上下文默认限于一个轮次，扩大范围需要明确选择。支持有界批量读取、片段续读，以及选定来源内的关键词搜索。游标绑定筛选条件、读取版本和排序方式。返回结果附原文位置和证据。记录的消息类型与失败信息只能帮助筛选候选，不能证明语义重要性或工作已经完成。

元数据发现与正文读取分开。读取前校验来源身份和选定内容，明确保留变化、缺失、不支持和不完整状态。索引边界之外的追加内容不能悄然进入固定结果。使用现有 Rust 时区及归属规则。公开 DTO 和校验器必须从 Rust 生成。通过已授权的 Web 宿主和非 TTY 接口交付，支持取消和响应预算。

[合成数据实验](../../../../scripts/benchmark-conversation-access.ts) 测试 SQLite 位置索引和直接跳转读取。[原型](../../../../scripts/conversation-access-prototype.ts) 使用测试专用格式，属于研究代码，不是生产适配器或公开契约。原型中的完整记录指纹仍属于实验方案。生产使用 [隐私规则](../../../reference/privacy.md) 约束的有界文本块指纹；已交付行为和边界由 [内核参考](../../../reference/core.md) 维护。现有快照和普通查询响应继续排除对话正文。显式内容读取接口需要单独说明边界。

## 考虑过的方案

已知准确位置时，直接读取原文件仍是有用的性能下界。原生关键词搜索无需构建索引，适用于较小的来源。重复完整解析支持灵活的语义筛选，但会重新处理无关内容。另建全文数据库会增加正文保留、存储和同步成本。本实验测试元数据索引与选定原文件内的搜索，不构成使用向量或复制全文的依据。

## 验收条件

- 使用相同的合成结果，对照完整解析、已知文件内的原生关键词定位，以及已知偏移的直接读取。分别报告首次进程查询、重复查询、启动、读取字节、响应字节、索引构建及大小、进程峰值内存和缓存条件。已经知道位置的直接读取可能更快。
- 索引定位和有界片段请求以实际组装入口低于 100ms 为目标。原型进程内耗时不能证明 CLI、Web、操作系统冷缓存或目标平台的表现。不得宣称短对话普遍更快。
- 验证组合筛选、批量读取、同范围续查、Unicode、字节预算、来源身份冲突、无用量活动、未闭合尾行、追加、截断、替换、恢复时间戳的改写、取消和资源耗尽。没有结果与尚未完成关键词扫描必须区分。
- 大消息续读应避免反复完整解析原记录。关键词查询限制工作量，返回可续查的覆盖状态，不能把未完成扫描视为无匹配。资源测试覆盖生产来源适配器和传输层，包括大于普通片段预算的消息。
- 完成基于来源证据的活动发现、版本校验、受支持消息映射和生成契约后，才能认定交付。真实内核、Web、非 TTY 和目标平台分别验证。真实来源输出保存在仓库之外。
