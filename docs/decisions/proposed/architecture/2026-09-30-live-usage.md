# 决策记录：实时索引的持久版本与规模目标

中文 | [English](2026-09-30-live-usage.en.md)

Status: proposed

本页负责尚未完成的存储缩减、持久 MVCC、依赖闭包局部归并、数据库聚合和规模验收目标。按需服务、增量游标、SQLite 事务及固定内存视图已由[实时查询](../../implemented/architecture/2026-10-01-rust-live-query.md)与[紧凑索引](../../implemented/architecture/2026-10-02-compact-live-index.md)决定承接；当前操作和生命周期归属[内核](../../../reference/core.md)、[契约](../../../development/contracts.md)与 [CLI 指南](../../../guides/cli.md)，不在此重复。旧 TUI、旧协议兼容和旧快照迁移不再属于提案。

## 问题

来源级候选归并和内存事实仍随历史规模增长；固定视图的内存保留不能等同于持久 MVCC。增量读取不自动意味着归并、查询和内存成本只随新增量增长。需要缩小受影响计算范围，同时保持晚到证据、更正、撤销与分层计量守恒。

实时数据库保存安全观察、解析投影、查询成员关系和访问索引，不只是文件偏移。事件封装重复保存来源、世代、任务、轮次、时间和身份字段。相同投影共享内容，但逐事件成员关系仍重复保存标识。解析恢复重放事件，已保存的投影同时服务查询。两者用途不同，删除任一种表示前都必须替换其消费者。SQLite JSONB 减少编码开销，但不消除重复事实或字段。[SQLite JSONB 文档](https://www.sqlite.org/json1.html#jsonb)说明其空间节省有限，多数操作仍为线性复杂度。本机体积观察保存在私有测试产物中，不作为公开测试数据。

## 方案

### 计算模型

将问题建模为本地分析数据库的精确增量维护。在已提交版本 `v` 中，`E_v` 是具有物理身份的保留安全观察，`D_v` 是明确记录的身份和继承依赖，`F_v = R(E_v, D_v)` 是 Rust 归并产生的规范计量与操作，`A_v(q) = Q_q(F_v, price_v)` 是给定查询范围的结果。证据查询还读取 `E_v` 的选定子集。来源文件缺失只改变可用性和覆盖状态，不产生负的计量贡献。

这些关系具有不同的访问方式。观察持久保存为可独立读取的冷数据块；规范事实和贡献来源保存为紧凑类型化记录；只持久保存已有实际需求的聚合键，并明确版本和价格归属。内存只保留解析检查点和按字节限制的工作集。聚合查询不得打开观察块，恢复已提交查询视图不得调用全量事件重放路径。精确分析仍可在现有限制内解码选定的冷证据。

更新先归并依赖闭包 `C(deltaE)`，再产生 `deltaF = removed(-1) + inserted(+1)`。对于可相加的聚合，`A_(v+1) = A_v + fold(deltaF)`。负权重属于维护关系，不是对外返回负的 Token 计量。例如，将合成的 120 Token 累计估计替换为 40 和 70 Token 两条精确计量时，应撤回 120 并加入 110；直接追加新计量会错误地得到 230。旧贡献必须持久保留，或通过具有索引的来源关系恢复。模型状态、累计区间、明确祖先关系或别名的变化可能扩大闭包；输入变化小不代表受影响范围小。

增量化前先分类归约。Token 与精确十进制小计支持有符号差量；缺失数量、未计价数量和已知小计分别保存，不能把 null 当成零。最小值、最大值、精确去重集合、冲突证据、区间并集和连通分量在撤回后需要辅助状态或重算受影响分组。只保留原有标量、前 k 名列表或两条冲突证据，不足以支持一般删除。物理记录数与规范操作数保持独立。本地日期查询需要精确时区边界和原始时间戳；UTC 每日总计不能回答任意本地日期。

两类依赖图保持独立。类型化 Call/Item 别名只在精确的来源、任务和轮次范围内形成无向连通分量；明确继承关系则提供跨范围的有向依赖。内部连通分量根节点不是公开稳定操作 ID，来源锚点顺序和冲突消解仍是独立规则。环、身份缺失和不确定祖先关系保留现有失败或覆盖语义。

令 `N` 为观察总数，`Delta` 为变化观察数，`C` 为归并闭包，`M` 为内存预算，`W` 为工作线程数，`P` 为单个工作线程允许处理的分区字节数。目标是 `peak <= fixed_state + caches + queues + W*P <= M`，计入数据库页和编解码缓冲。更大的状态保存在磁盘中，不能藏在内存映射页或另一个进程里。仅按任务分区仍不充分，因为一个任务可能占据大部分观察。中间结果须能溢写磁盘并有界归并；若无法处理允许范围内的输入，应保留已提交视图并明确失败。新增工作的成本应取决于读取 `Delta`、归并 `C` 及维护对应索引，而非常规地重放 `N`。完整重建仍须读取所有必需来源字节；限制内存不能消除这一成本下界或必要的完整性校验成本。

### 业务价值与保留范围

优先采用聚合索引、紧凑精确事实和按需读取来源详情的布局。不能仅因解析器产出安全事件，就全部复制到永久存储。保留历史计量能力，并在改变存储前明确哪些分析仍须在来源缺失时可用。日期筛选只缩小回答范围，不代表可以删除更早事实。

| 数据 | 业务要求 | 建议处理 |
|---|---|---|
| 规范计量与计量输入 | 精确总计、任意日期与时区、模型、任务、继承、更正和重新计价 | 持久保存紧凑的类型化事实及重算所需观察证据，不按年龄自动删除 |
| 规范操作与关联 | 历史失败、耗时、资源、重复请求、Skill/MCP 使用及工作量 | 必需字段和别名只保存一份，保留冲突与观察来源，不分摊操作费用 |
| 安全事件证据 | 时间分析、首次内容延迟、物理记录数、缺口、上下文边界和证据分页 | 保存这些计算必需的紧凑精确观察；其余详情从已核验的来源区间按需读取，缓存有界；要求离线可用的证据固定保存为压缩块 |
| 来源身份、世代、检查点和覆盖状态 | 正确增量读取、重放、来源缺失和来源变化 | 独立于可丢弃的查询缓存持久保存，保留精度和未知状态 |
| 总计、排行、分析结果和解码块 | 固定范围与版本下的快速回答 | 持久保存常用小型聚合；可选缓存有界；受影响聚合与事实原子更新，解码详情可丢弃 |
| 用户决定、处理历史和显式快照 | 持久用户意图与固定证据 | 排除在索引淘汰与重建范围外，单独统计占用 |

逐项核对持久字段是否服务当前查询、计量规则、重放要求或证据契约。只有所有消费者和失败路径都有替代方案，才能删除字段。不为未来假想功能预存字段。不能因值相同而合并不同物理记录：消息计数、操作阶段、顺序和覆盖状态可能依赖这些记录。精确重放去重沿用现行身份规则。原始对话正文、参数和工具输出继续排除。

采用三层结构：常用小型聚合、紧凑精确事实与来源定位、按需详情。冷数据表示不同的访问和保留策略，不是把第二份完整副本藏到数据库之外。原始只读日志作为来源层；新建归档和持久缓存计入索引占用。仅保留精确重算或已承诺离线能力必需的证据，以及用户历史和固定快照引用的证据。完整离线证据归档仍作为明确的比较方案，不是每次安装的必要前提。

按需详情改变离线保证：来源删除、替换或不可读时，旧详情可能不可用，已保留账本仍可读取。Web 和非 TTY 接口必须说明这些能力和覆盖状态。来源定位需要身份、世代、字节区间、解析器版本及独立解析必需的最小上下文。核验区间及必需上下文；仅靠文件长度和修改时间不能证明内容未变。来源不匹配时，不能返回错误版本的详情。测试无派生缓存时首次访问、来源改写或删除，以及跨区间上下文。完整冷详情请求仍受 100 ms 门槛约束，返回受理状态不算通过。重建时不能静默淘汰已承诺离线保留的证据。

### 紧凑事实与证据

保留 Rust 业务边界，存储引擎和算法开放选型。SQLite 作为比较基线，不预设为最终引擎。为参与查询的计量、操作、来源世代、任务、轮次及其关系使用类型化表。重复路径和身份通过共享字典键保存。公开稳定身份保持不变；关联使用本地整数键，必须持久保存的哈希使用完整二进制值。不能截短哈希，也不能用仅在本次安装有效的行号替换持久身份。类型化时间保留原始精度和缺失值，不将纳秒舍入为毫秒。保留精确 Token 整数、十进制金额、冲突和不同的不可用原因。

需要保留的不可变观察内容只保存一次。规范事实作为明确的查询投影，关联到建立这些事实的观察。共享内容不能指向会被后续更正修改的规范行。只有替换投影引用并证明重启可重建，才能移除冗余解析副本。成员范围完全一致时，用来源世代或块成员关系替代逐事件投影成员；实际例外单独表达。只为已有查询路径建立紧凑的任务、轮次和时间索引。按行结构比较普通 rowid 表与 WITHOUT ROWID 表，不对所有数据套用同一种形式；[SQLite 文档说明了不同取舍](https://www.sqlite.org/withoutrowid.html)。

需要离线保留的安全证据保存为可独立解码的块。SQLite 候选将块放入 BLOB，使元数据与块共用事务。其他候选必须提供等价的原子发布与恢复。外部不可变文件需要持久暂存、原子提交清单及考虑读者的孤立文件回收；仅重命名文件不能建立跨存储事务。按来源世代及任务、轮次局部性组织块，为未归属证据保留明确分区。共享块元数据减少重复封装，有界字典编码重复字符串。对成熟的序列化库和 [Zstandard](https://facebook.github.io/zstd/) 做基准比较，不自行设计压缩算法。起始实验采用低压缩等级和解码后 128–512 KiB 的目标块；这些是实验参数，不是已交付限制。保留现行超大记录契约，在分配内存前约束完整解码大小、字典、校验和及取消检查的工作量。压缩后必须还原相同的安全事件值、身份、来源、精度和来源顺序。

保留有界可变尾块，完成的块封存。晚到观察追加新事实并使受影响投影失效，不重写整份任务归档或全部历史。查询通过小型目录定位任务、轮次块，只将选中块解码到有界缓存。哈希、格式版本、声明大小和实际解码大小必须一致。不能把来源日志当作已保留离线证据的唯一副本。新块格式与存储布局独立版本化；单纯无损编码变更不改变计量方法或公开 DTO。

### 查询成本与存储生命周期

已提交查询头、有期限的同版本查询批次、显式世代重建和近期文件准备已接入[内核](../../../reference/core.md)与 [CLI](../../../reference/cli.md)。这些调整将回答用量问题与恢复解析状态分开。重复轮询和模拟项目恢复批次增加计算，却不能建立真实来源进度，因此已移除。近期准备包含完整的已声明分支和副本家族，因为较早证据可能修正近期计量。延后历史时覆盖仍属暂定；文件修改时间不能证明发生日期范围内的完整覆盖。解析事实驻留、完整请求延迟、重建空间预览及旧世代回收仍有未完成验收。

仅持久保存已证明常用的少量聚合，例如完整任务总计和指定日历汇总。不要预计算项目、模型、时间范围和时区的全部组合。任意筛选及本地日边界保留带精确时间的底层事实。聚合继续区分缺失、零、部分和未计价。更正必须撤回原贡献，并在同一版本发布替代结果；仅靠缓存过期不能修复陈旧账本。

用量总计、每日分布和任务排行读取规范事实及适用汇总，不恢复全部安全事件。分析读取必需的操作切片和证据块。查询规划必须考虑所选时区及汇总不支持的组合，不能使用错误小计。扫描和归并采用流式处理，不在分页前物化全部事实。重启只恢复必需检查点和查询状态，详情随后按需加载。分别计量数据库页、解码缓存、解析状态及完整进程树。若启动仍将每条事件保留在内存中，磁盘缩减不能视为完成。

派生缓存同时限制字节数和条目数。读视图租约有界，读者过期后回收无引用的事实版本和块。常规清理保留当前事实、被引用证据、用户记录和固定快照。分别报告保留事实、可丢弃缓存、WAL、空闲页及过时世代。[SQLite WAL 检查点](https://www.sqlite.org/wal.html)和日志保留设置不提供硬性磁盘配额。暂存前检查可用空间，限制事务和临时排序；空间不足时停止并保留上一个已提交视图。停止的扫描报告覆盖不完整，不能报告零用量或静默裁剪历史。

通过 Web 和非 TTY 入口提供范围明确的重建流程。预览受影响索引数据、来源可用性、保留的用户记录及预估峰值空间。未知格式继续拒绝并保留；从来源重建不等于原地兼容迁移。建立新世代，验证后原子切换。成功替换且获准退役前保留旧世代，不在缺少可见原因和清理操作的情况下累积世代。空间预估包括新旧数据库、WAL 和临时文件。来源缺失时不能声称完整恢复历史。此流程必须解决不支持格式后只能手动删库的问题。

### 依赖归并与原子提交

保留文件贡献、跨文件候选及依赖，按受影响对话和累计区间归并，支持插入、更正与撤销。现代明细可撤销先前累计补差，继承 owner 可修正副本，工具结果更新原操作。闭包无法确定时回退来源级重建并公开同步状态，不直接累加新增行总量。

解析检查点保存白名单解析状态，包括模型/强度继承、累计前值和未完成调用关联，不保存 raw 消息或工具输出。游标不等于完整状态。文件身份、长度和边界哈希不能证明整个前缀未变化；追加伴随旧段改写需要预算化完整核验及明确水位，不承诺任意修改两秒内发现。

来源候选、规范事实、价格、汇总、来源状态、解析检查点、偏移和 revision 原子提交；大的重建可分块暂存，但最终一次切换世代，读者继续看到上一个已提交版本。提交前崩溃重读，提交后幂等恢复；来源缺失或不可读不静默抹账。变化通知只能在提交后发布。

### 持久读视图与数据库聚合

SQLite 候选使用版本化事实和稳定身份，以 validFrom/validTo 表达可见性。其他引擎必须证明相同的持久版本与可见性契约；仅有引擎快照 API 并不足够。readView 固定索引实例、revision、价格 epoch 和租约，查询仅持有短事务，避免长期 WAL 读事务阻塞 checkpoint。分页、总计与下钻同版本，过期明确失败，不静默切换。租约、GC 与回压须有界；不能回收活动视图仍引用的事实，不能删除固定快照或不可重建的用户决定。

SQLite 候选使用 WAL、FULL 同步和单写队列复用数据库事务能力。其他引擎须保留等价的已提交数据持久性，并由内核统一发布；网络共享盘不是本机数据库的受支持部署。数据库损坏时，隔离原索引并设计独立重建流程，不删除来源、身份登记或用户决定。未发布版本只维护当前格式，未知版本拒绝并保留原数据，见[当前格式决定](../../implemented/architecture/2026-10-03-current-format-only.md)。

数据库金额保存规范十进制字符串或明确缩放整数，不使用 REAL 求和。时间、来源、模型、项目和对话索引支持分页前汇总；缓存键包含范围、时区与规则版本、价格 epoch 和 revision。任意时区自然日不能从 UTC 日小计拼出；未知分类保留计数与已知小计，更正后重算受影响桶，不将 null 当零相减。

价表取得遵循[现行价格策略](../../../reference/pricing.md)。新的价格投影从规范事实构建，完整后原子切换；同一视图不混合费率，固定快照金额不随索引更新改变。通知区分事实变化与价格修订，慢客户端合并失效提示，溢出或重连明确要求重查，不承诺完整事件重放。

## 考虑过的方案

高频完整刷新反复读取和重写全部历史；只累加新增字节无法处理继承、累计更正和截断。每个入口独立监听会重复采集并增加写锁与生命周期冲突。永久守护进程增加安装与常驻负担；按需共享服务仍是边界。只保留内存丢失恢复状态，持续导出全量 JSON 成本随历史增长，因此固定快照继续用于显式归档，增量索引用于实时查询。

VACUUM 和页大小调节可以减少空余空间，但不能移除已保留的事件内容。逐行压缩现有记录仍保留重复标识，并为每行支付编解码开销。整库或整份任务归档压缩会增加小批追加和详情读取成本。只保存每日总计会丢失任意筛选、更正与证据；删除全部事件会破坏现有时间分析和历史使用能力。当端到端实测收益足以支持事务、集成和打包成本时，可以替换 SQLite。引擎选型仍须消除重复业务表示。优先顺序是逐字段审查保留需求、紧凑精确事实与聚合、已核验来源的按需详情，以及离线证据的有界压缩块。按需来源与完整离线两种方案分别定义能力契约并测量。新布局通过验收前，本提案不将已实现的紧凑索引决定标记为已替代。

### 存储与算法选型

先比较两个主要原型：紧凑 SQLite 表加压缩证据，以及使用原生列式存储的嵌入式 DuckDB 类型化表。初期布局实验可使用结构相近的合成行，但明确仅提供存储证据。集成验收必须使用相同的 Rust 规范事实和独立真值，避免把解析器变化当作存储收益。主要原型完成后，若需保留的冷证据仍是瓶颈，再增加分区 Parquet 证据变体。只有增量写入或点查、范围读取仍为实测瓶颈，才进一步评估 RocksDB。此顺序控制原型成本，不将最终选择预留给 SQLite。

| 候选 | 验证问题 | 必须检查 |
|---|---|---|
| 紧凑 SQLite 加压缩块 | 紧凑键、共享事实、选择性索引和证据块能否同时通过两项硬门槛？ | 聚合扫描、首次详情读取、WAL 峰值及索引维护 |
| 嵌入式 DuckDB | 列式存储和分析执行能否在存储预算内改善完整历史筛选与聚合？ | 小批更正、选择性详情读取、启动/RSS、索引成本及进程所有权 |
| Parquet 冷证据加事务目录 | 列编码和分区裁剪能否减少保留证据，同时维持精确任务读取速度？ | 行组读取放大、过小分区、重写峰值及跨文件原子发布 |
| RocksDB | 有序键和批量写入能否在已证明的高频路径上优于 SQL 候选？ | 二级索引与聚合的实现成本、压实峰值、读取放大及持久版本语义 |

DuckDB 的[并发模型](https://duckdb.org/docs/current/connect/concurrency)要求关注写入进程，数据库继续由共享内核服务持有。其[索引指南](https://duckdb.org/docs/current/guides/performance/indexing)区分选择性查找收益、聚合和索引内存成本。[Parquet 行组指南](https://duckdb.org/docs/current/data/parquet/tips)说明选择性读取与大范围扫描的取舍；文件紧凑不能单独证明详情查询达到 100 ms。[RocksDB 概览](https://github.com/facebook/rocksdb/wiki/RocksDB-Overview)说明有序键值访问、原子批量写入及压实，其快照不跨重启持久保留。这些资料用于确定实验，不证明某个引擎胜出。

通过成熟库比较重复字符串的字典编码、有序位置与时间的无损差分编码、低基数值的 RLE/位打包及分块压缩。[Parquet 编码规范](https://parquet.apache.org/docs/file-format/data-pages/encodings/)提供可评估的成熟编码方式。即使为分区裁剪改变物理行顺序，也保留精度、空值语义、来源及可恢复的来源顺序。比较向量化聚合、条件和列下推与索引行读取；只需前 k 条排序结果时使用有界 top-k 选择，同时单独计算完整范围总计。布隆过滤器等概率结构可以跳过无关工作，但不能决定计量身份、精确数量或删除。不能用近似去重计数或分位数替换现有精确结果以满足延迟。

原型阶段的初选带有条件。候选必须在相同测试数据上通过正确性、总存储缩小十倍、完整请求延迟和恢复门槛，才能正式采用。对通过者继续比较峰值内存、追加与压实写入量、临时空间、程序体积、启动、Rust 集成、许可证、绑定库维护情况、离线运行及全部发布平台。采用前锁定依赖版本并执行许可证检查。混合布局的收益须足以支持新增发布与清理复杂度。金额、归属和证据语义仍由 Rust 负责；SQL 和编解码器执行这些规则，不另建一套业务实现。集成正式写入路径前记录实测选择及淘汰原因，不在缺少实际消费者时长期维护多种生产存储后端。

### 先减少计算，再改变算法

从现有 SQLite 实现开始，删除没有必要消费者的计算。只有做减法后仍存在实测瓶颈，才引入新引擎、通用增量运行时、更多工作线程或缓存。下述技术是剩余工作的备选解法，不是必须逐项实现的组件清单。

| 要省掉的计算 | 替代路径与边界 |
|---|---|
| 为统计查询或打开未变化的已提交视图恢复全部观察块 | 读取持久规范事实和适用聚合。只有需要证据的消费者才解码，保留必需的离线证据 |
| 每恢复一个项目，都重新建立此前已恢复项目的索引和汇总 | 复用完成的分区及其汇总，只计算新分区和变化的跨分区依赖，保留一致的部分视图覆盖状态 |
| 普通追加时重算所有历史分组 | 替换受影响依赖闭包内的贡献。价格变化只更新价格和金额聚合，不重新解析来源或计算原始 Token 事实；更大范围的身份更正可能需要更多计算 |
| 请求到来前预备全部分析和维度组合 | 只保留已有需求的常用聚合，有界明细结果按需计算。延后处理的请求仍须满足自身的完整响应延迟门槛 |
| 对同一批选中事实反复遍历、排序和建立中间副本 | 合并可以共享的归约，消费者允许时复用已有顺序。保留溢出检查、校验失败、稳定身份和输出顺序 |

除耗时外，用计算量验证减法：观察解码条数、事实访问条数、关联输入条数、重建分区数及读写字节数。目标是普通统计及未变化查询视图的重启不解码观察，不重建未变化项目分区，单独改价不重放来源。这些是拟议验收条件，不是当前行为。依赖扩展和回退次数须明确报告。必要的来源完整性核验、计量守恒、缺失值语义和证据保留不属于可以删除的工作。把相同计算挪到启动、后台进程或另一层缓存，不能证明已经省掉计算。

### 有界计算实验

以当前已验证的发布构建为对照，先在相同 Rust 事实和独立真值上验证类型化事实、持久聚合及有界暂存的 SQLite。证据保留范围保持一致。先验证不恢复安全事件的持久查询读取，再验证固定预算下的完整重建，最后验证更新、更正和依赖闭包。只有剩余扫描或溢写成本的实测结果支持比较引擎，才实现等价的 DuckDB 候选。实验不包含完整通用增量编译器；适用时复用持续维护的算子与存储实现。

使用 10 万、100 万和 1,000 万条合成观察，保持生成规则一致并提供独立预期结果。分别改变规范事实密度、唯一字符串数量、分组数量和来源体积。覆盖均匀分区、单任务占 90% 观察、单个超大身份连通分量以及有效大记录。在一个和两个工作线程下比较 256、512 和 1,024 MiB 内存预算。暂定实验门槛为重建峰值 RSS 不超过 512 MiB，现有稳态目标不变。这些是评估目标，不是已交付限制。计入队列、字典、数据库缓存、编解码缓冲及完整进程树；同时跟踪临时和保留磁盘字节，确认内存压力没有转移成交换空间或无限临时文件。

每个规模均测试小量追加、晚到明细替换累计估计、别名桥接及桥接撤回、明确继承更正、价格版本变化、任意时区与夏令时边界、来源丢失、重启和发布中断。将每个已提交版本与独立全量重算比较，包括缺失、未计价状态和证据覆盖。在冷、热读取以及并发 1 和 4 下重复完整前台延迟门槛，保持输出大小不变，并保留失败范围。只解析数据、只测热缓存、跳过规范归并或丢弃离线证据的原型不能通过。

候选通过这些门槛后才能选型。分别记录发现与校验、解析、规范归并、证据写入、聚合构建和发布耗时。完整重建与增量维护分别报告吞吐，差量处理不能绕过首次扫描。固定产物哈希、语料哈希和资源设置，让重复测试可以判断收益能否应对规模增长和数据倾斜。若 512 MiB 门槛失败，应调整数据处理流程或明确范围选择，不能暗中提高内存额度。

### 初步技术验证

[合成存储实验](../../../benchmarks/storage-layout-2026-10-11.json)比较了 JSONB 布局基线、紧凑 SQLite 加 Zstandard 块、类型化事实加相同压缩块的 DuckDB，以及按需读取来源的 SQLite。实验还比较了直接扫描事实与四类小型持久聚合。报告记录测试真值、全部事件往返、实际分配空间、查询分布、内存和限制。这些是结构相近的存储原型，不是经过 Rust 适配器的扫描。

下一阶段实现原型优先采用 SQLite，配合常用小型聚合、紧凑精确事实、已核验的来源定位，以及仅用于离线保留证据的压缩块。DuckDB 在本实验中改善了大范围事实扫描，但受测分块布局占用更多空间。持久聚合可将这些扫描移出常用查询路径，无需引入新引擎。这不证明所有 DuckDB 或 Parquet 布局都更差。只有剩余实测工作负载足以支持新增存储和发布边界时，再实现 Parquet 或 RocksDB 实验。

完整布局对照使用 300,000 条事件；3,000,000 条基线超过有界运行时间，不计入缩减比例。新布局完成了更大规模测试。按需来源结果仅是受测事实字段的占用下界：实验使用生成的安全事件区间，不是 Codex 原始日志，并改变离线详情可用性。它不能证明完整产品占用或冷来源解析延迟。测试进程包含生成器和验证内存，不能据此验收服务 RSS 预算。正式采用前仍须覆盖真实 Rust 事实、其他分析字段、聚合更正、重启与崩溃、冷文件缓存、并发、全部平台及完整公开入口延迟。

使用以下入口和新的输出目录复现一个测试规模。对照时将引擎改为 baseline、duckdb 或 tiered；规模测试使用 3000000 条事件和 1200 个任务，另用 --unique 测试高唯一性。DuckDB 实验需要单独安装精确版本 @duckdb/node-api 1.5.6-r.1，并通过 --duckdb-module 提供位置。本次未增加生产依赖。

[产品存储实现](../../implemented/architecture/2026-10-11-packed-live-index.md)移除重复解析副本，对保留的离线证据分块压缩，并新增持久块聚合及有界查询工作集。这不代表本方案全部完成：全历史解析驻留、来源按需明细、严格前台延迟，以及完整规模和并发矩阵仍未完成。

## 验收条件

### 存储目标与测量

在现有基准入口增加确定性的存储测试规模：1,200 个文件、3,000,000 条安全事件、200,000 条计量候选、250,000 个规范操作。比较布局前固定事件类型分布、任务与轮次数量、路径长度、字符串唯一性和更正比例。高唯一性及难压缩变体单独运行。这些是合成参数，不复制真实对话。使用同一来源测试数据和范围与当前发布版本比较；旧本机格式的测量不能建立当前发布版本基线。

硬性验收目标为至少缩小 10 倍：同一测试数据和范围下，退出后的索引总占用不得超过基线的 10%。这是必须达到的工程结果，不是进阶目标或压缩率预测。中间阶段较小的降幅不能视为完成。主合成测试规模另设 500 MB 的暂定绝对预算，待基线固定后核定；调整绝对预算不能降低 10 倍要求。此处 MB 使用十进制。计入全部事实表、证据块、字典、索引和持久缓存。不能通过移动目录、遗漏历史或只统计压缩内容来达标。报告每事件、每计量字节数及增长斜率；只比较来源字节比例会被不保存的消息正文干扰。最终预算必须绑定固定测试数据；未达标时修订设计或明确业务取舍。

测量首次扫描、重启、无变化刷新、小批追加、晚到更正、指定轮次详情和完整历史查询。报告耗时、p50/p95 延迟、读写字节、峰值 RSS、数据库/WAL/临时文件峰值，以及服务退出后的实际分配字节。计入回收和重建峰值，区分保留的旧数据与新世代。无变化刷新不创建新事实版本，也不增加持久事实。历史增长可以增加保留事实；固定大小缓存、旧版本及重复改写不能造成无界放大。长行和不可压缩字段必须按既定限制停止或报告状态，不丢失有效的已提交数据。

通过独立真值和事件往返验证存储变化保留全部精确事实：时间与精度、缺失/零/未计价区别、冲突、物理记录数、别名、父子归属、覆盖状态及来源顺序。覆盖建库后来源删除、块损坏、解码数据超限、解压取消、封块时崩溃、封存分区晚到更正、过期及活动租约、可用空间不足时重建。按需来源与完整离线两种方案分别验收；较小的按需来源索引不能通过隐藏不支持的详情通过完整离线测试。

### 查询延迟门槛

存储缩减与查询延迟必须同时达标。对于已就绪的已提交数据，在受支持测试规模和查询预算内，每次受测前台查询必须在 100 ms 内返回完整结果。从公开入口计时，包含分发、排队、IPC 或回环 HTTP、数据库读取、块解压、业务计算及响应序列化与传输。新建 CLI 调用还须计量进程启动，并计入该入口的请求耗时。SQL 语句快不等于请求快。报告 p50、p95、p99、最大值及超时次数，百分位数不能替代 100 ms 完成门槛。声明结果前明确硬件、进程状态、缓存状态、并发数、响应大小和测试数据。

覆盖用量总计与每日分布、含完整总计的任务排行、跨项目/模型/时区筛选、列表分页、指定轮次时间分析、证据分页，以及现有调查和复盘查询的受支持范围。测试重启后首次查询、冷/热文件缓存、重复查询、更正失效及写入期间并发读取。只命中缓存不能通过验收。初始验收并发设为 1 和 4，另报饱和状态。有效的大范围查询若无法在 100 ms 内完成，仍属于验收失败，直到明确重设访问路径或受支持操作契约；不能静默缩小范围或截断结果。

常用汇总查询使用紧凑规范表及有界物化汇总。只预计算实测常用归并，保留完整依赖、时区、价格和版本键。覆盖索引必须证明减少读取，其占用计入十倍缩减预算。详情请求定位有界数量的证据块。减少无必要的进程、连接创建及重复序列化。先测量完整请求路径，再分配内部耗时预算；压缩块大小和等级必须同时满足存储与首次详情延迟。不能用分页或响应缓存掩盖无界扫描。

首次采集、完整重建、来源核验、导出及显式要求的最新同步作为长任务单独测量，需要进度、取消，以及存在时可读的前一已提交视图。100 ms 内返回受理或同步预览，不算完整查询延迟通过。昂贵分析若改为异步操作，单独记录任务完成时间和变化后的用户契约，此变化不会自动满足本门槛。界面绘制时间与请求延迟分开报告。

### 正确性与恢复

独立合成真值覆盖现代/旧累计计量、晚到明细撤销、跨批模型/强度、重复事件和读取、父子继承、跨文件冲突、晚到工具结果、半行与大行。随机字节/记录切块和重启后，Token、十进制金额及层级汇总与独立真值一致；不能只比较两个可能同错的实现。

在事务边界注入崩溃/取消、磁盘满、锁超时、来源不可读、事件溢出、截断/等长替换/追加伴随改写、归档重命名、睡眠、数据根变化和多客户端启停。验证无重账、缺账或半版发布，已提交当前格式快照可读，前缀改写的最终核验会更正并公开检测延迟。

真实组装入口验证固定版本分页/下钻、夏令时、价格切换、断线重连、版本过期、稳定选择、筛选输入与取消清理。无来源变化不持续发布无意义版本。平台 IPC 的 Windows 多进程、拒绝远程连接及超时另需目标系统证据；UI 测试使用当前 Web，不保留退役终端验收。

### 性能目标（待验收）

固定 macOS arm64、Node26.4.0+、release，10,000 文件、1,000,000 条计量；20 个活跃文件合计每秒20条且不超过1MiB追加，普通行不超过64KiB。另测1/10/100MiB有效长行、首次建库和长期积压，不混入普通追加 SLO。

- 已建索引、热缓存下，完整行落盘至 Web 显示 p95 ≤2秒；活跃文件漏事件巡检恢复 ≤5秒，新文件漏事件 ≤35秒，均以无持续积压为前提。
- 首屏旧已提交结果 p95 ≤500ms，同步状态可见；已就绪数据请求还必须满足上述完整 100 ms 查询门槛。同步、纯查询、CLI 进程启动、IPC 冷启动及冷文件缓存分别报告，不能把适用工作排除在请求门槛之外。现行查询预算超限要明确状态。
- 普通追加读量随新增字节增长，不重写全部历史；完整核验和目录巡检单独计量。空闲核心平均 CPU <1个核的1%，服务 RSS ≤256MiB；大行峰值、宿主/浏览器和整个进程树另报。
- 首次建库不承诺两秒完成，报告吞吐、耗时、内存、磁盘放大及回填查询延迟。连续24小时检查积压、WAL、事实版本、租约回收和磁盘增长；无限尾行缓存或永不回收版本不合格。

已有[历史基准](../../../benchmarks/live-usage-2026-09-30.json)只能说明对应构建和语料。持久版本、局部归并、数据库聚合及以上规模目标仍未通过完整验收；先定位读取、归并、事务、IPC 与渲染成本，不降低计量正确性换取性能。
