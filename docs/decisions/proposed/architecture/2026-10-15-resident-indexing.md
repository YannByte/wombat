# 决策记录：本地常驻索引

中文 | [English](2026-10-15-resident-indexing.en.md)

Status: proposed

## 问题

首次真实查询需要等待初始准备；服务空闲退出后，又会重复启动和解析恢复。直接保持现有进程运行，也会长期保留整源解析状态和明细缓存。仅把工作移到后台，不会减少计算或内存。

## 方案

使用一个 Rust 常驻服务，保留现有写入者和索引线程。受管安装启动近期准备，原生用户会话管理器负责登录启动及有界失败恢复。CLI、Codex 和 Web 共用已提交视图。文件通知合并变化后触发增量，定期发现用于补漏；历史准备保持显式，并保留完整的已声明依赖家族。

解析器专用恢复状态与规范事实、来源进度同事务持久化。语义允许时引用稳定的规范值，引用可能变化或消失时保留归并前例外。淘汰超预算来源缓存时，不清除事实，也不强制每次返回都重放原始事件。重型批次先结束线程局部堆，再由协调线程创建保留的查询头，将临时与持久分配的生命周期分开。查询使用紧凑的已提交头，明细缓存和过期视图租约可以释放；空闲检查点重建租约时，必须保留精确版本及来源代次。后台调度只作用于索引线程，保证查询请求的响应能力。先释放超预算解析状态，再分配保留的查询头，并通过锁定版本的 mimalloc 分配器回收闲置页。原生分配器检查区分了较小的活动堆和较大的扫描后驻留占用。直接使用系统内存段可以避免大块可复用分配区，使空闲段能够解除映射，而无需仅为归还已释放页面增加进程编排。页面回收和调度提示不是资源配额。

本提案部分替代[实时查询决定](../../implemented/architecture/2026-10-01-rust-live-query.md)中的空闲服务生命周期，以及[优化提案](../../proposed/product/2026-10-03-optimization-lifecycle.md)对安装后索引调度的排除。预算监控仍需要获授权的宿主；常驻索引不增加账户轮询、模型调用、提醒或自动全历史加载。[持久索引提案](2026-09-30-live-usage.md)仍拥有十倍存储缩减、受影响范围计算及完整请求延迟验收。当前命令及限制归 [CLI 指南](../../../guides/cli.md)和[内核参考](../../../reference/core.md)所有。

## 考虑过的方案

仅在安装时准备可以改善首次查询，但不能保持数据更新。每次更新都启动索引进程，会丢弃可复用解析状态并增加恢复工作。保留现有完整对象图可以避免恢复，却会让内存随历史增长。常驻索引器配合持久化恢复和有预算缓存，可以在保留模块化单体架构的同时处理这些成本。

## 验收条件

验证首次安装准备、无客户端索引、暂停与恢复、通知遗漏、未完成尾行、替换、截断、迟到关联、进程失败、重启、升级及显式移除。通过 CLI 和 Web 核对旧版本不可变及独立计量真值。每个原生用户会话管理器需在对应平台实测，生成配置不能代替安装验收。

运行至少 24 小时的可复现合成负载，记录进程内存、空闲 CPU、追加成本、查询延迟、数据库与 WAL 大小、缓存状态及来源修订。真机首次安装验证需在准备阶段删除历史 Wombat 版本和产品状态，原始 Codex 日志保持只读。解析缓存编码预算不能证明进程内存硬限；在替代实现通过所属提案的测量前，整源活动归并及完整性读取仍是明确的规模限制。
