# 决策记录：扩展上下文占用与使用频率体检

中文 | [English](2026-11-01-extension-review.en.md)

Status: implemented

## 问题

用户想看清哪些 Skill、MCP 等扩展占用上下文较多，近期却很少使用，从而决定保留、按需启用、缩小范围或停用。安装清单和单独的使用排行不能同时回答这两个问题。

参考 Claude Code 的 [`/skill-doctor`](https://code.claude.com/docs/en/skills#find-unused-skills)：把每项 Skill 的上下文负担与使用频率放在一起，让用户先复核占用较高但少用的项。Wombat 面向 Codex，复用自己的 CLI 和证据口径，不复制另一套管理器。原有内容与正文参考 Token、使用依据和关联任务缺少原生实例状态及目录元数据计量；正文估算不能代替上下文占用。

## 决定

### 产品决定

主线是“上下文占用 × 使用频率”，功能重叠、格式和引用检查作为选中项的进一步解释。维持一个主 Skill、三份参考和五个 CLI 入口，按需执行，不增加 Web、专门 Skill、整体评分或常驻采集。费用能力保持现状，不作为体检主指标或卖点。

本决策拥有体检取舍依据，补充[优化提案 G05](../../proposed/product/2026-10-03-optimization-lifecycle.md)；G05 继续约束“已证实长期闲置”的结论。[只读检查与单插件](../architecture/2026-10-31-on-demand-checks.md)确定的职责不变：Wombat 提供事实、证据和复查，Codex 解释并执行授权修改。当前入口和测量限制由[CLI 指南](../../../guides/cli.md)与[公共契约](../../../development/contracts.md)拥有。

### 一张表回答用户

表格按对象展示类型、来源与启用范围、上下文 Token 及其测量状态、选定窗口内的使用次数、最近使用和处理建议。主 Skill 先展示值得复核的少数项，CLI 提供完整分页结果和按需证据。默认审查最近 30 个本地日（含今天），用户指定的范围优先；同时说明时区、边界和覆盖情况。

先区分当前启用、停用、未确认可见及仅在磁盘发现的对象。在相同类型、统计单位和测量方法内，优先展示低使用项，再按上下文量由高到低排序；支持用户分别按占用或频率查看。未知量单列，不能排序成零。不生成“浪费分”或以 Token 除以调用次数推断价值。

| 观察组合 | 优先建议 |
|---|---|
| 上下文占用高、近期使用少 | 优先复核；结合当前工作决定按需启用、缩小范围或停用 |
| 上下文占用高、使用频繁 | 优先保留；有具体内容问题时再建议精简 |
| 上下文占用低、近期使用少 | 较低整理优先级，不为凑数量要求停用 |
| 占用、使用或覆盖未知 | 展示已知事实与缺口，不判定无用 |

低频但关键的发布、恢复等能力仍可保留。零次记录只说明所选窗口内未观察到使用，不证明所有项目都不需要。调整建议保留用户任务和作用范围，用户也可明确选择停用某项，无需先等待完整闲置证明。

### 上下文占用的口径

Skill 的主指标是当前目录中常驻的发现元数据：名称、描述及宿主实际展示的定位信息。按需加载的正文和引用单列，不将整份 `SKILL.md` 当作每轮常驻开销。仅在宿主版本、对象可见性和渲染范围有依据时纳入上下文汇总；否则可以显示带方法的条目估算，但标明可见性未确认，不计入已确认可见项的汇总。

优先采用有明确范围和方法的宿主观测值。无法取得时，复用 Rust 参考分词器，对版本化的目录渲染文本估算，并标明编码、方法、输入范围和版本；不称为当前模型的精确占用，也不把当前目录估算套到历史会话。当前完整文件和正文估算不能直接改名冒充该指标。

MCP 只对可靠取得的工具、资源或提示词定义计量，区分已暴露与延迟加载的部分；配置文件大小、工具个数或预设倍率不能替代。Hook 脚本大小也不等于注入上下文，只有可靠注入载荷才计入。第一版优先完成 Skill 体检；MCP 和 Hook 可先展示使用与配置证据，缺少可靠载荷时占用显示“未测得”。完整 MCP 定义观察仍由[优化提案 G02](../../proposed/product/2026-10-03-optimization-lifecycle.md)约束。

汇总只相加同一视图、相同方法和非重叠范围的已知量，并列出未测项数量。保留启用、宿主可见、历史加载和实际使用的区别，不以桌面安装总数计算上下文负担。体检不分摊扩展 Token 或费用，不承诺实际节省。

### 使用频率的口径

沿用[统一使用定义](../architecture/2026-10-04-event-metrics.md)和 [MCP 身份规则](../architecture/2026-10-04-mcp-runtime-evidence.md)。Skill 定向读取与可靠原生加载、MCP 工具调用与资源读取分别保留证据类型；读取不是指令被采用或任务成功的证明。操作次数、关联任务数和最近时间分开呈现，不改成会话文件计数。

开始、结果和重放按操作身份去重；独立重试和已派发的失败保留。清单展示、发现请求、普通文本提及和 Wombat 扫描不算使用。不完整、缺时间、未知版本及身份冲突保留缺口，不能填零。先固定原始读视图，再检查对象内容，避免当前取证读取回灌本次判断；不排除包含正常工作的整个会话，不增加日志解析器或使用历史库。

### CLI、Skill 与变更复查

Rust 复用配置对象、使用依据和参考分词器，补充实际消费者需要的目录元数据量、测量状态及排序汇总，通过 Rust DTO 生成 TS 和 Schema。Node 复用原生连接和 `skills/list`，按项目区分名称、路径、来源和启用状态；文件存在不能代替宿主启用。

复用 `check inventory` 的列表、详情、证据和关联范围，静态问题继续走 `check` 与 `check recheck`，同步经 `api`、`call` 暴露。具体参数与字段由实现时的公共契约拥有。在三份参考中，`diagnose` 组织体检，`verify` 组织授权调整、恢复和复查，`query` 按需补充历史。

用户要求执行后，Codex 使用核验过的宿主配置能力或可信项目工具，只处理选定项，保留最小恢复材料。优先停用或缩小范围，不默认删除文件或插件缓存；不支持项目级控制时说明实际全局影响。已有授权不重复询问，影响范围变化才重新确认。恢复只撤销本次选中值，不覆盖后来的无关修改，不新增自动处理历史。

变更后按相同项目、对象身份和测量方法重新读取原生启用及可见状态，比较目录元数据量，核对需要保留的能力。使用频率不因停用而清零，历史视图保持原样。仅有估算时报告估算变化，不称为实际整会话节省；原条件过期时重新取证，不重建旧成功结论。不得为盘点启动 MCP 服务或运行无关模型会话。

### 调研采用的机制

| 来源 | 采用与限制 |
|---|---|
| [Claude Code skill-doctor](https://code.claude.com/docs/en/skills#find-unused-skills) | 以每项上下文负担和使用频率作为主线，优先看高占用、少使用项；不把其私有计量方法或宿主状态直接套给 Codex。 |
| [codex-skill-admin](https://github.com/zjp1997720/zhijian-skills/blob/d3bca91227aaf043345d761a9b4785a954184c3a/skills/codex-skill-admin/SKILL.md) | 原生列表、预览、停用、恢复和可见性复查；保留 Wombat 的操作计数。 |
| [洁癖 Skill](https://github.com/Pluviobyte/jiepi-skill/blob/0dc5c2868949234d4ae3ddfb510d35c95d8abe97/SKILL.md) | 保留、复核、候选及插件来源区分；没有确认记录不等于无用。 |
| [skill-graveyard](https://github.com/sfrangulov/skill-graveyard/blob/7e499c360cf7498dc6ff7c5e34b6be8c23e533cc/README.md)与 [Skills Janitor](https://github.com/khendzel/skills-janitor/blob/4b42f391fd537b791d1c09c7825be0bc641fd41c/README.md) | 安装与使用交叉、按项目查看和逐项取舍；不复制安全删除推断、另一套评分或交互终端。 |
| [dr-mcp](https://github.com/Inferensys/dr-mcp/blob/ed6e00d1f8d821e9ee5fa0d2bbb1f877b22f10ca/README.md) | 配置来源与具体调整计划；持续安装不能当作调用频率，预设工具量不能当作实测上下文。 |

外部项目只核对了文档和部分源码，尚未安装实测。Codex 原生列表不提供当前模型实际采用的别名、描述预算或动态筛选结果，因此首版采用版本化的未缩写参考条目，始终标记可见性未确认，不产生已确认可见 Token 总量。完整 MCP 定义观察仍属于 G02。

## 考虑过的方案

- 只做安装或频率排行：缺少上下文负担这一取舍维度，改为同表展示。
- 先做全面功能价值评审：扩大当前任务，改为两项主指标筛选后再按需解释选中对象。
- 直接采用外部管理器或新增 Skill：会重复解析、计量和变更职责，复用现有 CLI 与三份参考。
- 按近期零次或“占用除以次数”自动停用：会误伤低频关键能力与不完整观察，改为排序和用户取舍，不作为删停结论。

## 影响与验证

- [核心夹具](../../../../core/src/config/tests.rs)覆盖正文独立、冲突与未知、原生状态的宿主版本、排序和分页；原有时间窗口、操作去重及账本测试继续约束使用口径。
- [CLI 端到端测试](../../../../tests/e2e/extension-review.test.ts)覆盖原生插件条目与历史读取关联、保留视图、正文增长、停用与恢复、协议失败、`api`／`call` 可达，以及固定快照的用量不变。
- [真实宿主验证入口](../../../../scripts/verify-skill-native.ts)在全新隔离配置中安装当前插件，验证原生发现、真实停用与恢复、目录计量和旧视图。该验证不调用模型，不证明未来建议采纳或实际整会话节省。
- 当前宿主不能观察的内容保持未知；低频关键能力仍需用户任务判断。授权编辑与恢复由 Codex 执行，不增加变更管理器、自动处理历史或另一套使用数据库。
