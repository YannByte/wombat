# 决策记录：本地 Web 与共享前端

中文 | [English](2026-10-01-local-web.en.md)

Status: implemented

## 问题

Web、CLI 与后续桌面需要共享 Rust 业务，不能在浏览器重新实现计量或暴露通用内核 dispatch。桌面选型还需要兼顾现有 Rust/TypeScript 团队和分发成本。

## 决定

React 前端通过生成契约和 UsageClient 访问窄操作；Node 本机宿主复用已有内核进程、连接与官方价格下载。未来 Tauri 2 注入受限传输，业务继续归属 Rust。当前宿主认证、资源限制和生命周期由 [Web 宿主参考](../../../reference/client.md)维护，前端边界由 [前端开发](../../../development/architecture.md)维护。

Tauri 2 复用系统 WebView 和 Rust，避免另外维护一份桌面业务或捆绑完整 Chromium。该选择基于共享工程与分发取舍，不代表已测得更低内存或更快启动。桌面工程尚未交付；Web 先行不改变桌面选择。后续[移除 TUI](2026-10-01-remove-tui.md)结束了过渡终端安排。

与设计样本的有意差异：侧栏展示实际目录和未知归属；来源按原型弹窗查看，另保留地址直达入口；搜索提交后查询；语言切换替代演示设置；优化显示有依据的静态提醒，建议支持直接复查与明确用户决定。实际记录数、模型、价格与尺寸随真实内容变化，样式复用不代表所有动态内容逐像素一致。

## 考虑过的方案

Rust HTTP 宿主可以减少运行时层次，但需要迁移已有 Node 连接、进程与受限下载逻辑，只有实际收益足以覆盖迁移成本时再评估。只做桌面无法满足先交付 Web 的需要。

Electron 的 Chromium/Node 一致性有利于跨平台渲染，但扩大分发与运行时维护范围；纯 Rust GUI 减少 Web 技术栈，却不能直接复用 React 页面。两者均不改变共享内核原则，当前采用 Tauri。

## 影响与验证

Web 静态资产随 CLI 分发；运行时取舍由 [GitHub 分发决策](2026-10-04-github-release-distribution.md)维护，当前操作由发行 Skill 维护。本机启动令牌不是远程账户体系，来源只读，未支持的规则保持不可用。

现有合成宿主测试覆盖认证、文件边界、资源上限与取消；Rust 端到端测试比较 Web/CLI 查询和下钻。历史测试不证明当前构建、Tauri 或所有平台通过，当前未完成验收由[未完成提案](../../proposed/product/2026-10-03-optimization-lifecycle.md)维护。

桌面接入仍须选择受限 sidecar 或库调用，并验证取消、崩溃、重连、单写索引协调与大响应背压；不暴露任意 shell。需要目标系统上的安装签名、更新签名、输入法、字体、DPI、辅助功能和睡眠恢复证据，并分别测量进程树启动、空闲 CPU、内存、包体及长期运行。未知协议或数据版本按[当前格式决定](2026-10-03-current-format-only.md)拒绝并保留数据；桌面更新与官方价表更新是不同信任边界。
