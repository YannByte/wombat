# 决策记录：从已观察记录持续发现项目

中文 | [English](2026-10-04-observed-project-discovery.en.md)

Status: implemented

## 问题

历史会话已经包含可靠工作目录，但 Web 切换到该项目时仍要求单独加入目录；直接打开配置页还可能在用量页建立项目列表前失败。运行中首次使用的新项目也需要重启或人工添加，和持续增量读取不一致。

## 决定

共享 Rust 用量结果中的项目目录作为本机 Web 会话的项目目录。Web 每次取得用量结果时合并新项目；配置、优化或交接直接请求未知项目时，宿主先同步当前来源，再只接受同步结果中精确出现的路径。已观察项目无需单独授权或重启。未出现的额外目录继续通过宿主系统选择器加入。

项目发现只保存派生身份并按需打开当前配置，不遍历磁盘寻找项目，也不执行日志或项目内容。浏览器提供的 `roots`、`projectRoots` 或未观察路径仍被拒绝。

## 考虑过的方案

- 为每个历史项目显示一次授权提示。用户明确要求不需要授权；它也会把已有来源事实重复变成一次设置流程。
- 直接相信浏览器提交的项目路径。该方案会把本机 Web 变成任意文件读取入口，因此未采用。
- 扫描常见父目录自动寻找仓库。它会扩大隐私、磁盘和归属边界，而且无法证明目录被 Agent 使用，因此未采用。

## 影响与验证

项目在支持的 Agent 首次写入可靠工作目录记录后自动出现；仅创建文件夹不会出现。来源目录的文件通知、巡检和 fresh 同步负责发现变化，持久索引负责重启恢复。按项目读取仍有明确用户导航动作，日志内容本身不能触发命令。

合成端到端测试覆盖宿主启动前项目、宿主启动后新增项目、直接配置读取、优化读取、任意未观察路径及浏览器伪造读取根。完整首次读取的项目级播报和渐进提交是独立缺口，见[初始化设计](../../rejected/product/2026-10-02-progressive-initialization.md)。
