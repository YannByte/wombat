# 决策记录：Rust 实时查询与故障隔离

中文 | [English](2026-10-01-rust-live-query.en.md)

Status: implemented

常驻索引生命周期部分替代空闲退出选择，见[常驻索引提案](../../proposed/architecture/2026-10-15-resident-indexing.md)；来源隔离和不可变读取语义仍然适用。

## 问题

一个来源的读取错误曾使同批健康来源无法提交；大来源的缓存恢复持有共享查询锁，拖慢其他已就绪来源。重复查询每次重新汇总，纯逐响应追加也复制候选映射并执行通用归并。

## 决定

每个来源使用 SQLite savepoint，读取失败回滚该来源并丢弃其内存工作缓存，保留最后成功投影。健康来源继续提交；返回 partial 和 sourceSyncFailed，重启恢复保留同一失败状态。全部失败仍返回错误并保留上一版本。游标、投影与版本仍在外层事务一起提交。

缓存恢复移出共享 entries 锁，使用只读事务固定 SQLite 读取版本；重新取得锁后仅在尚无版本时发布恢复结果，避免覆盖并发同步结果。

每个不可变实时版本拥有独立 LRU 查询缓存，最多16条、编码后总预算2 MiB、单条256 KiB；预算不等于精确堆内存上限。容量计数不分配完整编码副本，也不持有缓存锁。键包含完整请求和请求时区的日期，避免默认日期范围跨日失效；实时新鲜度在返回时另行附加。固定文件快照不缓存。

纯逐响应且无身份迁移时，复用事实引用并跳过累计归并；旧累计、混合记录或身份迁移仍执行通用路径。计价行按有序身份合并复用；分布查询跳过不需要的模型明细，实时轮次查询借用计量引用。

## 考虑过的方案

直接改为数据库聚合和持久 MVCC 能进一步降低全历史重建开销，但涉及身份迁移、旧累计撤销和快照兼容。本次选择先修复可复现阻塞和冗余，保留现有数据口径；完整数据库方案仍未交付。

## 影响与验证

不改变公共 DTO。回归覆盖健康来源推进、失败来源保留、全部失败、重启及恢复；缓存容量、返回值独立性与版本隔离；现有适配器样本核对完整扫描、增量、重启、更正和撤销。性能使用同一 release 合成语料，记录耗时、峰值内存和守恒，见 Git 历史中的验证记录。

追加仍遍历部分全量安全事实并重建内存索引；缓存未命中的筛选仍需汇总，不能称为常量时间或常量内存。不同根共享单个同步 worker；本次解除的是缓存恢复对就绪查询的阻塞。macOS 验证不代表 Windows/Linux 已验收。

## 本地传输取舍

从退役的 npm 分发记录合并：共享服务采用 Unix 私有 socket 和 Windows 命名管道，不把内核变成 HTTP 服务。环回 TCP 会另增端口发现和认证边界；平台 IPC 可以限制同用户访问，但仍须验证身份、锁、超时和清理。Windows 管道拒绝远程连接并使用当前用户 DACL，连接截止时间及非阻塞等待不能被锁等待绕过。启动锁、同步工作、固定视图缓存和空闲退出属于共同服务生命周期；平台安装或编译成功不替代 Windows 多进程与故障验证。
