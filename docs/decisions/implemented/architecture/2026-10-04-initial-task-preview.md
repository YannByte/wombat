# 决策记录：首次扫描的临时任务视图

中文 | [English](2026-10-04-initial-task-preview.en.md)

Status: implemented

## 问题

首次完整扫描和索引事务结束前，任务与汇总均不可查看。只改善等待提示不能满足先查看部分任务的需求；把临时结果保存成完成索引，则会把未知覆盖误报为已读取。

## 决定

无已提交视图时，Codex适配器预读完整的首条session_meta，只保留原生身份、目录、时间和来源版本。共享预算为64个文件、128个目录、2,048个目录项、深度64、每文件128KiB；100毫秒截止时间在目录遍历间检查，不承诺阻塞文件系统调用的硬超时。不跟随目录链接。超大、未完成或不可识别的首条记录不进入预览，完整扫描仍处理全部有效记录。

预览仅驻留内存，来源标为partial并带initialScanIncomplete。共享响应freshness.initialScan明确区分临时任务元数据；任务用量未知，不能宣称最近活动或高消耗排名已经完整。自动查询给快速扫描最多250毫秒机会直接返回完整结果；较慢扫描可先返回预览。cached无指定版本时只读已提交视图；fresh和refresh仍要求完成同步，refresh不接受指定快照。

完整扫描保持原有事务、失败隔离和账本归并，不用预览初始化持久缓存，不新增预览数据库。Web打开预览任务后解除临时版本固定，保留筛选和任务身份，完成时自动补齐。普通固定版本仍不自动跳转。取消只停止页面等待和轮询，不终止其他入口共享的扫描。

## 考虑过的方案

继续等待完整事务无法提前交付任务；按每个文件反复复制和发布完整事实会放大初次扫描的内存与聚合成本。选择一次有界元数据预读，代价是最多额外读取8MiB的首行数据；没有可识别首条记录时，仍需等待正式扫描。

## 影响与验证

Rust生成跨语言字段，CLI与Web共享临时结果和partial口径。合成测试覆盖身份一致、正文不留存、超大及未完成首行、共享预算、目录冲突、cached与导出拒绝；Web状态测试覆盖正在查看任务时补齐。浏览器旅程及实际资源边界见 Git 历史中的验证记录。该设计不提供百分比或预计完成时间，不解决全量事实驻留的内存成本，也不代表完整启动、全部来源或其他平台验收。
