# 决策记录：在执行端保护所选 Codex 清理

中文 | [English](2026-10-31-codex-cleanup-guards.en.md)

Status: implemented

## 问题

只读预览后再由外部删除，无法使 Codex 安装锁持续覆盖破坏性操作。更新程序可能在两个操作之间切换当前或待更新版本。通用临时目录名称也无法区分缓存、完整运行环境和持久会话状态。

## 决定

Codex 仍负责用户决策、具体选择和授权。为受支持的 Codex 可清理对象增加范围受限的核心操作，接受原始候选身份而非任意路径，重新执行当前检查，并在删除旧后台服务版本期间保持安装锁。当前规则与限制由[核心契约](../../../reference/core.md#artifact-observations)负责。

此选择仅针对受支持的 Codex 可清理对象细化[原生 Codex 交接](2026-10-03-native-codex-handoff.md)的执行边界。项目编辑、通用临时文件清理、任务创建和恢复仍由 Codex 负责。只读来源查询、来源保护、明确决策和不自动记录执行历史的原则继续适用。更广泛的[优化提案](../../proposed/product/2026-10-03-optimization-lifecycle.md)保留尚未完成的覆盖与工作树要求。

## 考虑过的方案

将所有删除留在 Wombat 外部，可以维持原先较小的接口，但无法让同一把锁覆盖最终版本校验到删除结束。通用删除 API 会将权限扩大到已知产品布局和当前消费者之外。直接调用 Mole 会引入外部安装及更广的清理范围。所选操作复用现有产物视图、CLI 和核心服务，不增加数据库或后台服务。

## 影响与验证

Apply 为永久操作，仅限原视图中的明确候选。未知、被替换或新出现活动的对象会被跳过，不提供强制覆盖或自动恢复。既有来源、状态和凭据保持受保护。目录与进程观察不是通用文件系统事务，因此结果保留不完整和失败状态。独立合成用例验证保留规则、锁、进程变化、身份变化、不完整盘点和链接目标；组装后的 CLI 检查验证所选操作。实际平台与真实来源结果保留在任务证据中，不写入此决策。
