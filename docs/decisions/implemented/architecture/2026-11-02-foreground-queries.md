# 决策记录：不依赖公开视图的前台查询

中文 | [English](2026-11-02-foreground-queries.en.md)

Status: implemented

## 问题

保留读取视图给原本有边界的工具调用增加了过期、恢复和协调流程。可选常驻服务还需要端点发现、自启注册、实例检查及各平台生命周期控制。这些机制掩盖了真正的来源失败，也让简单查询依赖进程历史。

## 决定

核心操作通过本次调用拥有的前台子进程执行，SQLite 仅作为内部增量索引。项目报告复用一次读取与配置清单；事务及临时状态随请求结束关闭。不保留公开视图选择器、保存视图操作、服务控制或安装选项，不提供兼容别名。

复查时将原始选中建议和清理计划作为数据传回，按原范围、规则比较当前证据，不保留报告生命周期，也不把传入计划当作当前删除许可。选中身份、文件检查和明确用户决定继续保留。不透明游标绑定来源目标及位置，不绑定进程租约；来源变化可能使其失效，无关数据版本变化不应使其失效。

计量、定价规则和原始来源文件保持不变。已有冷热索引、规范来源身份、来源进度及压缩证据继续复用。SQLite 事务保证增量写入原子性及单次请求读取一致性；替换成临时文件体系会重复实现这些正确性要求，不能直接改善用户任务。

本方案替代早期实时查询及按需索引决策中的服务和视图生命周期，并拒绝常驻索引方向；独立计量、有边界读取及存储方面的理由继续适用。本次不以性能指标作为验收门槛。当前接口归 CLI 指南和内核参考所有。

## 考虑过的方案

把视图藏在自动恢复之后，仍会保留过期与协调路径。保留可选服务，会留下两种执行模式及平台管理。移除 SQLite 则需要另外实现原子发布、并发和查询体系。这三种方式都会增加所选前台工具模型之外的工作。

## 影响与验证

首次使用和历史范围扩展可能需要等待采集；去掉服务不能让大范围查询免费，也不承诺延迟或资源硬上限。并发索引请求在加载事实前等待文件锁。只有显式启动的前台监测循环会在检查之间持续运行。

本机 darwin-arm64 产品全套测试及隔离运行时检查覆盖生成接口、独立计量真值、无关更新后的限定范围续读、无状态诊断和清理复查、受保护删除及取消后的清理。同一周真实用量和三个会话任务已与原基线核对。用户决定和原始来源与临时测试索引分开保留。本次不证明其他操作系统或永久本机升级已验证。
