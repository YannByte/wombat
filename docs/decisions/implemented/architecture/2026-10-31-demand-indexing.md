# 决策记录：按需索引

中文 | [English](2026-10-31-demand-indexing.en.md)

Status: implemented

## 问题

[常驻索引提案](../../proposed/architecture/2026-10-15-resident-indexing.md) 把准备工作移出首次查询，但也会在没有使用者时计算。启动恢复、文件通知和定期发现可能占用内存并更新无人读取的索引，Web 页面轮询还会让这些工作持续发生。

## 决定

把进程存活与计算授权分开。只有经过验证的查询能提交来源任务；服务启动和控制不打开索引，也不恢复视图。文件通知只使缓存视图过期，不调度同步。下一次符合条件的查询处理过期状态或已到期的重新检查。显式监控保留已授权的循环。安装不再默认启用常驻启动。[CLI 与任务 Skill 决策](2026-10-31-cli-task-skill.md) 移除 Web 交付及其轮询。

保留规范事实、持久化增量恢复状态和有界查询缓存，避免每次查询重放来源历史，并保留计量、依赖家族和固定版本规则。两种进程生命周期都先释放扫描期间的临时分配，再保留紧凑查询头。这部分取代常驻提案中的启动准备、通知触发增量和空闲巡检；其持久化恢复、资源回收理由及尚未完成的原生平台和规模验证继续适用。当前行为归[内核参考](../../../reference/core.md)所有。

参考 [Better Harness 在 b605532 版本的 Codex 分析器](https://github.com/QoderAI/better-harness/blob/b605532fcf1014bcb48d3e6940a5bc64e80cddd5/scripts/session-analysis/platforms/codex.mjs)，它先发现候选、选择会话，再加载所选会话；Skill 在多个分析之间共享固定的证据包。这支持先限定范围和复用版本，不要求删除持久化计量事实。它的 `all-eligible` 选择会忽略给定数量限制，返回全部符合条件的会话；所选会话加载还会保留事件数组。输出少或输入流式读取，都不能证明计算和内存有界。Wombat 保留精确的统计总体和已有的有界明细读取，不把语义抽样当作用量总数。

## 考虑过的方案

把同一轮大扫描推迟到进程启动，仍保留无必要的启动工作。完全删除持久化事实，会使重复查询重放日志并削弱版本复用。统一由查询驱动的单写入者保留现有计量和存储模型，同时删除独立调度路径。

## 影响与验证

首次请求可能等待准备；按需执行不意味着全历史采集没有成本，也不构成耗时或内存硬限。原生通知是缓存过期的依据，不能证明本次读取边界。已完成的强制同步遇到后续过期状态时，可返回过期视图，不误报超时，也不丢弃通知。缓存和固定版本读取不授权同步。空闲缓存回收和 SQLite 检查点仍属于维护，与来源计算分开。

选择器测试覆盖合并、取消、过期及迟到通知。真实内核常驻场景覆盖无查询启动、无人读取时的变化、显式查询、暂停恢复、半尾行、替换、重启、范围隔离及固定读取。安装器测试覆盖默认不启动和显式常驻。Web 和 UI 检查依 CLI 与任务 Skill 决策退役。完整请求延迟、真实来源资源、长时间规模及原生平台验收继续使用原有归属的检查，不从这些测试推断通过。
