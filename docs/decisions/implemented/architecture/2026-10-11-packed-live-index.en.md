# Decision Note: bounded compressed live-index facts

English | [中文](2026-10-11-packed-live-index.md)

Status: implemented

## Problem

The previous row layout stores repeated observation envelopes and one projection reference per event. Parser measurement and operation copies are redundant for recovery: replay already reconstructs them from observations. Removing these copies reduces persistent data without changing accounting. Compressing isolated rows cannot exploit their repeated source, task, and schema fields.

## Decision

Retain SQLite transactions and pack related facts with the pinned Zstandard library. Keep safe observations sufficient for offline replay; remove redundant parser projections and per-event reference rows. The [core reference](../../../reference/core.en.md) owns the current format, bounds, and recovery behavior. This partially supersedes the row/reference layout and page-cache choice in the [compact-index decision](2026-10-02-compact-live-index.en.md); its identity, exact-value sharing, current-format-only, and atomic-publication rationale still applies.

Source-local windows bound append rewrites. Exact-target blocks allow a native SQLite expression index to replace the duplicate task-membership table; block writes no longer maintain or scan that second representation. Canonical query facts use separate bounded frames so queries and restoration do not need to decode observation blocks to obtain measurements. Small appends reuse the current fact frame. Checksums, decoded-size limits, explicit codec versions, and identity checks protect reads. All block, membership, checkpoint, and view writes use the existing transaction boundary. User decisions and collection history remain in their independent stores.

Retain lossless safe evidence rather than switch to source-only locators in this change. Source removal must still allow existing accounting and analysis to recover. A source-only profile requires a distinct availability contract and verified source generations. No conversation or tool-output body is added to the index.

Restore one prepared view from canonical facts and compact evidence metadata. Pin its existing SQLite revision rather than recreate event envelopes in memory. Project progress shares that prepared state, including immutable task, turn, and event-partition metadata. Restore operations as verified frame locators and use counters; decode full operation records only when requested. First scans flush observations in bounded batches. Recover accounting order through temporary disk sorting of minimal business inputs, and reduce association graphs one task/turn scope at a time. Reuse the same accounting reducer for direct observations and ordered replay; full observation envelopes and operation details do not enter that sort. Retain canonical components and identity anchors instead of raw phases; preserve global identity collision order and refresh only affected scopes on append. This uses temporary disk space and still retains canonical source state. Transaction-local frame metadata reuses facts from verified writes, avoiding a second payload decode for indexing; it does not introduce another persistent representation. Append reduction reuses unaffected target partitions instead of decoding the whole archive. Target joins use [SQLite join-order control](https://sqlite.org/optoverview.html#manual_control_of_query_plans_using_cross_join) and the existing expression index. Virtual target lists have no stored cardinality statistics; target-first lookup prevents multiplicative target/frame scans without another persistent index. Evidence remains lossless and available after source removal; reads decode only selected blocks. This adds small locator metadata and may retain WAL pages while fixed views remain leased. The core reference owns current limits and release behavior.

Persist frame-local sufficient statistics inside the canonical fact transaction. Cluster new measurement frames by task, model, effort and timestamp hour. Aggregate across turns, preserving bounded exact slot membership for each turn; per-turn aggregate payloads would approach measurement cardinality and repeat pricing envelopes. Keep matched-turn distinctness in its own spillable relation rather than a growing task record. Recompute affected frames on correction rather than implement inverse min/max, distinct-set, or price arithmetic. This preserves exact scopes without materializing all timezone and filter combinations. UTC-hour groups use exact local dates, reading bounded canonical members only when a timezone boundary splits a group. Prioritize recently accessed aggregates under a byte budget, because date alone cannot limit high-density usage. History stays on disk without narrowing results or discarding offline evidence. Query reductions spill to private SQLite temporary storage when their memory budget fills. Limit expensive concurrent queries and reuse completed duplicate requests within a fixed view. The core reference owns limits; parser residency and strict request latency remain separate acceptance work.

Unix service connections wait for socket readiness instead of periodic polling. This removes an avoidable foreground delay while reducing idle wakeups. It does not alter query freshness, synchronization, or cancellation contracts.

## Alternatives considered

The [storage experiment](../../../benchmarks/storage-layout-2026-10-11.json) compared SQLite and DuckDB with compressed safe observations. DuckDB improved broad fact scans in that experiment, but used more total space and introduced a second engine. SQLite reuses the existing transaction and deployment boundary. Keeping only aggregates would lose exact corrections and supported evidence. Source-only storage has different offline guarantees. The [live-usage proposal](../../proposed/architecture/2026-09-30-live-usage.en.md) retains unfinished residency, aggregate-scale, and latency acceptance; compressed storage alone does not establish those claims.

## Consequences and verification

The storage format changes independently of public DTOs and source mappings. Unknown or older layouts are rejected and retained; this change does not migrate or delete them. Block compression adds CPU work and native dependency packaging. A correction rewrites its frame, while unchanged frames keep their bytes. SQLite WAL and temporary-space peaks remain separate from settled database size.

Rust regression tests cover exact numbers and nulls, small append packing, corrections, retractions, missing or corrupt frames, read-only selection, replay after source removal, restart, and transactional rollback. The [production benchmark](../../../benchmarks/production-storage-2026-10-11.json) checks independent tokens and money, task and daily totals, snapshot export, restart, and rebuild through real CLI entries. Platform, corpus, cache, and memory limits belong to each benchmark result. Verification and source-replacement residency, association state, aggregate scale, and strict request latency still require the follow-up design in the proposal.
