# 决策记录：实时索引的有界压缩事实

[English](2026-10-11-packed-live-index.en.md) | 中文

Status: implemented

## 问题

原有逐行布局重复保存观察封装，并为每个事件保存一条投影引用。解析器中的计量和操作副本不参与恢复：现有重放已经能从观察恢复这些事实。移除副本可减少持久化数据，同时保持计量语义。逐条压缩无法充分利用重复的来源、任务和结构字段。

## 决定

保留 SQLite 事务，使用锁定版本的 Zstandard 库对相关事实分块压缩。保留足以支持离线重放的安全观察，移除重复的解析投影和逐事件引用行。当前格式、边界及恢复行为由[内核参考](../../../reference/core.md)维护。本决定部分替代[紧凑索引决定](2026-10-02-compact-live-index.md)中的逐行引用布局和页缓存选择；原有身份、精确值共享、只支持当前格式和原子发布的理由继续适用。

按来源文件划分窗口，限定追加时需要重写的范围。规范查询事实单独保存在有界块中，查询与恢复可以取得计量事实，而不必解码观察块。小批追加复用当前事实块。读取校验摘要、解码大小上限、明确的编解码版本和身份。块、成员、检查点和视图沿用同一事务边界。用户决定和采集历史保留在各自独立存储中。

本次保留无损安全证据，不切换为只保存来源定位。来源被移除后，已有计量和分析仍须能够恢复。只依赖来源的方案需要独立的可用性约定和经过校验的来源代次。本次不向索引加入对话或工具输出正文。

每个不可变实时视图都预先构建有界的精确汇总。查询只合并完整入选的分组，部分筛选继续按行计算。这样可减少首次请求的聚合工作，不依赖已有响应缓存；更正与价格变化会生成新的聚合所属视图。纳入限制及回退行为由内核参考维护。持久化聚合表不在本次范围内。

Unix 服务连接改为等待套接字就绪，取消周期轮询引入的额外前台等待，并减少空闲唤醒。不改变查询新鲜度、同步及取消约定。

## 考虑过的方案

[存储实验](../../../benchmarks/storage-layout-2026-10-11.json)比较了 SQLite 和 DuckDB 保存压缩安全观察的方案。DuckDB 在实验中加快了大范围事实扫描，但总占用更大，并引入第二种引擎；SQLite 可复用现有事务和部署边界。只保留聚合会丢失精确更正及已有证据能力。只依赖来源的存储具有不同的离线保证。[实时用量方案](../../proposed/architecture/2026-09-30-live-usage.md)继续维护未完成的聚合、驻留和规模验收；压缩存储本身不能证明这些目标已达成。

## 影响与验证

存储格式独立于公共 DTO 和来源映射变化。未知或旧布局被拒绝并保留，本次不迁移或删除旧数据。块压缩增加 CPU 工作和原生依赖打包成本。更正重写对应块，未变化块保持原字节。SQLite WAL 和临时空间峰值与稳定数据库大小分开统计。

Rust 回归覆盖精确数字与空值、小批追加合块、更正、撤回、缺失或损坏块、只读筛选、来源移除后的重放、重启及事务回滚。[生产基准](../../../benchmarks/production-storage-2026-10-11.json)通过真实 CLI 校验独立的 Token 与金额、任务和每日合计、快照导出、重启及重建。平台、语料、缓存和内存限制由各基准结果说明。解析器和快照的全历史驻留仍需方案中的后续设计。
