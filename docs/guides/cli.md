# Wombat CLI 完整使用指南

中文 | [English](cli.en.md)


Wombat 帮助查看工作记录与用量、定位值得改善的问题、检查清理候选，并复查修改结果。可以直接运行命令，也可以在 Codex 中用自然语言提出任务，由 Wombat Skill 选择命令、解释证据并协助后续操作。

第一次使用，从[快速开始](#quick-start)读起。查找具体操作，阅读[全部命令](#commands)。需要精确查询、脚本或 Skill 集成，阅读[高级参数](#options)和[自动化接口](#automation)。遇到问题，查看[结果与恢复](#recovery)；不熟悉的词可查[名词说明](#terms)。

<a id="quick-start"></a>

## 快速开始

### 确认安装

先按[安装指南](installation.md)安装 Wombat，然后在终端输入：

```sh
wombat --version
```

显示版本号表示程序可以启动。若提示找不到命令，按安装指南检查命令位置；此时不要反复重装。查询本地记录不需要填写模型 API Key，也不需要先运行初始化命令。

### 从一个任务开始

每次选择一行运行。普通查询和检查不会修改原始工作记录。

| 想做什么 | 输入 |
|---|---|
| 看今天用了多少 | `wombat usage` |
| 看这周的用量 | `wombat usage week` |
| 看最近做过什么 | `wombat history` |
| 找以前关于发布失败的讨论 | `wombat history search "发布失败"` |
| 检查当前项目 | `wombat check` |
| 看 Skill 的目录占用和使用记录 | `wombat check skills` |
| 看当前项目有哪些清理候选 | `wombat clean` |
| 检查安装和插件 | `wombat system doctor` |

运行 `wombat` 查看这五类入口及常用示例，不启动查询或扫描。运行 `wombat COMMAND --help` 查看该命令的帮助，例如 `wombat history --help`。AI 可以用 `--help --json` 一次取得任务示例与下一步；已知命令直接执行，只有不熟悉精确字段时才查询所选方法的 Schema。

### 读懂一次结果

结果先说明项目、日期、时区及数据状态，再展示总量或相关条目，最后给出下一步。先确认范围符合问题，再判断结果。

“没有找到匹配记录”表示已检查的范围内没有匹配；“数据尚未准备好”或“部分记录无法读取”表示暂时不能得到完整结论。未取得的指标显示为未知，不显示成零。只展示部分条目时，结果会说明是否还有后续内容，并提供继续查看的命令。

普通用量查询读取当前日志，或复用已与当前文件核对的计量数据。符合条件的历史查询重复运行时，Wombat 可在返回结果后准备可复用的账本。用 `--fresh` 显式更新完整索引，或用 `--cached` 读取完整索引中最近一次提交的数据。

### 选择项目

`usage` 和 `history` 默认查看已授权记录来源中的所有项目。`check` 和项目模式的 `clean` 默认选择终端当前所在的项目目录。两种范围都会写在结果中。

在其他目录运行，或只想查看某个项目时，使用 `--project`。把示例路径换成实际项目文件夹，并保留路径两侧的引号。

```sh
wombat usage week --project "/path/to/My Project"
wombat history --project "/path/to/My Project"
wombat check --project "/path/to/My Project"
wombat clean --project "/path/to/My Project"
```

Windows 路径可以写成 `"C:\Work\My Project"`。同一个 `--project` 同时选择项目检查范围和相关记录，不要求重复输入读取目录与过滤目录。项目以明确记录或选定目录识别，不根据目录名中的关键词猜测。历史与用量查询按记录中的项目身份筛选，即使原目录已不存在也可查询。用量、历史和按任务查询保留记录中绝对项目路径的原始格式，即使记录来自其他操作系统；只有相对路径才按当前目录解析。现场检查和清理需要存在且可读取的目录。

无法识别当前项目时，检查和清理会说明缺少的范围，不扩展扫描整个主目录。在可交互终端中可以按提示提供文件夹；脚本应直接传入 `--project`。

<a id="commands"></a>

## 全部命令

五个顶层入口分别是 `history`、`usage`、`check`、`clean` 和 `system`。下表列出本指南的全部操作；详细数据能力通过 `system api` 和 `system call` 提供，不增加顶层入口。

| 入口 | 操作 | 默认结果 |
|---|---|---|
| `history` | 列表、`search`、`show`、`read` | 最近工作、匹配位置、记录信息或原文片段 |
| `usage` | 时间选择、`top`、`stats`、`compare`、`alerts` | 总量、任务排行、任务分布、范围对比或预算提醒 |
| `check` | 项目检查、`skills`、`mcp`、`rules`、`hooks`、`--task`、`verify` | 问题、观察依据、复核线索或原条件比较 |
| `clean` | 项目预览、`--codex`、`verify`、`--apply` | 候选及保护原因，或明确选择的清理结果 |
| `system` | `doctor`、`update`、`api`、`call`、`hook codex` | 维护、接口发现或集成输入 |

## 找回工作记录：history

### 列出最近工作

```sh
wombat history
wombat history --project "/path/to/project"
```

默认列出最近 30 个本地日内有活动的工作记录，含今天，每页 20 条。每条显示主题、项目、最近活动时间及查看方式。工作记录对应来源中的会话；标题、出现过的操作或记录数量不证明工作已经完成。

### 搜索关键讨论

```sh
wombat history search "发布失败" "release failure" "上传超时"
wombat history search "验收" --project "/path/to/project" --fixed --json
```

一次可传入最多 16 个字面搜索词。搜索直接读取 Codex 日志，返回可见消息的原文片段、来源文件和字节范围。含空格的短语要加引号。默认查最近 30 日。查更早的内容时，指定日期或使用 `--all-time`。

找用户明确表达的决策时，用 `--speaker user`。用 `--max-bytes` 限制每段原文的长度。默认每页 20 条，用 `--complete` 可取到每页最多 200 条。扫描有后续页时，保留筛选条件，使用 JSON 中的 `nextSearch` 或终端给出的命令继续。日志清单在翻页期间发生变化时，从第一页重新查询。

用 `--context 1..5` 查看命中前后的可见消息，支持在同一份日志内跨轮查看，前后可以包含双方消息。CLI 直接读取原始日志，并在同一页内合并重复的相邻消息。自动化流程确实需要索引事件 ID 时，用 `--locate`。

```sh
wombat history search "保留" "删除" --project . --speaker user --complete --context 2 --json
```

### 查看一条记录

```sh
wombat history show "发布流程"
wombat history read "发布流程"
wombat history read "发布流程" --find "验收" --find "validation" --limit 6
```

`show` 返回记录信息、轮次、操作和可用证据。`read` 返回原文、说话者和时间。从搜索命中回读时，在字节预算内带回命中前后的原文。重复使用 `--find` 可在选定记录内匹配任一词。用 `--limit` 一次选取最多 20 个位置。相同片段只展示一份正文，各来源位置和续读游标分别保留。 用 `--context 1..5` 读取同一来源文件和会话中前后各几条可见消息。上下文可包含双方发言，并可跨轮读取。原筛选指定精确轮次时，只读该轮。命中跨多条记录时，通过 `system call` 把证据位置和读取游标传给同一次 `conversation` 读取。

记录选择可以使用完整记录 ID，或在当前查询范围中匹配记录标题。只有一个匹配时打开它；多个匹配时先展示时间、项目和主题。在可交互终端中选择一条后再读取，编号只在该次命令内有效，不保存成跨命令快捷方式。

脚本应使用完整 ID；标题不唯一时返回歧义错误与候选，不默认读取第一条。返回的继续命令绑定选定记录和原筛选范围，后续阅读不会重新按标题选择另一条记录。

明确选中记录后，未指定日期时可以查看该记录的完整可用历史，不受发现列表的默认 30 日范围截断。明确指定的日期、来源和项目限制始终保留，`show`、`read` 不会悄悄扩大范围。原文分段返回，按提示继续，不默认一次输出整段长会话。`--turn` 可以精确选择轮次；更细的位置、前后文和游标控制通过自动化接口提供。 在 `history read` 后加 `--tools`，可在选定范围内检索和读取工具请求与结果，包括后续成功操作的结果，例如：`wombat history read RECORD --turn TURN --tools --find "error"`。通过 `history show RECORD --turn TURN --json` 获取规范操作 ID，再用 `history read RECORD --turn TURN --operation OPERATION --json` 一次读取该调用最多四个有定位的请求／结果片段，自动包含工具文本。有 `nextLocations` 或片段游标时继续读取；这不关联后续其他调用，也不证明业务问题已经解决。结果包含操作身份和原始位置，续查保留该标记与范围。索引只保存位置和校验信息，正文在既有字节预算内按需读取。

### 接续工作或整理报告

接续工作时，先用 `history search` 找到相关记录，再用 `show` 查看操作位置，必要时用 `read` 确认原话、交付位置和未完成事项。记录中声称“完成”只是待核对的依据；实际文件和测试结果仍需检查。

日报或周报需要把同一日期与项目范围内的工作记录和用量放在一起。可以在 Codex 中要求：“总结这周这个项目做了什么、用了多少 Token、还有哪些事项未验证，并给出记录位置。”Skill 只读取有关片段，并区分用户要求、已记录的动作与已验证的结果。整理知识文档也使用这些证据，写入位置由用户指定，不自动建立另一套知识库。

## 查看用量：usage

### 常用时间范围

```sh
wombat usage
wombat usage yesterday
wombat usage week
wombat usage last-week
wombat usage month
```

| 时间选择 | 范围 |
|---|---|
| 不填或 `today` | 今天 |
| `yesterday` | 昨天 |
| `week` | 本周星期一至今天 |
| `last-week` | 上一个完整自然周，星期一至星期日 |
| `month` | 本月第一天至今天 |

日期按本地时区解释，结果写明实际日期与截止时间。指定 `--timezone` 可改用另一时区。原始事件时间保持不变。

总量包含完整匹配范围内已记录的用量，不从当前显示的几条记录相加得到。输入、输出和缓存保留各自口径；来源缺少字段或尚未完整读取时，结果说明哪些数值不可用或仅为已知部分。

日历报告默认列出每期总量，模型明细不挤占日期。`--limit` 和 `--offset` 对这些总量分页；`--by model` 或 `--by project` 选择分布。JSON 默认精简覆盖详情的样例；需要完整明细与覆盖信息时，使用生成的 `usage` 接口显式选择。

来源告警覆盖整个索引。`quality.issueScope` 标明该范围；`queryImpact=unknown` 表示尚未将告警归属到本次查询。所选汇总另行报告计量字段的覆盖情况。历史告警既不能证明指定日期存在错误，也不能证明这些日期不受影响。

### 看哪些任务用量较多

```sh
wombat usage top
wombat usage top week
wombat usage stats
```

`top` 默认列出今天 Token 用量最多的五条任务；添加时间选择可以改变范围。结果注明完整总量、排名范围和未显示的条目。不把排名较高直接判断为浪费。

`stats` 默认分析最近 30 个本地日的任务分布。均值、中位数和 P90 来自具有完整总量的任务，不完整任务和未归属用量单列。P90 表示该总体中约九成任务不超过的用量位置，不是预算或效率评分。

按项目、模型、推理强度、来源及记录进一步筛选，使用高级参数或自动化接口。同一任务可能使用多个模型，不能简单相加模型组内的任务数。

### 对比变化

```sh
wombat usage compare
```

对比默认读取完整索引中最近一次提交的数据。首次准备索引或需要比较当前记录时，用 `wombat usage compare --fresh`。

默认比较最近两个已经结束的完整自然周，避免把尚未结束的本周与完整上周直接比较。结果明确列出两段日期、时区、总量变化和分布变化。要比较本周进度或其他日期范围，应明确给出双方边界。

自选周期必须等长且不重叠。对比两个任务时使用 `--task RECORD --against RECORD`，需要包含已记录的子任务时添加 `--family`。记录选择规则与 `history show` 相同，脚本使用完整 ID。

用量变化可以与任务数量、单任务用量及模型分布一起查看，但这些统计不自动证明变化的原因或工作产出。费用估算与账户额度作为辅助信息按需读取，不与 Token 预算混为一谈。

### 查看预算提醒

```sh
wombat usage alerts --once
wombat usage alerts
wombat usage alerts --id PLAN_ID --interval 60
```

先通过 Skill 或自动化接口保存预算计划。没有启用计划时，命令明确说明尚未设置预算，不以安静输出暗示检查正常。`alerts` 默认持续监视，只输出新的提醒；`--once` 检查一次后退出。默认间隔 60 秒，可用 `--interval 5..3600` 调整。

Ctrl+C 结束本次监视。监视只在命令运行期间生效，不安装定时任务或自动发送消息。已有计划可以使用 `--id` 选择，多个计划可重复该参数。Token 预算、账户额度与费用估算分别展示；部分用量可以证明越限，不能证明剩余额度。

`alerts` 沿用已保存预算计划的范围，不使用普通 `usage` 的今日默认值，也不接受时间词、日期或项目筛选来覆盖计划。需要选择计划时使用 `--id`。

## 检查问题：check

<a id="project-diagnosis"></a>

### 一次诊断当前项目

```sh
wombat check
wombat check --project "/path/to/project"
```

这是当前项目的综合事实入口，不需要依次输入各类检查命令。结果组合项目规则和配置检查、有关 Skill/MCP 的占用与使用依据、近期工作线索，以及项目临时和编译产物的只读候选。后续详细读取按线索选择，不自动读取所有会话或扩展全部 Skill 正文。

事实报告先说明项目、实际日期、时区和各部分覆盖情况，再展示确定性问题、值得调查的线索及证据位置。配置格式有误、引用失效、明确声明的副本与源文件不一致，或有效 Hook 的目标存在问题，可以成为具体检查结果。较长文件、重复片段、用量高或缺少使用记录只作为复核线索，不直接变成整改建议。

默认选择当前项目及明确作用于它的配置，历史窗口是最近 30 个本地日，含今天。`--project` 同时限定现场目录和有明确项目身份的记录；`--since`、`--until` 与 `--timezone` 可以调整历史窗口，不改变当前文件所代表的版本。用户级缓存与无关全局配置不纳入默认清理范围。

部分历史不可用时，仍返回独立可完成的当前检查，说明缺失或截断的部分；查不到历史不表示项目没有问题。各部分保留其原始读取版本和复查依据，不宣称整个项目拥有单一完整快照。无法确定项目、参数无效或整个请求无法执行时返回明确错误。

综合报告复用已有统计口径与核心返回的总量，不因合并线索改变 Token 或费用结果，也不把选中的几条记录相加当作整个项目的用量。

命令不修改项目文件或启用状态，不安装依赖、不构建、不启动 MCP 服务，也不自动清理。Wombat 可以为证据读取更新自身的派生数据。`--json` 返回结构化事实，进度写入 stderr；非交互执行不等待用户选择，证据不足以形成结论时保留缺口。

CLI 不调用模型来判断代码机制或执行整改。在 Codex 中通过 Skill 发起同一任务后，Codex 根据事实追踪必要代码、给出可选择的优化方案，在用户确认或已有明确授权的范围内修改并验证。完整的报告、选择与恢复体验见[项目诊断](plugin.md#project-diagnosis)。没有新增顶层命令，也没有通用的自动修复开关。

### 检查 Skill、MCP、规则和 Hook

```sh
wombat check skills
wombat check mcp
wombat check rules
wombat check hooks
```

| 检查对象 | 结果重点 |
|---|---|
| `skills` | 来源、项目作用范围、原生启用状态、目录 Token 估算、使用记录及复核线索 |
| `mcp` | 配置来源、能识别的工具调用与资源读取、最近使用及缺失证据 |
| `rules` | 指令文件、引用、重复片段和有明确关系的内容漂移 |
| `hooks` | 已观察的原生注册、启用与信任状态，以及可验证的目标问题 |

使用情况默认查看最近 30 个本地日，含今天。报告直接显示“使用了 N 次”或“所选时间内未使用”，扫描未完成和历史读取错误单独说明。低频发布、恢复等能力可以继续保留。运行 `wombat check skills --explain` 查看计数方法、数据版本和证据缺口；`mcp`、`rules`、`hooks` 同样支持该选项。无论是否添加该选项，JSON 均保留原始次数和覆盖字段。

解释结果列出每条记录为何计入或排除、对次数的贡献，以及原始聊天和日志位置。用返回的条目 ID 配合 `--item ID` 检查单个对象，或用 `--unassigned` 查找无法归属的目标。经核验的原生命令读取计入次数，目录发现和未核验的 Shell 读取标签不计入。需要比较修复结果时，先保存解释报告：

```sh
wombat check skills --explain --json > explanation.json
wombat check skills --baseline explanation.json
```

第二条命令沿用原项目、来源、日期和对象选择，只重算本地事实，不执行历史命令，也不调用模型。输入一致时报告结果一致或发生变化；输入事实、配置或范围变化时单独说明。即使明细分页，次数和指纹仍覆盖完整选择；用返回的续查命令查看其余记录。逐条差异只比较已提供的明细，不将省略的记录视为已经完整比较。

Skill 目录估算包括参考名称、描述和定位信息，正文按需加载量另列。该估算不等于当前模型实际看到的全部上下文。MCP 缺少可靠定义载荷时显示未测得；Hook 脚本大小不作为上下文占用。当前启用、历史加载、实际使用和服务是否可访问是不同事实。

### 复盘某项工作

```sh
wombat check --task "发布失败"
```

先选择目标记录，再查看失败后重试、重复读取或请求、输入量变化等有证据的线索。需要具体轮次时，按提示选择或使用 `--turn`。CLI 给出检查位置和依据，Skill 结合项目代码提出具体修改及验证方法。 选定任务报告会提供有界的操作冲突原因和抽样原始位置。结构化续查参数错误会指出具体字段，并提供可运行的接口查看命令；应保留原选择，不猜测其他游标。

正常的负面测试、必要的验证、合理重试或长时间等待不能自动判断为错误。来源缺少时间、结果或目标身份时保留缺口，不推断完整耗时或因果关系。

### 修改后复查

先保存原始结构化报告，再选择其中的建议复查。例如：`wombat check --project PATH --json > check.json`，然后执行 `wombat check verify --baseline check.json --suggestion ID --json`。原范围与规则覆盖值从报告读取，改变条件会使比较无效。

复查绑定原问题和检查条件。比较结果会区分仍存在、相同条件下未命中、条件不可比以及证据不足。只有相同条件下的有效比较才能说明该检查的问题已不再出现。工程修复还需要重新运行原来的项目测试。

原始报告作为数据传入，不随进程结束过期。复查仍校验范围、规则和当前观察。“保留”或“不适用”仍是明确的用户决定，与修复结果分开。

## 查看和执行清理：clean

### 先查看候选

```sh
wombat clean
wombat clean --path target --keep dist
wombat clean --codex
```

默认仅预览，结果首先说明“仅预览，未删除任何文件。”项目模式检查可再生成的构建输出和明确选择的临时路径；`--path` 可以重复，按当前项目解析。`--keep` 保留仍有用途的输出或用户指定的材料。已跟踪文件、用户资产、来源记录及需要保留的状态不会因名称像缓存而成为删除对象。

`--codex` 选择当前用户受支持的 Codex 缓存和旧暂存内容，不限于当前项目；当前目标范围是 macOS 的 Codex 目录布局。它不表示清理所有平台、所有 AI 产品或整个主目录。此模式不接受 `--project`；用 `--path` 限定时提供明确的绝对路径。Wombat 自己的临时发布内容需明确添加 `--wombat-temp`，不能与 `--codex` 同用，也不纳入正式索引、已用户数据和恢复代次。

结果区分“候选”“需要判断”“保留”“无法判断”和“原位置不存在”。同时说明归属、可再生成依据、观察到的大小和影响选择的条件。候选需要结合交付文件、待使用输出和当前占用复核；逻辑大小不等于实际可回收空间。

### 在终端确认 Codex 清理

下面的操作会永久删除选中的受支持 Codex 候选。需要保留的内容不要选择；项目构建产物的删除由 Codex 原生工具执行，不使用该入口。

```sh
wombat clean --codex --apply
```

此命令重新检查当前候选，展示完整路径及依据，再让用户选择具体条目并确认。按回车不会默认选择全部或确认删除。取消或不选择任何条目时不开始删除。选择仅用于本次命令，不读取隐式的“上次清理清单”。

执行前再次检查所选条目的身份、当前使用情况、版本及保护条件。新候选不会自动加入；条目变化、保护条件出现或证据未知时停止后续处理，并报告已移除、未处理和失败的条目。已完成的永久删除不会因取消自动恢复。

无交互终端时，该命令要求明确的原检查结果和选择，不等待确认输入。脚本调用方式见高级参数。程序不会用强制删除绕过未知或受保护的结果。

### 清理后复查

复制清理结果提供的 `clean verify` 命令，检查原来的条目。它只比较原选择，不重新扩大清理范围。对于项目产物，让 Skill 先核对归属与待使用输出，再使用可信工具清理，并按相同范围复查。

原路径不存在表示该路径的当前状态，不证明实际磁盘空间已经释放。永久删除没有通用恢复能力；保留项与未处理项会在结果中单列。

## 检查和维护安装：system

### 检查运行环境

```sh
wombat system doctor
wombat system doctor --project "/path/to/project"
wombat system doctor --hooks
```

`doctor` 分项显示程序安装、插件发现、运行资源匹配及当前项目识别情况。需要 Hook 原生注册证据时添加 `--hooks`。检查不安装内容、不运行模型，也不建立会话用量索引。

某项未知或失败不抹去其他已完成项。结果说明受影响的功能和具体下一步，例如选择项目、修复插件发现或处理资源版本不匹配。不要把所有检查失败都当成需要重新安装。

### 检查或安装更新

先检查是否有更新；下面的命令不安装内容。

```sh
wombat system update --check
```

决定升级后，下面的命令安装最新发行版。

```sh
wombat system update
```

需要安装特定发行版时，将 `VERSION` 换成实际版本号，再单独运行：

```sh
wombat system update --version VERSION
```

`update --version VERSION` 选择要安装的版本，与查看当前程序版本的 `wombat --version` 不同。

更新运行程序与插件资源匹配是不同结果。需要同步插件时，结果提供对应说明；运行程序更新成功不代表当前项目已发现匹配插件。安装前提与恢复方式见[安装指南](installation.md)和[插件指南](plugin.md)。

### 接口和集成入口

`system api` 和 `system call` 面向 Skill、脚本及需要详细控制的用户，提供账户、预算、价格、来源授权和偏好等接口。Wombat 在前台执行，不提供服务控制。

`system hook codex` 是接入程序使用的输入入口，不是日常检查命令。它保留独立的建议性接收协议：在四秒内接受最多 64 KiB，不输出 stdout，接收失败也不阻止宿主操作。接收成功不证明原生注册、加载或完整采集，也不改变权限或模型上下文。

## 高级参数

### 公共约定

参数只在适用的命令中接受。不支持的选项、重复的单值参数或互斥组合会给出错误与修改示例，不会静默忽略。命令名称使用完整拼写，不依赖自动缩写。含空格的路径和查询文字用引号包围。

| 参数 | 用途与适用范围 |
|---|---|
| `--help`、`-h` | 查看当前入口或子命令帮助；不启动查询或变更 |
| `--version` | 在顶层查看当前程序版本 |
| `--lang en\|zh` | 选择展示语言；也可用 `WOMBAT_LANG` |
| `--json` | 输出结构化结果；监视输出为逐行 JSON |
| `--no-input` | 禁止交互提问；缺少选择或确认条件时返回错误 |
| `--project PATH` | 为支持项目范围的查询、检查和清理选择明确目录 |
| `--since DATE --until DATE` | 成对提供自选日期，格式为 `YYYY-MM-DD`；起始包含当天，截止不含当天 |
| `--timezone ZONE` | 指定日期解释时区，例如 `Asia/Shanghai` 或 `UTC` |
| `--all-time` | 查询全部可用日期，包含日期未知记录；不能与日期边界同用 |
| `--root PATH` | 选择记录来源目录；可以重复；默认使用 `CODEX_HOME` 或 `~/.codex`，不是项目文件夹 |
| `--source ID` | 在支持的查询中限定明确的来源实例 |
| `--limit N --offset N` | 列表分页；不修改完整范围总量 |
| `--fresh`、`--cached` | 更新完整索引，或只读完整索引中最近一次提交的数据。两者互斥。 |

`DATE`、`PATH`、`RECORD`、`VERSION`、`PLAN_ID` 等大写词是说明占位符，不是直接输入的值。优先复制实际结果提供的完整下一步命令。自然语言请求中的“刚才那个”，由 Skill 保留其原选择；独立 CLI 调用不依赖隐藏的最近结果状态。

### 日期、范围和分页

```sh
wombat usage --since 2026-10-26 --until 2026-11-02 --timezone Asia/Shanghai
wombat history search "验收" --all-time --project "/path/to/project"
wombat usage top week --limit 10
```

显式时间词不能与 `--since`、`--until` 或 `--all-time` 混用。未写时间词时，成对的自选日期替换该命令的默认范围；缺少一端、无效或颠倒的范围会报错。日期在命令开始时按所选时区解析并固定，使用原明确日期的分页跨过午夜也不会自动改变范围。

普通列表默认每页 20 条，任务排行默认五条。列表的 `--limit` 可选 1..200 条，`--offset` 为非负整数。原文读取分别限制位置数量和文本字节数。继续查看时使用返回的命令或结构化游标，保留原范围。

完整 ID 和不透明游标仍绑定所选来源与条件。来源替换可能让位置失效，此时按原范围重新查询，不使用旧游标或重建旧证据。

### 用量筛选与对比

| 参数 | 用途 |
|---|---|
| `--model MODEL --effort LEVEL` | 按模型和推理强度筛选 |
| `--task RECORD` | 选择任务；自动化请求使用完整身份 |
| `--against RECORD` | 与 `--task` 一起比较两条工作记录 |
| `--family` | 在任务对比中纳入已记录的子任务关系 |
| `--baseline-since DATE --baseline-until DATE` | 与自选 `--since`、`--until` 一起指定周期对比 |
| `--group day\|week\|month` | 用量按日、周、月分组；不另外扩大已选日期 |
| `--by project\|model` | 为用量或任务分布选择维度；周期对比还可以选择 `task` |
| `--sort time\|tokens\|cost` | 用量列表排序；`top` 只接受 `tokens\|cost`，默认 Token；未知费用不当成零 |
| `--compact --json` | 保留完整总量与请求条目，减少质量详情中的样例和分面 |
| `--watch` | 持续查看变化的用量；仅用于实时用量，不与 `--cached` 同用 |
| `--rebuild`、`--include-history` | 明确重建派生数据或纳入历史来源；属于高级数据操作 |

周期对比与任务对比不能混用。更细的日期未知、模型未知、记录定位、输入轨迹、资源热点与风险线索，通过生成的自动化接口选择。统计保留缺失、已知部分与真实零值，不给工具操作分摊 Token 或费用。

### 检查、复查与明确决策

综合 `check` 支持日期、时区、项目和来源选择；日期只筛选相关历史，不把当前配置视作历史版本。`check skills` 和 `check mcp` 另支持分页选择。Skill 支持 `--sort review|context_tokens|least_activity|recent|name`；MCP 使用相同选项，但不提供缺少定义载荷的 `context_tokens` 排序。缺少占用或频率证据的条目单独标明，不当成零排列。

`check --task RECORD [--turn TURN]` 分析所选完整轮次；日期和配置检查参数不与该任务范围混用。需要限定日期的片段时，使用 `conversation` 的日期与轮次选择。`check verify --baseline check.json --suggestion ID` 使用原始检查条件，并接受原结果要求的来源、项目和规则参数。`--agents-bytes` 和 `--description-characters` 只调整对应产品提醒，不改变格式规范阈值。

`verify` 是普通命令中的名称；自动化接口仍使用生成契约中的 `recheck` 动作。名称调整不改变原问题、范围或比较条件。

需要保留某项或说明不适用时，通过 Skill 或 `system call` 的 `optimize` 方法明确记录理由和决策版本。这些写入独立于派生索引。清单详情、证据、关联范围与规则能力发现仍可通过 `config`、`optimize` 的结构化动作完成。

### 清理选择与非交互执行

```sh
wombat clean verify --plan cleanup.json --item ITEM
```

下列命令是明确删除请求，只有核对原候选并填入真实选择后才能使用。

```sh
wombat clean --apply --plan cleanup.json --item ITEM
```

大写占位符必须替换为原检查返回的值；不要把模板直接作为删除命令运行。复查可不传 `--item`，表示核对原范围；删除必须明确选择条目，`--item` 可以重复。删除只接受受支持的原 Codex 候选。

提供原计划的删除模式不接受新的 `--project`、`--path`、`--keep`、`--codex` 或 `--wombat-temp`，不扩展原选择。当前支持的对象仍会重新发现并校验保护条件。执行无需再次交互确认，授权来自明确的 apply 请求及选中 ID。批处理必须逐项检查结果。

项目模式不能直接添加 `--apply` 删除文件。需要清理项目产物时，由 Codex 使用可信工具处理具体已授权路径。重试前先核实哪些项已完成；取消不会撤销已经发生的永久删除。

<a id="automation"></a>

## Skill、脚本与自动化接口

### 按需发现方法

```sh
wombat system api
wombat system api usage --json
wombat system api usage --output-schema --json
```

无方法时列出方法及用途；指定方法时读取该方法的输入说明，`--output-schema` 同时读取输出说明。发现操作本地、只读，不扫描会话或调用模型。熟悉的请求可以直接执行，不必每次重新获取全部 Schema。

### 执行结构化请求

`system call` 从标准输入读取一个 JSON 对象，始终返回该方法的结构化结果。可将请求保存为文件；文件中的目录、日期、完整身份和版本应来自明确选择或前一次结果，而不是标题猜测。

```sh
wombat system call < request.json
```

PowerShell 7 可以使用下面的 UTF-8 文件输入方式。

```powershell
Get-Content -Raw -Encoding UTF8 request.json | wombat system call
```

例如，请求用量较多的三条任务时，`request.json` 的内容为：

```json
{"method":"usage","params":{"query":{"action":"threads","sort":"tokens","limit":3,"compact":true},"mode":"auto"}}
```

结构化请求独立于普通命令的自然日期默认值。上例没有指定日期，应按返回的 `scope` 解释；要回答今天或指定周期的问题，明确传入日期与时区。返回的数据版本仅供追溯，不作为后续选择参数；每条命令读取当前事实或明确选择的缓存事实。

输入最多 1 MiB，在十秒内读完一个对象；输出最多 2 MiB。只有 stdin 和 stdout 都连接交互终端，且没有 `--json` 或 `--no-input` 时，普通命令才可提问。其他情况及 `system call` 不等待问题选择或删除确认。歧义、缺参数或范围冲突通过相应格式的错误返回，不扩大范围或选择第一个匹配。

完整 ID 无需扫描活动即可定位元数据，日期筛选仍约束后续原文读取。标题查找达到预算上限时返回 `SCAN_INCOMPLETE`，并在 `error.details.next` 中提供续查请求，通过 `system call` 执行。该状态与数据准备状态不同，不要求刷新索引。

### 完整方法范围

`history read` 的 JSON 在 `result` 中返回有界原文、说话者、时间与片段游标。在 `alsoAt` 中查看同一片段的其他位置。`nextLocations` 是下一页位置请求，可传给 `system call` 的 `conversation` 方法。续读原文时，使用对应位置的证据和游标。在 `readIssues` 中查看失败或推迟的目标。共用的上下文正文在 `neighbors` 中，各位置通过 `visibleContext` 引用消息 ID。遇到响应上限时，把返回的 `retryRead` 传给 `system call` 读取剩余目标。

| 方法 | 可执行的动作 | 作用与边界 |
|---|---|---|
| `usage` | `usage`、`threads`、`turns`、`steps`、`statistics`、`compare`、`investigate`、`trajectory`、`resources`、`review`、`context` | 当前用量及分析；返回 `result` 和数据状态 |
| `project` | 组合当前项目证据 | 配置、检查、工作记录、原用量及清理候选；各部分独立说明状态与读取版本，不修改项目 |
| `conversation` | `resolve`、`records`、`activity`、`locate`、`search`、`read` | 活动、位置及原文；记录不等于已验收的代码交付 |
| `config` | `list`、`detail`、`evidence`、`related_scopes`、`capabilities` | 配置清单、计量、原生观察及关联使用；只读 |
| `optimize` | `list`、`detail`、`checks`、`activity`、`capabilities`、`recheck`、`keep`、`not_applicable` | 检查与比较；只有明确决策写入用户存储 |
| `artifacts` | `inspect`、`recheck`、`apply` | 清理观察和受保护的 Codex 删除；不依赖会话索引 |
| `timing` | `summary`、`evidence`、`capabilities` | 指定任务与轮次的过程证据，缺失时间不填零 |
| `setup` | 观察运行与原生集成 | 检查兼容性与发现状态，不执行安装或模型任务 |
| `account` | `read`、`refresh`、`history` | 账户及额度观察，不能推算某个项目的订阅余额 |
| `monitor` | `list`、`upsert`、`remove`、`check`、`acknowledge` | 预算计划与提醒；保存计划不自动启动监视命令 |
| `prices` | `status`、`update`、`auto_update` | 辅助计价资料；失败保留原价格，不修改原始 Token |
| `directories` | `list`、`authorize`、`revoke` | 明确路径和用途的目录授权 |
| `preferences` | `get`、`set` | 展示语言等受支持偏好，不修改来源文本 |
| `collection` | `status`、`events`、`configure`、`pause`、`resume` | 可选接收观察与控制，不证明完整历史覆盖 |

具体字段、允许组合、版本与限制由对应生成 Schema 提供，不从表格自行拼接未知参数。`usage`、`conversation` 和 `timing` 的选择结构不同，不能互换；完整身份、原始筛选、来源位置和每种游标各自保留。

### 保存范围并处理失败

Skill 负责把用户问题转为范围明确的查询，按需读取证据，并在授权后使用原生工具修改或恢复。日报、接续工作和知识整理组合这些能力完成，不默认新增报告数据库、自动执行历史或每日发送流程。

脚本应检查退出码、数据状态和逐项结果。超时或取消会停止本次内核进程。已完成的写入可能已经生效；先检查状态再决定是否重试，不能自动重复删除、授权或决策写入。

<a id="recovery"></a>

## 结果、错误与恢复

### 数据状态

| 看到的情况 | 含义 | 下一步 |
|---|---|---|
| 完整结果 | 当前范围已得到可用完整结果 | 按需要查看明细或继续任务 |
| 范围内没有匹配 | 已完成的查询未找到匹配项 | 检查关键词、项目和日期；需要时明确扩大范围 |
| 结果不完整 | 部分来源、时间、身份或操作无法确认 | 使用已知事实，缩小到明确记录，保留缺口 |
| 指标未测得 | 该指标缺可靠观察 | 不填零，不据此停用、删除或宣布改善 |
| 来源游标失效 | 引用的来源或位置已经变化 | 按原条件重新查询，不继续使用该游标 |

### 常见问题

| 问题 | 处理方式 |
|---|---|
| 找不到 `wombat` 命令 | 按安装指南检查命令位置与终端环境 |
| 找不到某条历史记录 | 先核对来源、项目、日期及关键词，再明确查询更早范围 |
| 多条记录标题相同 | 交互选择时间和项目，或使用完整 ID；不默认选第一条 |
| 当前目录不是目标项目 | 传入 `--project` 或在终端提示中提供明确文件夹 |
| 安装成功但插件未发现 | 运行 `system doctor`，按具体分项结果处理发现或资源问题 |
| 配置格式或参数不支持 | 查看该命令帮助或该方法 Schema，按原任务修改输入 |
| 请求超出读取范围或预算 | 缩小到项目、任务、日期或轮次；继续原游标，不反复扩大读取 |
| 原始记录在读取期间变化 | 按原范围重新查询，不使用失效游标，不替换旧原文或声称成功 |
| 索引格式不支持 | 保留原数据；明确重建派生索引 |
| 清理条目变化、被保护或无法确认 | 保留已完成结果，重新检查剩余具体对象，不用强制删除绕过 |

### 重建派生索引

仅在诊断明确要求重建派生索引时使用下面的命令。它重新读取所选来源，可能需要等待。若使用自选来源，应保留原来的 `--root`。

```sh
wombat usage --rebuild
```

新索引成功前保留原有效数据，用户决定与授权独立保留。不要删除原始会话文件来处理索引问题。

### 输出与退出码

普通结果写入 stdout，进度与诊断写入 stderr。`--json` 和 `system call` 的结果及错误使用结构化输出，原始内容和协议标识不翻译。不会因为输出被管道接走就自动改变格式。

| 退出码 | 含义 |
|---|---|
| `0` | 命令按其约定完成，包含完整空结果 |
| `2` | 有可用结果，但存在部分、暂定或需要说明的状态 |
| `1` | 参数或执行失败 |
| `130` | 用户取消本调用 |

可选指标未知不自动表示整个任务失败；仍需结合范围覆盖与结果状态判断。`system hook codex` 使用前述独立的建议性接收协议，不能用它的退出码判断业务检查成功。

### 原始记录与恢复边界

工作记录保持只读。索引是可重建的派生数据；用户明确保存的决定、身份和授权独立保留。重建前保留现有数据，新的代次准备成功后再切换，失败不破坏原有效代次。未知格式不会触发隐式迁移或删除。

历史和统计来自本地记录，查询不调用模型。程序更新与价格补全可能访问网络；需要禁用自动补价时可设置 `WOMBAT_AUTO_PRICES=0`。每份结果记录其价格依据。对外发送记录内容需要另行授权。

缓存命中、较低用量、候选路径消失、用户决定保留，以及检查命令成功，都不自动证明工作已交付或效果已改善。需要结论时，回到原问题、同样的检查条件和实际项目验证。

<a id="terms"></a>

## 名词说明

| 名词 | 在本指南中的意思 |
|---|---|
| 工作记录 | 来源中的一次会话，不等于已经完成或验收的工作 |
| 轮次 | 工作记录中可识别的一次交互范围，不把每次工具操作都视为独立轮次 |
| Token | 模型处理内容的计量单位，不等于中文字数或单词数 |
| 来源 | 被选中读取的本地记录目录及其来源身份，不是要检查的项目目录 |
| 数据版本 | 一份结果的追溯信息，不是租约或后续请求参数 |
| 基线 | 原问题及其比较条件，用于判断修改前后能否有效比较 |
| 清理候选 | 有清理依据、仍需核对用途与保护条件的对象，不等于删除授权 |
| Schema | 可由程序读取的请求与结果字段说明 |
| ID、游标 | 程序定位记录、对象或后续页的标识；普通用户优先复制返回的完整命令 |

## 继续使用

只需记住与当前任务相关的一条命令。更多用法可以先看对应 `--help`，也可以在 Codex 中说明目标，让 Wombat Skill 负责选择范围、定位证据和携带复查条件。后续接口字段以生成说明为准；来源、统计与保护条件在人工和自动化调用中保持一致。

记录续查把省略的 offset 与零视为等价；保留原选择范围、查询词和非零 offset。游标不匹配时返回 `CURSOR_MISMATCH`，指出字段及接口说明命令。项目／日期筛选复用事件帧时间索引跳过范围外事件，仍保留没有对话正文的工作记录。
