# Wombat 双语文档流程

中文 | [English](workflow.en.md)

面向读者的公开文档均维护中英文版本，现有说明文档已完成配对。两种语言具有同等效力；可以先修改任一版本，再在同一次改动中同步另一版本。术语以[术语表](terminology.md)为准，内容归属以[文档维护约定](../AGENTS.md)为准。

## 文件与范围

各目录统一使用英文 `README.md` 和中文 `README.zh-CN.md`。其他文档沿用现有中文路径 `docs/foo.md`，英文版本为同目录下的 `docs/foo.en.md`，确认记录为 `docs/foo.i18n.json`。贡献与安全说明放在 `.github/`；这些仓库入口页的确认记录统一放在 `docs/i18n/records/`。版本 2 的记录以英文标题路径为键，逐节保存中英文内容的 SHA-256 哈希。代码块逐字比较，不计入章节正文哈希；各章节的记录独立更新，以减少合并冲突。哈希只能确认所记录的内容版本，不能证明翻译质量。

[配对清单](../../scripts/doc-i18n.manifest.json)列出全部配对页面及明确豁免项；`legacyUnpaired` 当前为空，不得用它登记新增单语文档。仓库根目录和各模块的 README，以及有效决策记录，也须逐份配对。新增公开文档必须同时加入中英文版本；引入外部旧文档时，也须补齐两种语言和确认记录。自动翻译草稿未经审校，不得确认为已配对版本。`AGENTS.md`、术语表、生成的 Schema 与注明日期的测量材料不属于逐页翻译范围。

## 修改流程

1. 先核实源码、契约和本次验证证据，再修改事实所属页面；不要从历史记录推断当前能力。
2. 同步另一语言中受影响的段落。两种版本的标题层级、列表结构、命令和代码块保持一致；文档链接指向已有的对应语言版本，豁免文档和机器可读证据的链接保持同一目标。
3. 按下文的语言审校要求核对译文，再执行 `corepack pnpm docs:i18n:record -- <中文文件>`。只更新已审校且明确指定的配对记录。
4. 执行 `corepack pnpm docs:check` 和 `git diff --check`，查看两种语言及记录的差异。

校验使用 Markdown 语法树，检查配对完整性、章节哈希、语言切换链接、标题层级、嵌套列表与起始编号、表格行列、代码块，以及含查询参数或片段标识的链接目标。它不能判断两种语言是否表达相同事实，也不能判断表达是否自然；这些内容仍由修改者审校。清单明确列出豁免范围，校验通过不表示产品中所有来源原文都已翻译。

## 语言审校

技术文档采用 [ASD-STE100 Issue 9](https://www.asd-ste100.org/) 作为英文写作与审校规范，覆盖操作说明、技术参考和模块说明。审校须同时依据官方写作规则和词典；项目术语按标准中技术名词和技术动词的规则处理。术语表用于保持中英文一致，不替代官方词典。中文采用适用的受控写作原则，保留中文语法和表达习惯。

操作说明用主动语态和祈使句明确动作；每步聚焦一项操作，先说明执行条件和必要警告。说明性文字每句表达一个主要意思，每段围绕一个主题。保留条件、限制和失败处理，不为缩短句子而删减必要信息。代码、命令和固定引用保持原样。

配对检查不验证 ASD-STE100 合规性。只有完成官方写作规则和词典审校后，才能声明英文文档符合该标准；审校未完成时，应明确范围和未验证项，不把检查通过当作合规证明。

译文应符合目标语言的表达习惯，同时保留相同的事实和约束。逐段对应含义，不要求逐句照搬词序或句长；可以在段内拆分或合并句子，但须保留配对检查要求的结构。

- 中文明确写出动作和对象，避免连续堆叠抽象名词、照搬英文被动句或省略必要主语。使用中文标点，中文与英文、数字及行内代码之间保留适当空格。
- 英文使用自然的主谓结构，按语境处理冠词、单复数、时态和介词。操作说明使用明确的动词，避免照搬中文的省略句或堆叠名词修饰语。
- 同一概念沿用术语表，按语境翻译说明文字；命令、字段、协议值、稳定标识和来源原文保持原样。链接文字可以翻译，但必须指向同一内容的对应版本。
- 对照核实执行者、条件、否定范围、数量、单位、限制和确定程度。不得把「计划」「可能」或「尚未验证」改成已交付或已验证的结论。最后分别通读两个版本，确认读者无需参照另一语言即可理解。

## 增量维护

本地化界面图片在配对清单的 `assetPairs` 中登记中文与英文路径；检查文件存在、配对唯一和 README 链接的语言归属，不自动判断图片译文。图片内容须人工审校，非本地化 Logo 共用同一文件。

日常修改先读术语表，直接同步改变的段落，保留未变译文。不得为了让检查通过而无审校重录哈希。删除或重命名文档时，两种语言与记录同时处理。

`corepack pnpm docs:i18n:check -- docs/i18n/README.md` 仅验证指定配对的正文；仓库检查仍验证全体配对。失败会指出改变的章节与语言。`node scripts/check-doc-i18n.mjs --migrate` 只迁移内容仍与旧整篇确认哈希完全一致的记录，不确认新翻译。新记录保持 JSON，该命令不重命名文件或调整配对范围。

产品语言与文档翻译分开维护，见[产品语言与文案](product.md)。
