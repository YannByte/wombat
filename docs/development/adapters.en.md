## Current support boundaries

- Version one parses rollout `session_meta`, `turn_context`, historical `thread_settings_applied`, modern `token_usage_record`, legacy `token_count`, turn lifecycles, tool calls/returns, supported `item_started/item_completed`, and compacted measurement copies. This does not promise all historical Codex versions or arbitrary new events.
- Where modern same-turn records lack cumulative coverage, select the per-response ledger and disclose that legacy coverage cannot be checked. When cumulative intervals only partly overlap direct records, do not add the overlapping legacy total; mark the source partial. Actual cost in the uncovered portion cannot be reliably reconstructed from those records.
- Legacy cumulative measurements require an explicit fork relationship and identical events to establish replay. Native operation replay requires explicit ancestry and matching upstream turn/call identities; see the [decision](../decisions/implemented/architecture/2026-10-04-mcp-runtime-evidence.en.md). Similar content without identity evidence cannot be deduplicated using approximate tokens or time. Operations without exclusive accounting receive no allocated cost.
- Retain only event types, tool names, explicit paths, MCP server/tool, exit codes, durations, status, identities, and provenance; never replay conversation bodies. Observed Skill adoption accepts only a positive assistant statement matching a native catalog name, a structured file path, or bounded literal `cat/sed/head/tail/bat` reads inside the `exec` wrapper; arbitrary shell is neither executed nor interpreted. AGENTS.md loads require native Codex content-kind metadata and are never inferred from user text.
- Reusable buffers read large log lines completely. Selective deserialization skips almost all message/output bodies; one native-tagged AGENTS.md content item is decoded only long enough to extract its header path and is then discarded. Accounting, conversation, and operation metadata still occupy memory during source reconciliation. Depth, file-count, byte, and title-index limits produce receipts; this is not unbounded or constant-memory scanning.
- Tool returns without reliable success/failure fields remain unknown instead of retaining the start event’s running state. Unknown returns do not erase known failure, cancellation or success; replayed starts do not reopen operations.
- Native titles come from `session_index.jsonl` in the same source. Missing titles remain missing rather than being generated from user questions. Repeated settings, failures, and missing fields follow source evidence.

Run `cargo test --locked --manifest-path core/Cargo.toml adapters` and `cargo test --locked --manifest-path core/Cargo.toml pricing`. Build with `corepack pnpm build` before complete CLI integration tests. Record actual results in the task or CI and keep outstanding acceptance in its owning proposal; test names on this page are not proof that a run passed.
