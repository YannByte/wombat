# Wombat user plugin

[中文](plugin.md) | English

This directory owns user plugin source. Skill workflows live under `skills/`, Hook declarations under `hooks/`, and collection scripts under `scripts/`. Repository development workflows remain in `.agents/skills/`. `plugin/package.json` declares the shipped Skill entries; their user tasks and invocation names are listed in the [plugin guide](../guides/plugin.en.md). Each Skill serves Chinese and English and loads task references as needed. Shared runtime rules and references live under `skills/wombat/references/`; task entries link to that owner instead of copying rules. Shared [answer rules](../../plugin/skills/wombat/references/expression.md) apply STE writing principles to both languages. English uses the standard’s sentence limits. Chinese uses natural grammar without English word-count limits. The guidance favors clear, natural wording without strict dictionary matching. It does not certify generated answers. `agents/openai.yaml` uses JSON-form YAML and owns the display name, short description and default prompt. The build reads this source for plugin interfaces and substitutes the plugin invocation name. See [AGENTS.md](../../plugin/AGENTS.md) for maintenance rules.

The build extracts `dist/skill/wombat` standalone resources from `skills/wombat/`, copies all declared Skills into `dist/skill/plugin` and generates a local marketplace, and adds collection resources only to the collection package. Release archives retain these assets under `lib/skill`. `package.json` owns plugin metadata and required capabilities; the root manifest alone owns the version. Build-generated `plugin.json` and `.codex-plugin/plugin.json` supply the supported host formats. This source directory requires a build before plugin installation. The standalone manifest binds version, source commit, file inventory and hashes; `wombat-runtime.json` binds the plugin version, content hash and required capabilities. The standalone hash covers the general query Skill; plugin metadata binds each declared Skill hash and their combined hash. Both modes share required runtime capabilities. The standalone installation contains only the general query entry; task entries require the plugin bundle. The recommended [installation command](../guides/installation.en.md) installs the runtime and Codex plugin together, then verifies discovery and runtime compatibility; opening Web is optional. It keeps an existing enabled collection plugin; a new installation selects the base plugin. Rerunning the installer with the plugin option updates the local marketplace to the selected runtime version. The plugin-only retry uses the current managed runtime and performs no archive download or PATH change; see installation for options.

Codex owns formal plugin management. The local trial entry is:

```sh
corepack pnpm build
codex plugin marketplace add ./dist/skill
codex plugin add wombat@wombat-local
```

On Codex 0.160.0 the plugin invocation name is $wombat:wombat. For standalone trials, wombat skill install defaults to ~/.agents/skills/wombat with invocation $wombat. status reports files and native discovery separately; uninstall removes only unchanged managed copies. Choose one installation mode; users select among existing multiple instances. Installation does not scan logs or read login credentials, and does not establish data readiness.

Local marketplace installation, enabled discovery and removal have been verified on Codex 0.160.0 on macOS. Packaged marketplace roots live under lib/skill in the selected managed version. No public marketplace submission or public plugin installation page is claimed. Codex manages plugin updates and removal; the runtime-only `wombat update` command does not update the plugin. Remove the chosen plugin with `codex plugin remove wombat@wombat-local` or `codex plugin remove wombat-collection@wombat-local`. Before switching from a standalone copy, use `wombat skill uninstall --json` to remove an unchanged managed copy; modified copies remain for manual review. Discovery, queue acceptance, browser interaction and data readiness require separate acceptance. Other platforms and complete conversational journeys remain unverified.

See the [product plan](../decisions/proposed/product/2026-10-04-codex-skill.en.md) for both entries, initialization, and responsibilities; the [CLI guide](../guides/cli.en.md) for arguments and scope; and [installation](../guides/installation.en.md) for the local runtime.

## Local collection package

The same build also produces `dist/skill/collection-plugin` and a `wombat-collection@wombat-local` catalog entry. It shares the declared Skill set and includes reviewed Hook declarations from `hooks/` and the minimal POSIX shell bridge from `scripts/`. The skills-only base plugin excludes both directories and has no lifecycle Hook declaration. Choose one plugin or standalone Skill mode to avoid competing enabled instances; actual native discovery supplies the invocation name.

For a source-build trial, register `./dist/skill` as above, then install `codex plugin add wombat-collection@wombat-local` instead of the base plugin. An installed archive keeps the same marketplace under `lib/skill`. The bridge prefers the managed user launcher with its ownership marker, then `wombat` on Codex’s PATH. A custom prefix needs that PATH entry. Collection mode and native Hook trust remain explicit separate steps; use the [CLI collection guide](../guides/cli.en.md). Installing or removing the plugin does not remove product data or modify other Hook declarations. The POSIX bridge is implemented; Windows and full native event acceptance remain unverified. Hooks plugins are for local manual installation and cannot claim public-directory publication.

The local collection package uses only the generated `.codex-plugin/plugin.json`. On Codex 0.160.1, a root manifest suppresses its Hook registrations; the skills-only package retains the standard root manifest. Native installation acceptance must detect this difference. Run `corepack pnpm verify:skill-native -- --output-dir /tmp/wombat-native --codex-bin /absolute/path/to/codex` with a fresh profile; it checks installation, discovery, untrusted registration, and data-preserving removal. It does not establish Hook execution or public distribution.

Run `corepack pnpm verify:skill-conversation -- --output-dir /tmp/wombat-conversations --agent-bin /absolute/path/to/codex --language both` after a build to qualify selected real Codex conversations over synthetic usage, allowance and configuration. The default `workflow` scenario confirms the same fixed version and project through Web, resumes the exact session for an authorized description edit, and checks the original suggestion, user decision and unchanged navigation artifact. `--scenario usage|pricing|timing|statistics|monitor|account|daily-review|task-retro|config-review` selects a focused task; `--scenario all` selects every scenario. `--variant 0..3` selects paired natural-question variants for focused reads. The three task scenarios select their own Skill. Configuration review starts read-only, then resumes the exact session for a description-only authorized edit and rechecks the original suggestion. Other focused tasks remain read-only. Usage follow-ups change the date interval and then the authorized project while retaining the original snapshot. Each case starts with absent product-data and runtime paths; only that case's follow-up resumes its generated state. Each case owns a temporary resident core until cleanup, so model latency cannot expire its local service. Configuration checks compare the complete fixture Skill directory, allowing only the authorized description change. Checks retain capability scope, independent facts and unchanged sources, decisions and budgets, plus unchanged configuration outside authorized follow-ups. Reports retain command counts, output bytes and native Token observations; a human reviews natural answers for clarity and qualifications. Use a fresh external output directory. Native model execution uses the current authentication profile without reading or copying credentials. The verifier does not change Hook trust or establish all real-project journeys.

After reviewing and trusting the collection declarations in native `codex` → `/hooks`, run `corepack pnpm verify:skill-native-events -- --output-dir /tmp/wombat-native-events --codex-bin /absolute/path/to/codex --wombat-bin /absolute/path/to/wombat --project /absolute/project --source-root /absolute/codex-home`. This explicit real-profile check creates one new read-only `pwd` task, verifies actual common-event receipt, and rechecks exact task/turn association against committed log facts. It preserves source files and credentials, stores private evidence outside the repository, and leaves safe receipts and derived indexes in product storage. It requires existing native trust and never grants or bypasses it. Unobserved lifecycle events remain unverified. Add `--session UUID` with a fresh output directory to recheck that exact native session without another model task. Log preparation waits at most 5 minutes; timeouts or storage failures retain evidence. A pinned usage reread checks that receipts do not add accounting.
