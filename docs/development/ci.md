# CI 执行与构建复用

中文 | [English](ci.en.md)

main 的 push 运行互不取消；同一 PR 的连续运行取消旧任务。只有确认仅修改说明文档的 PR 才跳过重型矩阵；产品指令、Skill 资源、生成协议和许可证清单仍须验证。名为 `CI` 的轻量最终检查始终给出结果；必要阶段失败、取消或意外跳过时，该检查失败。分支保护应使用这个稳定检查。main 和显式完整调度始终运行全部检查，包括 main 上的纯文档提交，保持发版来源校验不变。

来源规则只在 Ubuntu 运行一次。来源工具及构建前测试保留 Linux、macOS、Windows 覆盖。Rust lint 和内核测试在每个原生目标上运行，并与发布构建并行。每个平台的发布构建运行单元、集成、端到端测试、启动检查和许可证验证。类型与生成协议只在 Linux 运行一次，并复用已经构建的内核。五个平台的归档仍执行原生安装与升级验收。归档装配复用已经测试的 Linux 包和各目标已经验证的内核、运行时及声明，不再额外编译 Rust。

Node 设置 action 按锁文件缓存 pnpm store。Rust 任务按原生目标和来源输入分别缓存发布、测试产物，只有 main 写入 Rust 缓存。不缓存交付运行时、归档或 node_modules；仅涉及 JavaScript 的任务不恢复 Rust 缓存。仓库缓存总量保持在默认 10 GB 预算内。CI 工具使用固定版本的预编译发行包，校验下载内容，不回退到现场编译。

构建入口复用前检查来源身份、提交、编译环境以及打包和模块输出的哈希。输入或输出缺失、变化时重新构建。连续第二次构建在内容不变时不再编译或打包。协议检查复用已验证的发布内核；没有有效构建时，编译用于生成 Schema 的 debug 程序。分析最近 50 次工作流，运行 `corepack pnpm ci:timings -- --output-dir /tmp/wombat-ci --label before --logs`。报告分别保留运行器排队、准备、验证和依赖等待，并标明无法恢复阶段边界的历史混合步骤。使用 `--run ID --label after` 对照实测运行，使用 `--reuse` 避免重复下载未变化的证据。

耗时中位数不计失败或已取消的运行。
