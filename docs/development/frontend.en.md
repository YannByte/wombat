# Web frontend

[中文](frontend.md) | English

`@wombat/ui` is the React / TypeScript / Vite presentation module. `App` receives `UsageClient`; the browser entry wires HTTP and the access token. Rust supplies scanning, pricing, totals, grouping, and matching-usage sorting. Old TUI pages are not migrated.

## Running

Build and start from the repository root:

```sh
corepack pnpm build
node dist/wombat.js web --lang zh
```

Open the printed link; the page reads local records, and Ctrl+C stops the service. Use `--root` for sources and `--port` for a port. The service listens on loopback only; the token remains in the browser session, and a service restart requires a new link.

## Internal responsibilities

Overview, tasks and related configuration share internal return paths, preserving each level's filters, turn and operation-page selection. `navigation.ts` and `useNavigation.ts` manage reading positions: memory retains at most 24 views, while the current history entry stores bounded scroll, expansion and focus metadata so reload can restore the current position. Restoration waits for asynchronous content, and user input takes immediate precedence. Conversation bodies are not stored. Usage dialogs are not persisted as cross-page business records.

`App` assembles routes and shared context; `shell/` owns navigation, dates/filters and sources; `config/` owns evidence details and measurement labels; `optimize/` owns suggestion details and rule evidence. Query lifecycle stays in the corresponding hooks; business rules and user-record persistence stay in Rust. Pages use current routes and independent filter state.

## State and queries

Dates include both endpoints and convert to an exclusive API end; all dates includes and labels unknown dates; changing day/week/month leaves dates unchanged. All input includes cache reads/writes, while reasoning is a subset of output; existing `tokens.input` retains its uncached meaning. Derived values and directory/model groups come from generated contracts, with equivalent CLI queries.

URLs retain scope, filters, search, sorting, trend/conversation/turn pages and selection for browser back/forward. While visible, the page checks the current version about three seconds after each query completes. Unchanged versions do not reload lists; hidden pages pause and catch up when visible again. Reading conversations or expanding period details pins the current version and offers new data for explicit application; applying it retains same-scope detail expansion and pagination. Pending or failed synchronization exposes the previous-result state and keeps retrying. Explicit cancellation pauses automatic updates until navigation or retry. Expired credentials stop observation and direct users to the latest full terminal link. Empty views distinguish missing logs, incomplete source reads and unmatched filters, offering source details, filter reset and available dates.

The turn execution panel reads activity inspection from the same fixed snapshot, source, task, and turn as its timing summary. Advice first shows concrete counts or recorded ratios, next steps, and evidence links using the same presentation as CLI. The expanded section retains all five checks, thresholds, samples, and evidence limitations. Failure-share checks show determinate sample counts, failure counts, and explicit thresholds; small samples retain statistics and an explanation. Evidence buttons open the existing whole-turn record collection. Usage investigation and review candidates show measured values and next steps for signals already returned by the core. Missing values remain unknown, and views do not evaluate thresholds again. Leaving the selection cancels the read and discards late results. Expiry disables evidence actions while retaining the previous facts; local read errors allow retry. Synthetic previews use this production component with mock client responses.

The main list and trend update together at one fixed version; expiry triggers one reread with a notice outside turn execution. Turn execution retains its prior group and asks for an explicit whole-group refresh after expiry. The query cache holds at most 16 entries for a single version. Turns default to matching measurements; switching to full context locates the selected turn. Turns use 20 items per page and events 100. The trend uses 120 periods per page; expanded period details use 12 periods per page, and model/effort details load only for the expanded period. Full-scope totals, sorting and chart scales come from the core, never from the current page; queries no longer drain every page. Details within one period still use the core’s complete group and remain subject to the host response limit.

Failure/cancellation retains the last complete main view and allows drill-down for the same scope; a previous scope cannot be operated as the new scope; local detail failures can be retried independently. Detail identity includes version, scope, selection and page, so late responses cannot replace newer queries; scope changes reset detail pages. Browser reload retains the URL and reads a version again; the browser stores the theme, not results or full conversations. Period-detail and event pages stay inside their components and do not survive reload.

Only public client interfaces and locale services are imported, without Node, Tauri, terminal or raw source access. A full build copies static assets into `dist/web/`; rebuild and restart after edits. The desktop host remains unimplemented; see [architecture](architecture.en.md).

Builds and static checks do not replace real interaction or pixel comparison.

Configuration pages do not poll; explicit reload updates configuration and usage, and expiry requests a fresh read. Configuration layout lives in `src/config.css`; see the [configuration contract](contracts.en.md) for scope.

Tokens or amounts open the same right drawer, querying time/models/projects/related tasks against fixed usage. Optimize merges findings by object. URLs retain category, pending/history, suggestion/separate record identity, read view and decision revision. Details put the issue and actionable evidence first. Format diagnostics show the file, line/column, field, reason, and current/valid structures without retaining field values; rule versions, thresholds and methods remain collapsed. The primary interface has no single or batch dispatch buttons. “Use with Skill” in the header provides the discovered invocation and example questions. After inspecting evidence, review and handle objects in the current Codex conversation, then recheck in Web. Path copying still helps locate objects; initial observations preserve original evidence. Recheck comparisons consume the core’s explicit comparable/incomparable/unknown state; current file values never establish resolution. User decisions and their reasons remain separate from current facts and the immutable baseline.
