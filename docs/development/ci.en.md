# CI execution and build reuse

[中文](ci.md) | English

Main push runs never cancel one another. Consecutive runs for the same PR cancel older work. Only confirmed prose-only PR changes skip the heavy matrix; product instructions, Skill resources, generated schemas and license inventories still run it. The lightweight final check named `CI` always resolves and fails when a required stage fails, is cancelled or is unexpectedly skipped. Use this stable check for branch protection. Main and explicit full dispatches always run all checks, including documentation-only main commits, so release-source verification remains unchanged.

Source rules run once on Ubuntu. Source-tool and prebuild tests retain Linux, macOS and Windows coverage. Rust lint and core tests run on every native target in parallel with release builds. Each native release build runs platform unit, integration and end-to-end tests, startup checks and license verification. Types and generated contracts run once on Linux against its already built core. Five target archives still receive native installation and upgrade acceptance. Archive assembly reuses the tested Linux bundle and each target's verified core, runtime and notices; it performs no extra Rust build.

The Node setup action caches only the pnpm store by lockfile. Swatinem caches Rust dependency artifacts by native target and build profile, excluding workspace crates; only main writes these dependency caches. A separate official cache action stores current-project compiler outputs after successful jobs, using GitHub's reference scopes for PR caches. Do not cache shipped runtimes, archives or node_modules, or restore Rust caches in JavaScript-only jobs. Keep total repository cache usage within the default 10 GB budget. CI tools use pinned prebuilt releases with checksum verification and no source-compilation fallback.

Swatinem's `shared-key` overrides `key`; do not combine them. The workspace cache key includes the actual compiler, runner image, declared compiler settings, source, Cargo manifests, embedded prices, test fixtures and build recipe. Dependency restore runs first. Workspace restore follows it, so its automatic save runs before dependency cleanup. Cache paths include crate fingerprints, library metadata and native outputs, including MSVC's unhashed executable. Only an exact workspace hit permits normalization of checkout file times; a dependency-only restore leaves source times fresh and Cargo recompiles the project. The source gate rejects ignored keys, incomplete source bindings and unsafe cleanup order. Native regression builds a library and executable, restores the actual configured outputs, checks debug/release reuse and verifies recompilation after a source change.

After cache restore, `corepack pnpm licenses:prepare` fetches the complete locked Rust source set without compilation. License generation and checking remain offline, including notices for inactive locked packages.

The build entry checks source identity, revision, compiler environment and hashes of bundled and module outputs before reuse. Missing or changed inputs/outputs force a build. A second unchanged build does no compilation or bundling. Contract checks reuse a verified release core; without a valid build they compile the debug schema producer. To inspect the latest 50 workflow runs, use `corepack pnpm ci:timings -- --output-dir /tmp/wombat-ci --label before --logs`. Reports separate runner queue, preparation and validation, retain dependency waiting separately, and identify historical combined steps whose boundaries cannot be recovered. Use `--run ID --label after` for a measured comparison and `--reuse` to avoid downloading unchanged evidence again.
