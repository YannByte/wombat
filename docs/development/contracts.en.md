The separate `prices` interface provides status/update with `outputVersion=1`.

See [CLI](../guides/cli.en.md) for operations, enums, pagination, and errors. Measurement integers cannot exceed JavaScript's safe integer range; amounts remain decimal strings. New fields and rules require checking generated types, CLI JSON and current snapshots together.

Charts, sorting, and peaks use these analyzed subtotals; fractions require complete analyzed coverage in the same scope. Pricing continues to use original measurements. Independently versioned optional analysis preserves immutable native-only review records. Rust-generated contracts own public types, fields, and enums.

With either explicit presentation, offset/limit/page.total count periods; a detail page includes every model row for those periods without splitting groups. Omitting presentation retains existing row pagination. The core computes both `sort: cost` and token ordering by analyzed subtotals. Threads sort by matchedUsage or latest matching measurement; threadUsage retains full usage. Turns remain complete by default. Only turns accepts matchedOnly and locateTurnId, filtering and sorting before locating a page. Foreground calls complete synchronization before returning collected facts. Cached reads use committed SQLite facts and never create a provisional view.

## Client entries

`@wombat/client` exports generated request and result types. `UsageClient.query(request, options)` reads current usage; Node supplies `live({query,mode,verify}, options)` for explicit auto/fresh/cached controls. Both use the foreground core boundary. `createUsageClient` validates narrow transports and results. The portable entry has no Node or React dependency.

`@wombat/client/node` provides `createNodeClient({ binaryPath, timeoutMs, maxResponseBytes })` and owns local subprocess lifecycles. Callers do not handle arbitrary core operation strings. Other hosts can implement the same narrow transports and reuse generated contracts and validators.

Node's price transport downloads only the fixed official HTTPS document. The host request for the core `prices` operation includes document for update; status rejects it. Raw documents are absent from public request/response types. Rust parses and publishes them; other hosts must implement the same fixed-source retrieval flow.

## Whole-turn timing contract v8

`core/src/timing_dto.rs` defines the typed `timing` operation. Generated contracts include [requests](../schemas/timing-request-v2.schema.json), the [response union](../schemas/timing-response-v8.schema.json), [local](../schemas/timing-local-response-v8.schema.json) and [share](../schemas/timing-share-response-v8.schema.json) projections, and [safe errors](../schemas/timing-error-output-v1.schema.json). The client exports `TimingRequest` and `TimingResult`; do not maintain field lists separately from the Rust DTO and generated schemas.

The request actions are `summary`, `evidence`, and `capabilities`. Summary requires full thread and turn identities and accepts explicit source roots, source scope, `auto`/`fresh`/`cached` mode, and `local`/`share-v1` privacy profile. Evidence requires the same target and scope; its `turn_events`, `use_objects`, and `use_records` pages use opaque cursors bound to the source evidence and scope. Capabilities performs no source scan. Summary uses `outputVersion=8` and analysis method `safe_event_turn_v7`. Operation endpoint reduction is versioned separately; older responses are rejected. Local output may include local identities and paths, while `share-v1` is a separate whitelist that omits them. Timing does not trigger price downloads, configuration, Hooks, or account observations. See the [CLI guide](../guides/cli.en.md) for invocation and error handling.


Selected local turn summaries include bounded operation-conflict explanations from the endpoint reducer: reason codes, operation identity and sampled original evidence positions. These are not another counter or a retry verdict; sharing omits local diagnostics. Input errors expose bounded field paths and fixed validation reasons without echoing rejected values.

## Skill contracts

Only the `wombat:wombat` plugin main Skill is shipped. Rust generates discovery DTOs. Node uses bounded read-only app-server stdio queries for native Skills, Hooks and accounts, without task-send or queue methods. `wombat-runtime.json` binds resource hashes and capabilities; missing, modified and unsupported resources have distinct errors. No standalone Skill installation contract or collection-plugin package remains.

Setup version 1 checks plugin discovery and runtime by default. `includeHooks` defaults to false; an explicit request independently queries Hook registrations. Optional probe failures cannot erase completed discovery or compatibility results. CLI exposes `setup --hooks`; see the [CLI guide](../guides/cli.en.md).

Conversation request/result version 3 adds an exact operation selector bound to one thread and turn. It reuses canonical call/item aliases and retains the original date/source/project restrictions. Tool requests and results have bounded source locators, including successful results; bodies remain outside indexes and require explicit tool-text reads. The CLI reads up to four located fragments together and preserves continuation; neither operation identity nor success proves task resolution.
