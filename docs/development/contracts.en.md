The separate `prices` interface provides status/update with `outputVersion=1`.

See [CLI](../guides/cli.en.md) for operations, enums, pagination, and errors. Measurement integers cannot exceed JavaScript's safe integer range; amounts remain decimal strings. New fields and rules require checking generated types, CLI JSON and current snapshots together.

Usage summaries retain complete values and per-field recorded subtotals, with coverage counts and gap reasons for selected canonical measurements. Pagination does not change this scope. Subtotals are absent when no records have usable values; observed zero remains zero. Complete usage shares do not fill denominators from partial subtotals. A separate total analysis prefers native totals and, for request-scoped responses only, calculates unavailable totals from reliable raw input plus output. Raw input includes caches; output includes reasoning. Calculated counts and coverage are explicit, and original field gaps remain unchanged. Cumulative intervals are not reconstructed. Charts, sorting, and peaks use these analyzed subtotals; fractions require complete analyzed coverage in the same scope. Pricing continues to use original measurements. Independently versioned optional analysis preserves immutable native-only review records. Rust-generated contracts own public types, fields, and enums.

Usage requests add optional `presentation`, defaulting to details; distribution retains only period subtotals. With either explicit presentation, offset/limit/page.total count periods; a detail page includes every model row for those periods without splitting groups. Omitting presentation retains existing row pagination. The core computes both `sort: cost` and token ordering by analyzed subtotals. Response `distribution` supplies selected-scope token maxima based on analyzed subtotals, tied peak dates and exact filter scopes, cost maxima, and unpriced token counts. Usage, turn, and measurement `costShare` uses the complete-range priced amount as denominator; unknown or zero denominators return missing values. Threads sort by matchedUsage or latest matching measurement; threadUsage retains full usage. Turns remain complete by default. Only turns accepts matchedOnly and locateTurnId, filtering and sorting before locating a page. Matching-only mode changes items/page, not the full-conversation summary or share denominator; steps remain complete.

Live freshness.initialScan identifies provisional task metadata from the first scan, with partial coverage and unknown usage. Previews are not persisted or returned by unpinned cached reads; fresh/refresh still wait for completed synchronization. Ordinary fixed views remain fixed. See the [initial task view decision](../decisions/implemented/architecture/2026-10-04-initial-task-preview.en.md).

## Client entries

`@wombat/client` exports generated types including `UsageRequest` and `UsageResult`, plus `UsageClient.query(request, { signal, onProgress })`. `UsageClient.prices({action:"status"|"update"}, {signal,onProgress})` returns generated `PricingResult` with the full catalog and version/source hashes. `UsageClient.live({query,mode,verify}, options)` is optional host functionality; Node supplies it and CLI uses it by default, while fixed snapshots use query. `createUsageClient(transport, pricingTransport, liveTransport, configTransport, optimizeTransport, preferencesTransport, directoriesTransport)` wraps narrow transports and validates the protocol. The portable entry contains neither Node nor React dependencies.

`@wombat/client/node` provides `createNodeClient({ binaryPath, timeoutMs, maxResponseBytes })` and owns local subprocess lifecycles. Callers do not handle arbitrary core operation strings. Other hosts can implement the same narrow transports and reuse generated contracts and validators.

Node's price transport downloads only the fixed official HTTPS document. The host request for the core `prices` operation includes document for update; status rejects it. Raw documents are absent from public request/response types. Rust parses and publishes them; other hosts must implement the same fixed-source retrieval flow.

Summary uses `outputVersion=5` and analysis method `safe_event_turn_v7`. Operation endpoint reduction is versioned separately; older responses are rejected. Local output may include local identities and paths, while `share-v1` is a separate whitelist that omits them. Timing does not trigger price downloads, configuration, Hooks, or account observations. See the [CLI guide](../guides/cli.en.md) for invocation and error handling.

## Handoff allowance assessment

The handoff response exposes per-project allowanceChecks with status, actual/preview model, provider, observation deadline and reason. Optional preview reads cover at most 128 projects, four concurrently, within five seconds; unfinished reads remain unknown without preventing local review. Sending reads identity and allowance again after thread/start returns the actual model/provider, then revalidates files/evidence before queueing.

Only a ChatGPT account, the openai provider and an explicit native model restriction observed within 60 seconds can return blocked: blocked_model_slug in supported selected_model_limit or luna_reserve notices must match exactly, and the deadline cannot exceed native reset_at. Expiry becomes unknown rather than implying recovery. Percentages, spend flags and display names without model binding cannot block. At most 10% remaining in the ordinary codex bucket only warns; available means native ordinary account allowance is reported available, not that this task can execute. UI status expires without automatic sending; CLI text/JSON use the same result. A final restriction can leave an already-created empty Codex task without queueing; no receipt or automatic deletion is added.

Once per-project sending begins, cancellation before queueing returns failed/CANCELLED for that project; an unconfirmed queue attempt returns unknown/HANDOFF_UNKNOWN. Projects not yet started return failed/CANCELLED without further sends. Earlier cancellation may reject directly with CANCELLED. Node can return partial delivery facts. Cancellation does not withdraw requests accepted by Codex. Connections and the in-flight guard are cleaned up. Resending requires explicit user authorization, without persistent execution receipts.
