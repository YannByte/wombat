# Rust 内核

中文 | [English](core.en.md)

`wombat-core` 读取本机 Agent 记录，生成不可变快照，并为用量与对话查询提供同一业务口径。当前生产来源为 Codex；具体支持范围见[来源适配参考](../development/adapters.md)。

## 入口与职责

- `src/adapters/` 识别来源事实；`pricing.rs` 负责离线价格；`usage_store.rs` 保存与读取快照；`usage_app.rs` 执行共享查询。
- `usage_app_dto.rs` 定义请求和结果，生成 TypeScript 与 Schema；字段语义见[契约](../development/contracts.md)。
- `src/main.rs` 通过 stdin 接收一条 JSON 请求，在 stdout 输出一条最终 JSON 结果；阶段进度走 stderr。

## 内部业务模块

| 业务 | 代码职责 |
|---|---|
| Codex 来源 | `adapters/codex/`：读取和边界、事件解析、身份事实、直接/累计计量对账、索引标题；独立增量入口保留 |
| 对话关系 | `session_relations.rs`：索引显式父子关系，供计量与操作继承去重使用；循环及其后代不建立可信祖先归属 |
| 轮次耗时 | `timing/` 与 `timing_dto.rs`：固定轮次分析、有界证据、本地与分享投影，以及独立的快照结果缓存 |
| 用量查询 | `usage_app/`：范围校验、守恒汇总、日期/维度报表、任务/轮次/步骤；父入口装配查询缓存 |
| 计量存储 | `usage_store/`：持久代次、精确分片读取、单次请求的事实读取器；账本只有一个计量归属 |
| 前台查询 | `live/`：SQLite 增量采集、单次请求读取和项目汇总，不保留监听器或生命周期管理器 |
| 配置 | `config/`：盘点、范围、证据查询；扫描按文本/指令/扩展拆分，静态算法按完整块/声明关系/本地引用拆分 |
| 优化 | `optimize/`：确定性规则、逐规则结果、无状态比较和持久用户决定；用户决定与检查事实分别保存 |

拆分保持公开导出、协议版本、快照和用户记录格式。测试按同一业务分组，继续使用独立合成真值。

`operation_association/lifecycle.rs` 统一合并可靠终止状态与退出码。关联阶段共享同一操作身份字符串；端点归约同时生成只读 `TerminalResult` 和最多四个终止证据引用，时间分析与重复行为分析复用结果，不再分别重放终止证据。结果区分未观察到、确定和冲突；冲突不会由后续重复记录消除，也不用虚构状态表示。每个操作最多保留两种不同状态与两种不同退出码，终止证据合并为 O(n) 时间、O(1) 空间。此界限不包括完整身份关联或端点归约；时间闭合不证明工具成功，目标匹配与记账规则保持独立。

`SessionRelations` 只接收显式关系和精确证据身份；它不解析来源文件，也不按路径或时间推断父子关系。关系索引采用迭代遍历，继承归属按最早有记录的祖先选择；独立事件不被合并。资源路径由 `FilePathChange` 统一展开原路径和移动目标，校验、资源预算与变化统计复用这一规则，不查询当前文件系统。配置对象合并仍分别保存物理对象与来源清单身份；版本一致性按首个对象线性比较，发现差异就保留各观察，不推断历史内容。

<a id="artifact-observations"></a>

## 工作产物观察

`artifacts` 检查当前文件，不加载会话历史、账户数据或价格。原始结构化结果由调用方传回作为基线，不由服务暂存、不自动保存为报告，也不代表删除授权。

发现过程使用实际项目清单和固定输出名称，不使用路径子串或任意清理脚本。重新生成依据采用保守规则：带缓存标记、有效清单且未发现目标覆盖配置的 Cargo 输出，或声明了明确输出目录的直接 TypeScript 编译脚本。其他输出需判断。原生 Git 检查保护跟踪内容，并提示未跟踪材料。用户资产、嵌套仓库、符号链接以及文件被占用的正面证据会阻止候选判定。Git 或占用探测不可用时保留未知。打开文件观察不能证明历史闲置、交付已验收或今后无人使用。Wombat 临时发布目录还会检查现有刷新锁，且始终需要判断恢复需求。

遍历按八秒、100,000 次计数检查预算，以及累计 8 MiB 的入队路径字节。原生探测最多两秒，并监控输出大小。扫描不计算文件内容哈希；通过两次有界元数据遍历比较文件身份、大小和变化时间。总逻辑字节数对硬链接去重。可获得的已分配字节数也是观察值，并非可回收空间估计；共享块、其他链接、回收站和并发活动均会影响空间释放。达到上限或观察到变化时，覆盖标记为不完整。这些检查无法使外部删除成为原子操作。

每次工作产物响应不超过 256 KiB。复查接收原计划与选中 ID，不依赖限时租约；它核对规则、范围、项目身份及观察，结果区分未变、变化、原位置不存在和无法比较。[CLI 指南](../guides/cli.md)负责语法。Unix 占用探测使用 `lsof`；探测不可用及 Windows 的观察仍为未知。原生删除目前仅在本机 macOS 实测。

Codex 模式使用六类产品专属规则，不扫描任意用户缓存。固定桌面缓存叶目录可重新生成；Sparkle 暂存内容比较经过核实的应用标识和十进制构建号，版本不可用时采用孤儿数据保留期。插件市场暂存内容需符合已知安装前缀和时间条件。后台服务版本保留当前及待更新版本，并要求现有安装锁可用。运行环境缓存保留完整的配置与依赖组合，仅将未完成的条目判为可清理。Crashpad 仅选择 `pending` 中过期的直属普通文件，旁侧状态和嵌套目录保持受保护。孤儿数据保留期为 30 天。Codex 状态、会话、凭据、完整运行环境及未识别路径均不是清理目标。

`apply` 只接受传回的原 Codex 计划中的明确候选标识，不接受任意路径或强制选项。删除前重新核对选择、完整条目证据、规则、父目录与对象身份、进程、打开文件及版本依据。后台服务安装锁保持到删除结束。条件未知、变化或新出现活动时停止该批操作；逐项结果区分已删除、此前已不存在、跳过和失败。删除为永久操作，不提供自动恢复或持久执行回执。包内符号链接只测量链接本身，不跟随目标，删除时仅移除链接；候选根目录或祖先为链接时拒绝处理。普通项目输出仍由 Codex 原生工具清理。安装锁以外的并发变化无法普遍保证原子性；缺少最终观察不能认定成功。

发现和删除采用有界批次。发现未完成时，可提供已观察批次中的完整候选，但不能声称已完成全部盘点；条目或版本证据不完整时不能授权该条目。后续检查会发现剩余候选。Codex 模式支持 macOS 布局，其他平台返回不完整覆盖且不执行删除。此流程不需要会话索引、价格下载或账户读取。实现参考了 [Mole 的 Codex 规则](https://github.com/tw93/Mole/blob/85162c24071d98560749e5c0a192876a252d7733/lib/clean/dev.sh)，由 Rust 独立实现，不捆绑其代码。

## 限制与验证

原生日志总输入可独立于缺失的缓存细分展示。缓存命中率使用同一批记录的总输入与缓存读取量；逐条分类矛盾时不显示命中率，原生输入冲突不会通过分类求和恢复。

计量观察按字段保留模型、模型提供商、API 提供商和推理强度冲突，继承、追加及重放不会清除同一响应的冲突。影响定价的冲突保留 Token，但不选择模型费率；仅推理强度冲突不阻止计价。分档价格要求已记录的单次请求输入，不从可能冲突的分类重建。解析状态、投影和固定快照要求计量观察映射版本 2；不兼容版本拒绝复用并保留原数据。

默认刷新只读来源日志，写入限于产品数据目录。无价、缺失、部分来源失败与资源上限需保持可见；详细责任和故障边界见[架构](../development/architecture.md)与[内核约定](../../core/AGENTS.md)。修改算法或存储时运行对应合成真值、格式和 clippy 检查；跨语言测试先重建内核。

`investigate`、`trajectory`、`resources`、`review`、`context` 由 `usage_app/inspection.rs` 在同一已提交视图内执行，默认不触发来源同步或价表更新。检查方法 3 返回固定阈值、来源覆盖、完整命中数和有界明细；线索不证明浪费、原因或效率。检查判定由 `usage_app/inspection/rules.rs` 的纯函数读取已聚合候选与统一参数，统计和证据读取仍归原查询；规则不另取快照、时间或来源。任务摘要仍使用规范账本，失败统计复用工作观察的结果明确子集，相同请求仅在同轮次、同接收方和完整 callable 指纹下计额外观测，不证明重试或相同效果。

补充检查方法 1 为 `investigate` 和 `review` 增加 17 项独立检查：未定价用量；项目估算金额集中、任务估算异常与周期增加；缓存创建与复用、模型选择复核；敏感路径读取与变更、超出记录项目的变更；风险命令模式、可能的凭据、敏感读取后同路径外发请求、风险请求重复拒绝；显式授权请求、返回答案未覆盖问题、较长请求响应间隔、反复短间隔空轮询。Rust 统一维护固定参数、完整范围统计、命中/未达门槛/证据不足状态、缺口、完整发现数与每项最多三条明细。金额检查使用完整的 API 等价计价及此前不重叠等长周期，不向操作分摊金额。模型复核比较全部参与任务的操作数中位数，交由用户判断，不推断任务难度或节省。路径使用历史词法边界，拟议/报告变更与磁盘实际状态分开。运行检查在内存中检查有界受支持字段，仅保留分类、原生关联和必要路径。同路径外发请求不证明传输成功；明确返回的答案 ID 可以确认遗漏，缺少响应不能直接判为未回答；往返间隔不能单独测量用户等待。轮询需原生运行轮次边界、空输入输出、连续短间隔、足够任务与日期及近期观察；缺口、新输入和非空输出断开连续链。未知字段、过大内容和关联缺失保留覆盖缺口。安全模式命中用于复核，不证明执行或危害。每个所选任务共用一次有界事件读取，关联使用索引，不做两两搜索；不新增持久问题模型、来源写入或执行收据。

`investigate` 和 `review` 还返回活动方法 1 的流程改进发现：同一完整请求至少 2 次耗时达到 30 秒；本期至少 5 次已判定操作且至少 3 次失败，失败率达到 20% 且至少为历史的 3 倍（历史至少 20 次，零基准按 1% 比较）；本期最长耗时至少 30 秒，相对至少 8 次历史耗时的中位数达到 10 倍且增加至少 20 秒（历史中位数至少 2 秒）；同一项目至少 2 个任务出现至少 5 次相同请求；同一任务至少 3 次相同请求失败或至少 2 次被拒绝。参数由 Rust 返回，多个信号合并为同一请求组。历史期是所选日期前一个等长、不相交的窗口，保留来源、项目、任务、模型、强度与时区筛选；全部、未知日期或缺少起止日期时只运行不依赖历史的检查。

分组使用来源实例、记录项目及完整命令请求/历史 cwd 或 callable/参数指纹。未知项目只在同一任务内分组，接收方不可靠的请求不参与。指纹、正文、命令和输出不作为发现内容导出；相同请求不证明相同环境、效果或浪费。已确认的搜索、测试、差异请求退出码 1 不计失败；冲突和非终态结果不进入失败分母或耗时样本。反复被拒绝不代表授权提示次数；完整授权往返仍不可用，补充检查可使用明确返回的问题结果。活动聚合复用一次规范操作读取，计数覆盖本期与历史期；额外空间为 O(N)，按请求组排序及组内耗时中位数计算为 O(N log N)，N 受操作工作预算限制。不新增持久领域实体。最多展示 30 组，保留完整命中组数、匹配/结果/耗时覆盖及分别绑定窗口的证据，超出时缩小查询范围。未命中不证明来源中没有问题。

输入轨迹使用账本内请求级计量及安全事件的物理顺序。每点保留原始输入、未缓存输入、缓存读取和有符号变化；压缩、来源文件或代次、上下文声明、模型/推理强度、轮次、筛选缺口及来源断点切断连续比较。模型/推理强度缺失、多请求同物理行、计量位置不唯一或缺序不生成连续增量。压缩对照单独返回相邻的前后输入和有符号差值，要求两条记录同时位于选定范围，且来源、上下文和轮次一致；它不连接连续增量，也不证明因果节省。输入不是上下文占用，不推定容量比例。资源热点按来源实例、历史项目、路径及身份依据分组，已验证的词法读取目标与未验证别名的变更报告分开。保留提出/报告的变更、已知耗时小计及覆盖操作数、未定位操作；实际磁盘变更不可判断，不分摊 Token 或费用，多目标操作不能跨资源相加当成操作总数。

周期复盘组合相同视图和范围的前后周期贡献、主要任务、模型、工具、检查线索和资源。未指定日期时使用视图截止日期所在周，周一开始；截止日期不含当天，开放周期标为部分结果。主要任务、模型和资源各最多 10 项，模型剩余用量单独对账。集中度以完整规范用量合计计算前 1、5、10 个任务的占比；剩余任务用量包含未归属计量，与前 10 项对账。合计缺失或分母为零时，占比不可用。分页和证据绑定完整任务/轮次/操作身份、原范围、方法及快照；过期返回错误，重新取得原范围并按身份定位，不替换为当前排行位置。整任务检查保留视图账本用于核算，按规范操作的完整时间边界筛选轮次，只读取与请求日历范围相交的事件块。活动比较同时选择原比较周期。块索引中的无正文计量顺序、压缩、模型及缺口观察保留完整任务的轨迹边界，无须重新打开历史载荷；包含来源缺口的块仍须读取。摘要使用事实本身的时间戳，不用轮次开始时间替代，并单独保留未注明时间的观察。元数据归约仍与所选任务的索引大小相关，而非仅与返回页相关。预算保持不变：全视图计量上限 250,000，选中任务与资源组上限各 10,000，操作和事件工作量各上限 100,000，整份检查触及的事件块编码预算为 64 MiB。结果含实时元数据的编码预算为 256 KiB，超限整体失败并要求缩小范围；分页不代表索引有界计算或已验证规模性能。`investigate` 范围明确提供 `threadId` 和 `turnId` 时，只读取该轮计量与操作分片，并复用现有耗时读取器取得有界事件及相关来源控制证据，不遍历无关账本行或事件分区。读取预算为 100,000 条触及事实、64 MiB 编码和 100,000 次元数据检查；单个大轮次仍可能超限。结果标明仅检查选中轮次，保留原筛选与证据身份。检查先从同一已提交版本恢复证据元数据，再读取选定范围。

`context` 按选定范围分页盘点安全记录中的注入上下文和模型窗口，排除普通用户、继承及推理记录。计数单位是保留的物理记录，不代表请求注入次数或历史资源加载。历史内容版本与正文体量仍不可用。已记录的模型窗口表示容量，不表示占用。模型/推理强度筛选要求同轮次的规范计量，不证明独占归属。

原生账户观测另存于私有 `account-history.sqlite`，存储格式和间隔方法各为 1，与可重建用量索引及用户决定独立。保存经过规范化的时间、散列账户身份、窗口及百分比，不保存邮箱、凭据或原生正文；原生读取失败仍保存缺口，相同值仍是独立观测。`account history` 只读最新 20 项和完整观测数，不启动原生进程，不补采历史。仅相邻且同账户、额度桶、窗口长度及重置周期的有效观测计算百分点变化；身份未知、失败、重置、过期和时间逆序均切断间隔。单项存储预算 128 KiB，完整历史响应预算 256 KiB；未知存储版本在载荷解码或写入前拒绝并保留数据。历史保存失败独立报告，不掩盖本次有效额度。不能从历史推导本地任务归因、Tokens/百分点或耗尽预测。

资源热点省去对话级历史事件读取，使用规范操作事实。指定单个回合的查询保留原回合证据读取流程。检查查询读取操作时不再重新选择、复制回合计量，因为查询已持有所选范围的账本。操作与响应预算仍有效。需要事件顺序或上下文的分析保留原事件预算；这一调整不省略其证据，也不扩大其上限。

<a id="foreground-queries-and-internal-storage"></a>

## 前台查询与内部存储

每次 CLI 请求启动一个有边界的内核子进程，等待响应和退出。Wombat 不再监听本地接口，也不保留端点发现、服务注册、自动启动或视图队列。能力发现不打开索引或扫描来源。取消会终止本次调用的进程树；已经完成的写入仍可能生效。

SQLite 保留为内部可重建索引。增量采集将来源游标、观察和计量事实一并提交。私有文件锁串行协调不同调用的采集与索引发布，单次最多等待 600 秒。读取事务保证一次请求内部一致，不公开租约或读取版本选择器，随请求结束关闭。不同命令之间不承诺冻结结果。

当前索引保存压缩来源事实、共享元数据、计量投影和来源位置。消息正文及工具输出仍在只读原始文件中。查询头可在不解码全部事件帧的情况下恢复计量结果；对话查询按需读取分区和数据块。来源身份、格式版本、不透明游标绑定和原文校验继续有效。

自动用量、任务排行和统计查询在没有匹配的复用数据时读取原始记录。直读和复用采用同一套报表计算规则，包括价格状态。近期查询可以延后读取旧文件，并通过 `historyDeferred` 提示覆盖范围。修改时间只用于准备范围。历史日期和全部日期查询纳入可用历史。显式 `fresh`、验证、重建和证据操作仍使用完整 SQLite 索引。显式 `cached` 仅读取完整索引中已提交的数据，并报告上次检查时间。

在 macOS、Linux 和 Windows 上，同一份本地历史日志连续两次读取都至少耗时一秒时，第二次结果输出后可启动一个低优先级进程。只接受单个来源、256–512 MiB 输入及至多 256 个日志文件。工作时限为 45 秒，采样到的峰值内存超过 384 MiB 时触发取消。写入锁限制并发构建。只保留一份压缩账本，压缩体积最多 16 MiB，解码预算为 64 MiB。账本只保存规范计量和报表需要的元数据，不保存消息正文、工具输出或计价总量。日志身份、大小、修改时间或变更时间变化时停止复用。构建进程在原子发布前再次核对来源，尝试结束后退出。失败或已过期的构建保留已提交的缓存。系统无法读取进程内存或核对文件变更时间时，跳过构建。

用量批次最多接受八个附加查询，共用来源范围和读取事务。附加查询不能另选根目录、指定其他数据版本或刷新；整个批次响应不超过 2 MiB。普通 JSON 默认精简展示；完整范围的计量结果不依赖页大小或展示形式。

显式重建扫描到新的当前格式 SQLite 代次，持久化完成后才发布指针。失败保留原索引。用户决定、授权、身份及处理记录独立保留。未知格式直接报错，不迁移或删除。不再提供公开的保存视图导出或固定视图查询。

配置检查读取当前清单。复查接收原始选中建议、范围及规则参数，再检查当前条件。清理复查和执行接收原始检查计划及选中 ID；计划不随进程结束过期。计划不是授权，也不能替代当前事实：执行会重新发现受支持对象，核对项目身份、文件观察、占用和保护状态，并在需要时持有安装锁。变化、不完整或受保护的对象不会删除。检查与复查不自动创建报告历史。

## 运行时采集

`collection.rs` 负责版本 1 的事件接收、本机采集偏好、安全缓冲和分页查询。`collection/association.rs` 复用适配器身份函数，按原生来源、任务和轮次身份关联已提交日志。缺少事实时保留未知；索引不可读或版本不支持时标记关联不可用。`sourceEpoch` 是当前已提交的来源投影身份，不是固定查询快照。Hook 观察不新增计量、不分摊工具费用、不改写来源日志。

私有的 `collection-v1/observations.sqlite` 将安全元数据与可重建日志索引、处理决定分开保存。输入最多 64 KiB；正文、工具参数与输出、提示词及凭据在持久化前丢弃。接收时间不替代事件时间。原生事件 ID 或工具身份与阶段去重重复投递；缺身份时保持独立。身份冲突保留首条观察并记录缺口。默认 logs 模式，仅安装资源不会采集 Hooks。

暂停时最多保留 4,096 条待处理观察；恢复使已保留记录可用，不改变身份。存储最多接收 100,000 条观察，之后拒绝新事件并累计已知容量缺口。这些是行数限制，不保证 SQLite 文件字节上限。状态汇总检查所选来源与项目的记录；事件每页最多 200 条。接收通过索引检查身份与最后序号，待处理计数受缓冲上限约束。当前不提供删除、保留轮换或格式迁移入口。持久提交前失败保留既有数据；输入拒绝和运行时不可用只能由桥接入口报告，不计入已存缺口。不能声称无损采集。

## 任务统计与监控

`statistics` 按记录中的线程聚合所选规范计量，返回有计量、总量完整及不完整的任务数，以及 Token 均值、中位数和 P90；无法归属任务的计量单列。默认范围与用量日报的近期范围一致，历史统计使用 `allTime`。项目和模型总体沿用相同筛选；多模型任务可同时计入各模型，任务数不可相加。分位数复用耗时统计的 type-7 线性插值。总量不完整的任务不进入均值和分位数，零仍是有效样本。顶层 `threadId` 将所选任务与总体中的完整样本比较，返回包含并列值的分位排名及是否超过 P90，不据此判定任务质量或浪费。

给出等长、不重叠的周期后，增长统计分别返回任务数量与单任务用量变化。完整且非空总体使用对称拆解：`ΔN × (μ0+μ1)/2` 与 `Δμ × (N0+N1)/2`，两项之和等于可归属任务的 Token 增长；无法归属任务的增长单列。空总体不虚构均值，不完整总体不计算整体贡献。这些是算术描述，不是因果节省。查询优先复用项目账本索引，不读取操作正文。M 条计量、T 个任务的计算复杂度为 O(M log(M + T) + T)，除既有快照外使用 O(M+T) 临时引用。中位数和 P90 通过线性选择计算精确的 type-7 顺序统计量。分页只限制返回的组数，不限制总体计算；未变化的实时结果复用查询缓存。

`monitor.rs` 在独立的 `user-v1/monitor.sqlite` 中保存 Token 预算、日历周期与提醒，不混入派生索引或语言偏好。设置指定来源、项目、模型、推理强度和时区，支持日、周一开始的周及月周期，默认预警比例为 0.8。检查需要近期来源观察，来源失败会明确报错。部分小计可以证明越过阈值，不能证明剩余额度。预算提醒按授权来源集合、设置版本、周期和阈值去重；复盘描述最近结束的周期，事实变化会生成新版本；已读标记是独立的用户字段。检查不补发错过的全部周期。宿主必须显式持续检查，保存设置不会安装调度器。最多保存 100 项设置，每次检查最多指定 100 个 ID，每项存储设置最多 16 KiB，返回最近 100 条提醒。操作步骤由 [CLI 指南](../guides/cli.md)拥有。

配置列表同时返回所选范围的扩展使用统计，包括已记录使用次数，以及最近一次使用或窗口起点之后的完整日数。保留来源覆盖，缺失不可证明不存在；这些是无使用记录的时间段，不是确认闲置或删除建议。原生字面文本结果只保存哈希，不保存正文；可信原生 AGENTS 注入元数据可将无歧义的单份规则正文绑定到路径。规则注入按原生消息身份与文档路径去重，同一消息可以加载多个不同文档。后续跟踪区分复查版本的读取、规则加载及版本未知；读取或加载不证明执行使用。复查前后采用同一记录来源和项目范围、等长实际时间窗口，返回任务总体及用量，不分摊工具成本，也不认定修改产生了节省。缺失历史版本、MCP 采用和完整连续观察仍取决于来源证据。

## 对话证据

可见消息直搜以流式方式读取 Codex 原始日志，无需打开分析索引。筛选使用会话记录的项目和消息时间，出处保留原始记录的字节范围。需要跨轮上下文时，每份命中的文件只再扫描一次，同页复用相同的相邻消息。单次查询限制输入、时间和输出，续页要求日志清单与首次观察一致。只有真实任务在相同证据和筛选范围下证明索引能明显改善端到端耗时，才为这条查询引入索引。对比时计入首次构建、重复查询和磁盘占用。

`conversation.rs` 负责活动、位置、原文和字面检索查询。它读取安全事件分区，独立于 Token 账本。筛选组合来源、记录的项目、任务、轮次、消息来源及类型和日历范围。结果按索引来源顺序返回。一条来源记录可产生多个观察，数量不证明任务数或工作已经完成。当前事件索引版本为 3，内部清单版本为 5。旧格式会被拒绝，不执行迁移或删除。现有数据块摘要保留消息数量、UTC 时间范围和未注明时间的消息标志。定位及检索跳过范围外的数据块，借用非消息载荷，只解码消息事实。每次查询只读取选定块一次，后续分页可能再次打开该块。不新增消息正文、第二份文本索引或全历史缓存。返回的准确事件偏移可定位一个索引观察，无需扫描整个轮次。

原文定位使用安全事件格式 5、消息映射 4 和文件水位格式 2。用户角色记录的全部声明内容类型均指向 Codex 应用页面上下文时，将其归为注入上下文。默认消息筛选不返回这些记录，显式指定来源类型仍可读取。用户直接引用同类文本、用户与上下文混合类型，以及未知类型，均保留原分类。受支持的 JSON 文本部分按约 8 KiB 划分为可独立解码的块，保留字节位置和 SHA-256 校验值，不拆开 Unicode 或 JSON 转义。每条消息最多保留 4,096 个块，后续内容明确标为缺口。文件路径和物理身份归属于逐文件水位。正文及媒体不进入索引。历史消息和事件读取只打开不可变的证据目录及选定分片，不恢复计量或操作目录。后续明细查询共享相同的目录分区。目录元数据随单次请求保留，不缓存消息正文。读取校验选定块和来源身份，不证明整个当前文件未变化。实时浏览可纳入已提交的追加内容。固定导出范围使用选定事件分区、筛选条件和来源状态的指纹，跨请求校验证据，无需保留进程或视图。选定分区中的变化可能要求重查，即使变化的事件不符合精确日期或消息筛选。来源缺失、替换、截断或选定块变化时明确失败。旧格式被拒绝，不迁移或删除数据；派生数据需要单独授权重建。

记录列表包含没有 Token 计量的对话，每个记录任务返回一条匹配活动，并按最近活动排序；分页绑定来源目标、位置及筛选范围。未选项目或任务的全局字面检索必须同时提供日期上下界。检索命中携带匹配文本处的读取游标。回读在总字节预算内最多保留 512 个 UTF-8 字节的前文，并从命中处向后读取，无需解码整段消息前缀。每段原文保留消息来源、时间和证据位置。相邻事件返回各自的元数据，可按位置读取正文。

一次请求最多读取 200 个目标、打开八个来源文件。每个目标默认返回 8 KiB 文本，最多 256 KiB。包含元数据和新鲜度的响应编码预算为 1 MiB。定位及检索每页最多 200 个结果，每次最多检查 2,000 条消息事实和 10,000 个分区或数据块条目，未完成时返回绑定范围的续查信息。每次原文件读取预算默认 8 MiB，最多 16 MiB。检索按受支持文本部分进行字面匹配，可跨块续查；不重组增量文本流或检索非文本内容。来源及读取预算不是进程内存或耗时的硬上限。来源变化可能使游标失效，也可能包含历史内容的重新观察。CLI 操作见 [CLI 指南](../guides/cli.md)。

扩展搜索采用约五秒的协作时间片，最多检查 50,000 条事件及 100,000 个元数据条目。它复用同一个读取器，沿用原文读取与响应字节预算。可见上下文只在同一会话和物理来源代次内读取，按消息块边界定位，最多缓存 192 个块或 16 MiB 块编码，最多检查 10,000 个块元数据条目。最多返回 128 个共享相邻消息正文，每个最多 1 KiB。工具事件和消息增量不计入窗口。

检索最多准备 16 个字面搜索词，每个最多 4,096 个 UTF-8 字节。所有词共用一次来源扫描和每个通过校验的文本块。最长词决定跨块匹配需要保留的末尾文本长度。续查同一条消息时可能重读边界块。批读会在打开来源前合并证据、游标和字节上限相同的目标。不同位置的片段逐一校验后，再在同一响应中合并完全相同的原文。每个位置保留各自的上下文和续读游标。合并只作用于当前批次，不影响事件和用量计数。批读保留可读片段并列出失败目标，放不进响应预算的目标推迟读取。单目标读取直接返回错误。

前台操作在加载索引事实前共用文件锁，并发调用等待执行，不成倍加载完整查询数据。中断重建只清理有明确标记且尚未发布的目录，保留已完成代次和恢复副本。清理项目标识绑定原范围、项目物理身份和已审阅条件。
