# Rust 内核

中文 | [English](core.en.md)

`wombat-core` 读取本机 Agent 记录，生成不可变快照，并为用量与对话查询提供同一业务口径。当前生产来源为 Codex；具体支持范围见[来源适配参考](../development/adapters.md)。

## 入口与职责

- `src/adapters/` 识别来源事实；`pricing.rs` 负责离线价格；`usage_store.rs` 保存与读取快照；`usage_app.rs` 执行共享查询。
- `usage_app_dto.rs` 定义请求和结果，生成 TypeScript 与 Schema；字段语义见[契约](../development/contracts.md)。
- `src/main.rs` 通过 stdin 接收一条 JSON 请求，在 stdout 输出一条最终 JSON 结果；阶段进度走 stderr。

## 内部业务模块

| 业务 | 代码职责 |
|---|---|
| Codex 来源 | `adapters/codex/`：读取和边界、事件解析、身份事实、直接/累计计量对账、索引标题；独立增量入口保留 |
| 对话关系 | `session_relations.rs`：索引显式父子关系，供计量与操作继承去重使用；循环及其后代不建立可信祖先归属 |
| 轮次耗时 | `timing/` 与 `timing_dto.rs`：固定轮次分析、有界证据、本地与分享投影，以及独立的快照结果缓存 |
| 用量查询 | `usage_app/`：范围校验、守恒汇总、日期/维度报表、任务/轮次/步骤；父入口装配查询缓存 |
| 快照 | `usage_store/`：持久代次、精确分片读取、共享内存视图；账本只有一个计量归属 |
| 实时服务 | `live/`：增量采集、读取版本选择、类型化查询、连接与服务生命周期 |
| 配置 | `config/`：盘点、范围、证据查询；扫描按文本/指令/扩展拆分，静态算法按完整块/声明关系/本地引用拆分 |
| 优化 | `optimize/`：确定性规则、逐规则结果、处理记录服务和持久数据库；用户决定与检查事实分别保存 |

拆分保持公开导出、协议版本、快照和用户记录格式。测试按同一业务分组，继续使用独立合成真值。

`operation_association/lifecycle.rs` 统一合并可靠终止状态与退出码。关联阶段共享同一操作身份字符串；端点归约同时生成只读 `TerminalResult` 和最多四个终止证据引用，时间分析与重复行为分析复用结果，不再分别重放终止证据。结果区分未观察到、确定和冲突；冲突不会由后续重复记录消除，也不用虚构状态表示。每个操作最多保留两种不同状态与两种不同退出码，终止证据合并为 O(n) 时间、O(1) 空间。此界限不包括完整身份关联或端点归约；时间闭合不证明工具成功，目标匹配与记账规则保持独立。

`SessionRelations` 只接收显式关系和精确证据身份；它不解析来源文件，也不按路径或时间推断父子关系。关系索引采用迭代遍历，继承归属按最早有记录的祖先选择；独立事件不被合并。资源路径由 `FilePathChange` 统一展开原路径和移动目标，校验、资源预算与变化统计复用这一规则，不查询当前文件系统。配置对象合并仍分别保存物理对象与来源清单身份；版本一致性按首个对象线性比较，发现差异就保留各观察，不推断历史内容。

## 限制与验证

原生日志总输入可独立于缺失的缓存细分展示。缓存命中率使用同一批记录的总输入与缓存读取量；逐条分类矛盾时不显示命中率，原生输入冲突不会通过分类求和恢复。

计量观察按字段保留模型、模型提供商、API 提供商和推理强度冲突，继承、追加及重放不会清除同一响应的冲突。影响定价的冲突保留 Token，但不选择模型费率；仅推理强度冲突不阻止计价。分档价格要求已记录的单次请求输入，不从可能冲突的分类重建。解析状态、投影和固定快照要求计量观察映射版本 2；不兼容版本拒绝复用并保留原数据。

默认刷新只读来源日志，写入限于产品数据目录。无价、缺失、部分来源失败与资源上限需保持可见；详细责任和故障边界见[架构](../development/architecture.md)与[内核约定](../../core/AGENTS.md)。修改算法或存储时运行对应合成真值、格式和 clippy 检查；跨语言测试先重建内核。

`investigate`、`trajectory`、`resources`、`review`、`context` 由 `usage_app/inspection.rs` 在同一已提交视图内执行，默认不触发来源同步或价表更新。检查方法 3 返回固定阈值、来源覆盖、完整命中数和有界明细；线索不证明浪费、原因或效率。检查判定由 `usage_app/inspection/rules.rs` 的纯函数读取已聚合候选与统一参数，统计和证据读取仍归原查询；规则不另取快照、时间或来源。任务摘要仍使用规范账本，失败统计复用工作观察的结果明确子集，相同请求仅在同轮次、同接收方和完整 callable 指纹下计额外观测，不证明重试或相同效果。

补充检查方法 1 为 `investigate` 和 `review` 增加 17 项独立检查：未定价用量；项目估算金额集中、任务估算异常与周期增加；缓存创建与复用、模型选择复核；敏感路径读取与变更、超出记录项目的变更；风险命令模式、可能的凭据、敏感读取后同路径外发请求、风险请求重复拒绝；显式授权请求、返回答案未覆盖问题、较长请求响应间隔、反复短间隔空轮询。Rust 统一维护固定参数、完整范围统计、命中/未达门槛/证据不足状态、缺口、完整发现数与每项最多三条明细。金额检查使用完整的 API 等价计价及此前不重叠等长周期，不向操作分摊金额。模型复核比较全部参与任务的操作数中位数，交由用户判断，不推断任务难度或节省。路径使用历史词法边界，拟议/报告变更与磁盘实际状态分开。运行检查在内存中检查有界受支持字段，仅保留分类、原生关联和必要路径。同路径外发请求不证明传输成功；明确返回的答案 ID 可以确认遗漏，缺少响应不能直接判为未回答；往返间隔不能单独测量用户等待。轮询需原生运行轮次边界、空输入输出、连续短间隔、足够任务与日期及近期观察；缺口、新输入和非空输出断开连续链。未知字段、过大内容和关联缺失保留覆盖缺口。安全模式命中用于复核，不证明执行或危害。每个所选任务共用一次有界事件读取，关联使用索引，不做两两搜索；不新增持久问题模型、来源写入或执行收据。

`investigate` 和 `review` 还返回活动方法 1 的流程改进发现：同一完整请求至少 2 次耗时达到 30 秒；本期至少 5 次已判定操作且至少 3 次失败，失败率达到 20% 且至少为历史的 3 倍（历史至少 20 次，零基准按 1% 比较）；本期最长耗时至少 30 秒，相对至少 8 次历史耗时的中位数达到 10 倍且增加至少 20 秒（历史中位数至少 2 秒）；同一项目至少 2 个任务出现至少 5 次相同请求；同一任务至少 3 次相同请求失败或至少 2 次被拒绝。参数由 Rust 返回，多个信号合并为同一请求组。历史期是所选日期前一个等长、不相交的窗口，保留来源、项目、任务、模型、强度与时区筛选；全部、未知日期或缺少起止日期时只运行不依赖历史的检查。

分组使用来源实例、记录项目及完整命令请求/历史 cwd 或 callable/参数指纹。未知项目只在同一任务内分组，接收方不可靠的请求不参与。指纹、正文、命令和输出不作为发现内容导出；相同请求不证明相同环境、效果或浪费。已确认的搜索、测试、差异请求退出码 1 不计失败；冲突和非终态结果不进入失败分母或耗时样本。反复被拒绝不代表授权提示次数；完整授权往返仍不可用，补充检查可使用明确返回的问题结果。活动聚合复用一次规范操作读取，计数覆盖本期与历史期；额外空间为 O(N)，按请求组排序及组内耗时中位数计算为 O(N log N)，N 受操作工作预算限制。不新增持久领域实体。最多展示 30 组，保留完整命中组数、匹配/结果/耗时覆盖及分别绑定窗口的证据，超出时缩小查询范围。未命中不证明来源中没有问题。

输入轨迹使用账本内请求级计量及安全事件的物理顺序。每点保留原始输入、未缓存输入、缓存读取和有符号变化；压缩、来源文件或代次、上下文声明、模型/推理强度、轮次、筛选缺口及来源断点切断连续比较。模型/推理强度缺失、多请求同物理行、计量位置不唯一或缺序不生成连续增量。压缩对照单独返回相邻的前后输入和有符号差值，要求两条记录同时位于选定范围，且来源、上下文和轮次一致；它不连接连续增量，也不证明因果节省。输入不是上下文占用，不推定容量比例。资源热点按来源实例、历史项目、路径及身份依据分组，已验证的词法读取目标与未验证别名的变更报告分开。保留提出/报告的变更、已知耗时小计及覆盖操作数、未定位操作；实际磁盘变更不可判断，不分摊 Token 或费用，多目标操作不能跨资源相加当成操作总数。

周期复盘组合相同视图和范围的前后周期贡献、主要任务、模型、工具、检查线索和资源。未指定日期时使用视图截止日期所在周，周一开始；截止日期不含当天，开放周期标为部分结果。主要任务、模型和资源各最多 10 项，模型剩余用量单独对账。集中度以完整规范用量合计计算前 1、5、10 个任务的占比；剩余任务用量包含未归属计量，与前 10 项对账。合计缺失或分母为零时，占比不可用。分页和证据绑定完整任务/轮次/操作身份、原范围、方法及快照；过期返回错误，重新取得原范围并按身份定位，不替换为当前排行位置。整任务检查遍历视图账本和选中任务的操作/安全事件：全视图计量上限 250,000，选中任务与资源组上限各 10,000，操作和事件工作量各上限 100,000，整份检查触及的事件块编码预算为 64 MiB。结果含实时元数据的编码预算为 256 KiB，超限整体失败并要求缩小范围；分页不代表索引有界计算或已验证规模性能。`investigate` 范围明确提供 `threadId` 和 `turnId` 时，只读取该轮计量与操作分片，并复用现有耗时读取器取得有界事件及相关来源控制证据，不遍历无关账本行或事件分区。读取预算为 100,000 条触及事实、64 MiB 编码和 100,000 次元数据检查；单个大轮次仍可能超限。结果标明仅检查选中轮次，保留原筛选与证据身份。检查先从同一已提交版本恢复证据元数据，再读取选定范围。

`context` 按选定范围分页盘点安全记录中的注入上下文和模型窗口，排除普通用户、继承及推理记录。计数单位是保留的物理记录，不代表请求注入次数或历史资源加载。历史内容版本与正文体量仍不可用。已记录的模型窗口表示容量，不表示占用。模型/推理强度筛选要求同轮次的规范计量，不证明独占归属。

原生账户观测另存于私有 `account-history.sqlite`，存储格式和间隔方法各为 1，与可重建用量索引及用户决定独立。保存经过规范化的时间、散列账户身份、窗口及百分比，不保存邮箱、凭据或原生正文；原生读取失败仍保存缺口，相同值仍是独立观测。`account history` 只读最新 20 项和完整观测数，不启动原生进程，不补采历史。仅相邻且同账户、额度桶、窗口长度及重置周期的有效观测计算百分点变化；身份未知、失败、重置、过期和时间逆序均切断间隔。单项存储预算 128 KiB，完整历史响应预算 256 KiB；未知存储版本在载荷解码或写入前拒绝并保留数据。历史保存失败独立报告，不掩盖本次有效额度。不能从历史推导本地任务归因、Tokens/百分点或耗尽预测。

资源热点省去对话级历史事件读取，使用规范操作事实。指定单个回合的查询保留原回合证据读取流程。检查查询读取操作时不再重新选择、复制回合计量，因为查询已持有所选范围的账本。操作与响应预算仍有效。需要事件顺序或上下文的分析保留原事件预算；这一调整不省略其证据，也不扩大其上限。

## 存储与服务生命周期

带校验的聚合目录使普通用量与任务总体统计读取维度、日期覆盖时，无需解码范围外的聚合正文。时区边界仍由规范成员解析。总体统计复用 4 MiB 归并工作区和 128 MiB 私有落盘限制；分位数标量向量最多接收 500,000 个任务（4 MiB）。操作恢复排除无法建立操作关联的匿名消息阶段，不再保留没有操作的分量。时序和会话查询仍使用完整归档事件。无消费者的哈希别名查找表及脏键缓存已移除；原生别名成员在派生过程中共享一份不可变映射。

`compare` 在同一固定视图内比较等长、不重叠的日期周期，按目录、模型或会话给出正负贡献；结束日期不含当天。部分来源、尚未结束的周期和日期未知的记录分别说明。差值需要完整的分析 Token 总量或完整估价；未知值不填零，基准为零时不计算增长率。每页保留页外贡献，便于核对总变化；贡献不建立因果关系。

会话比较使用完整内部 ID，保留日期和维度筛选，可包含明确关联的后代。自身、后代及合计复用规范计量，每条计量只属于一个会话。两侧家族可能重叠，不可再相加。循环或冲突关系不建立后代关系，来源不完整或父会话缺失时显示部分结果；不判断任务等价、质量或效率。

实时刷新摘要与发布一起提交，记录计量新增、修正和移除、会话新增、轮次更新、价格及覆盖变化，完整恢复后仍可读取。首次发布或没有完整基准时不提供摘要；无变化刷新保留最近发布摘要，失败不发布新摘要。摘要独立于页面筛选，修正或移除不代表实际消费变化。总量超出安全范围时省略差值，保留变化计数。

比较输出有分页限制，但计算仍遍历视图计量；家族查询读取安全事件并构造关系索引。刷新摘要比较两个视图的计量和轮次，临时空间与记录数成比例，不承诺索引驱动的有界计算时间。

观察版本的字段名和值由共用描述符维护。解析状态和实时投影使用同一组头读写规则；内存与磁盘快照使用同一份类型化头构造，磁盘字段保持不变。各入口仍在读取负载或复用缓存前检查所需观察版本头；水位、存储格式和分析方法保留独立版本。

配置读取版本分别固定配置测量、静态分析和宿主观察的内部内容修订，采集完整性与授权范围参与对应修订；观察时刻单独保留，重复观察相同内容不会仅因时间变化而改写内容修订。默认日期范围按所选视图的截止时间解析。复查后的 Skill/MCP 观察复用使用操作的身份与计数口径，时间范围为 `(复查时间, 视图截止时间]`；缺身份、时间、派发或目标证据时保留明确关联的次数，并用 partial 说明完整计数受限。读取视图保存在内存中，最长十分钟，进程重启后过期；过期明确失败，不回退到更新观察。配置对象与后续观察公开同一方法 3 投影生成的 `useBasis`：固定快照、观察截止、所选来源/项目/任务/Agent 范围、时间窗口、派发/身份/目标/时间/轮次五维缺口及所选来源采集完整性。来源操作时间可能来自结果记录，不等同于派发时刻。已知零值仅描述已采集范围；有缺口的可运行投影仍返回已观察次数；不可用历史的次数与缺口维度为 null。配置中的规则加载/读取与后续观察中的规则文件读取保留不同单位。当前配置不能证明历史加载或内容。

只读的 `optimize activity` 提供五个固定轮次检查：失败后再次调用、同目标成功读取后的重读，相同请求再次出现，以及失败占比和请求输入变化。它复用共用重复行为次数及证据引用。`optimize/activity/rules.rs` 集中声明五条检查的方法、版本和测量口径，检查函数共用同一轮次统计。受支持的正向次数在覆盖不完整时仍可命中；零值只有在该次数所需覆盖完整时才表示未发现。可选耗时缺口不使次数失效。缺少执行顺序时不能确认前驱关系，但仍保留请求记录。五个检查事实均保留；已有确认的再次调用或重读线索时，不再重复显示泛化请求建议。失败占比检查直接读取同轮次的操作结果统计，采用 `terminal_failure_inspection_v1`：至少 5 次结果可判定的操作、2 次失败，且比例不低于 40% 才给出建议。比例仅针对已采集的结果可判定子集；低于阈值只表示当前子集未达到检查条件，不证明整个任务没有问题。样本较少时保留统计并解释，不生成该建议；部分来源仍可给出限定范围的正向建议。检查带有原统计及固定阈值，不重读来源或重选分母。优化响应版本 4、活动格式 3 隔离旧结果，不改变用户决定格式。这些是供检查的线索，不代表故障、浪费、节省或解决。响应编码预算为 256 KiB。此路径不采集配置或宿主钩子，不刷新价格，也不写复查记录。

规则在共用证据目录中声明自己的读取门槛。文件大小检查可使用本次授权采集的文件系统元数据，即使正文未读到；正文、格式和引用检查仍要求各自的有效内容。正文不足不会把未支持的算法改称证据不足。来源或检查方法改变时，复查仍要求同口径比较。

静态规则按实际参数、测量方法、相关关系与完整性、对象身份及授权范围缓存纯命中/未命中判断；无关日志追加不改变依赖键。每次仍检查当前可用性和原复查基线的可比性，再绑定当前观察时间，不缓存用户决定或“已解决”结论。进程内 LRU 最多 16 项、2 MiB 编码，单项最多 256 KiB；依赖扫描与编码也有预算；超限可保留当前判断，但跳过缓存并明确检查身份或依赖依据未知，不能据此完成复查验证。编码额度不代表实际堆内存上限，输入准备与依赖计算仍有成本；评估器尚无取消接口。

规则检查保存类型化测量、实际阈值、方法版本、依赖内容修订、授权范围和截止时间，未命中也保留这些依据。问题身份按可靠对象或关系及范围生成，不包含阈值、整文件修订或检查时间；本地引用与重复块缺少可靠位置上下文时明确身份未知，不按名称、行号或相近时间合并。首次观察即固定原始对象、范围和检查基线，后续复查仅更新当前事实。只有相同规则、方法、参数和范围下证据完整、可比的未命中才标为已验证；规则升级、缺身份或缺证据不会解决原问题。

用户决定绑定原问题及支持检查，同时以内容、相关依赖、方法、参数和范围检查当前适用性；无关日志修订和截止时间变化不改变适用性。问题位置身份未知时，决定仅适用于同一完整建议版本、内容和依赖，不跨新版本继承。处理记录独立保存在 `user-v1/reviews.sqlite3`，当前 SQLite 格式为 `user_version=4`，记录格式为版本 1；必需版本头先于载荷形状校验。未知版本报 `UNSUPPORTED_VERSION`，当前格式缺头或损坏报 `REVIEWS_CORRUPT`，均保留原数据，不迁移或自动修复。重建派生索引不清除用户决定和历史。规则身份及复查取舍见[规则决定](../decisions/implemented/architecture/2026-10-04-event-rules.md)。

默认数据目录为 macOS `~/Library/Application Support/Wombat`、Windows `%LOCALAPPDATA%/Wombat`、Linux `XDG_DATA_HOME/wombat` 或 `~/.local/share/wombat`；`WOMBAT_DATA_HOME` 可覆盖。快照位于 `usage-v4/`，索引位于 `live-v2/`；不替换旧 `latest.json`。

刷新持有进程文件锁，先写私有 generation、分片与哈希，再提交 manifest 并原子更新 latest；取消不发布半份快照。单源失败保留独立回执，全部失败保留旧 latest。源日志按本次长度读取，多文件不声称原子一致。只支持当前格式，未知版本拒绝，不自动迁移或清空。

安全事件按精确的 `threadId` 与可选 `turnId` 分区，分别保留无任务和无轮次的事实；事件索引独立标明版本。块按最多 200 条事实和 4 MiB 完整编码双重上限切分，并校验哈希、归属、顺序和数量。单条事件连同块元数据超过 4 MiB 时明确报资源失败，保留旧 latest。内存与磁盘使用同一分块索引；精确目标查询只读取触及的事件块。整目标读取最多 100,000 条事实，证据页最多 200 条，每次查询最多读取 64 MiB 块编码，事件数组编码也受此字节上限约束。查询支持取消；分页游标绑定快照、精确目标与分区索引哈希，超限或校验失败不返回截断成功。

每文件读取水位记录来源身份、文件代次、已提交完整换行边界、捕获长度、采集时间及覆盖状态，并随索引恢复和快照导出保留。采集时间不代替事件时间；未变化文件沿用原观察时间。增量读取不提交半尾行。每个文件在哈希、解析和复验期间固定本次读取长度；边界之后的正常追加不会中止扫描，由下一次同步读取。文件替换、截断或已捕获前缀内的改写仍会使本次读取失效。安装后的常驻服务在启动时准备近期来源。原生文件通知合并变化后触发增量同步，五分钟一次的发现巡检用于补漏。未启用常驻模式的按需服务在视图使用期间同步。显式刷新、强制读取和新的配置采集不受此间隔限制。Web 页面持续检查读取进度和已发布版本，在此间隔内不会因此强制重扫来源。单一来源失败保留原始错误码，不再统一显示为目录不可读。普通读取保留合法但无结尾换行的记录，同时报告读取不完整。文件消失或单源失败保留此前位置；混合成功只在新视图中标记失败，全部失败回滚且不改旧视图，也不单独持久化此次失败尝试。水位仍为内部事实；耗时摘要展示覆盖计数，不导出水位原字段。

Rust 快照接口 `timing_evidence` 按明确的来源、任务和轮次读取规范计量与操作、精确轮次事件、相关未归属断点及读取水位。操作归属与实际所属任务校验；查询不重新配对事件，也不遍历账本或未归属桶。内存与磁盘共用最多 100,000 条触及事实、64 MiB 编码和 100,000 次元数据工作预算，各项同时生效。超限、取消或校验失败返回错误，不返回截断成功。写入时在同次遍历中记录任务内缺少轮次的潜在 Skill/MCP 操作，作为必需元数据。未知元数据版本拒绝读取；当前格式缺少字段视为损坏，保留原快照。

Codex 消息事件只保留来源类别、内容是否为空、原生身份和记录阶段，不保留正文、长度、内容哈希或媒体地址。内容非空按原始字符串判断，空白字符串仍算非空。首条内容记录延迟使用明确轮次开始与首条已知非空可见助手记录的日志时间，不等同于首 Token 时间；较早的未知内容、缺时间、身份或跨文件顺序冲突、相关来源断点会阻止计算。已建立文件代次后的坏记录保留安全断点，增量半尾行不提交。恢复和追加要求当前消息观察映射版本，缺失或未知版本拒绝复用并保留原索引，防止混用不含消息标记的旧中间结果。严格响应间隙仍因缺少工具批次和响应周期证据而不支持。

已提交统计从版本 1 查询头恢复，不加载历史轮次、操作正文或事件目录。查询头保留来源覆盖、水位、任务归属和标题；发布前检查必需观察版本与规范标题绑定。恢复由单个工作线程负责，读取事务固定所选版本。明细查询按需从同一事务加载证据。新版本可以继续发布，旧固定视图仍可读取。

已提交聚合查询在解码目录前，将来源、Agent、项目成员、模型、推理强度和保守日期候选条件交给 SQLite 筛选。当前格式使用可重建的模型表达式索引，不另存一份规范字段。较大范围的目录读取保留可用日期、筛选维度和任务全周期总量；精确归约器保留时区、未知值和计价规则。聚合更新只访问变更块，包括已删除块；强制重新计价仍访问全部当前块。用量归约共用 10 秒执行期限、1,600 万次目录或归约工作，以及 1 GiB 的目录、压缩块和解码块字节预算。排队等待和 SQLite 进度回调均检查期限。超限返回 `RESOURCE_LIMIT`，不返回截断统计；该预算不保证 100 ms 延迟，也不是进程 RSS 上限。

事件序列化借用事实。恢复直接使用已校验的类型化事件，不再经过 JSON 编码和解码往返。解析器映射共享事件 ID，派生投影借用事件引用，不复制整份映射。较大的线程和轮次载荷分别装箱。事件来源、归属和证据路径通过有预算的文本池共享，包括线程与轮次载荷中的文本；文本池满后，各归属和时间字段仍各保留最多一个不超过 1,024 字节的最近值，用于共享相邻观察。构建事件块时，每个事件只编码一次，大小与摘要计算复用该编码，块缓冲仍受预算约束。已完成事件分区的不可变向量和哈希可在未变化的实时修订间复用。用量、任务和统计分页（含完整输出）在同一 50 行窗口内复用现有有界结果缓存，保持总量、筛选、顺序及请求的分页元数据精确。跨窗口或由定位驱动的分页保留原路径，每个视图的缓存仍限 16 项、2 MiB，所有条目的编码及键一并计入该总预算。缓存保留有界 CBOR 编码，避免请求线程退出后仍保留大量行对象。实时统计从已提交查询头恢复，不解码事件明细；指定证据查询按需恢复元数据并逐块解码。实时项目查询使用一份成员索引；对于 P 个项目及 M 条匹配计量，剩余筛选前的定位和引用收集为 O(log P + M)。离线快照构建仍保留全部 E 个安全事件，内存为 O(E)，新分区排序最坏为 O(E log E)；实时索引构建逐块处理，完整 manifest 及来源文件水位仍驻留。编码和缓存预算不是整个进程的堆内存上限。整源驻留与持久化总量上限尚未交付。

类型化 `timing` 操作返回整轮摘要、安全证据页或解析器能力；能力查询不扫描来源。证据集合明确为 `turn_events`、`use_objects` 或 `use_records`；游标绑定快照、来源、任务、轮次、集合、可选对象及方法。公开字段以 [Rust DTO](../../core/src/timing_dto.rs) 和[生成 Schema](../schemas/timing-response-v6.schema.json) 为准。固定快照查询保持离线，不触发价格刷新、配置、Hook 或账户读取。摘要输出最多 256 KiB。完整分区的原生边界索引在事实读取超限时保留独立的耗时、首 Token 时间及状态，并明确保留冲突。共用归约器最多保留两个不同数值依据及 100,000 个时钟域；对于 D 个时钟域，构建时间为 O(E log min(D,100000))，辅助空间为 O(min(D,100000))。时钟域超限时绝对锚点未知，独立原生数值仍可保留。

上下文详情超过 32 个分段或邻近记录时整体标为不可用，整轮分布不截取前缀。本地结果按快照缓存，最多 16 项、2 MiB 编码，单项连同键最多 256 KiB；每次重新绑定新鲜度，部分、运行中、超限与分享结果不缓存。分享由 Rust 独立白名单生成，使用相对时间和每次新建的包内别名，不含本机读取身份、路径或自定义名称。记录、候选和区间循环检查取消；有界排序阶段仍为协作取消，不能抢占。操作仅统计日志已观察到的范围，不能覆盖未记录活动；命令语义标签与严格响应间隙仍不支持。

请求输入变化使用 `request_input_observation_change_v1`，比较同一物理来源代次、任务、轮次及历史模型/推理强度阶段内首末请求的 `rawInput`，含缓存输入。按日志观察位置排序，不要求时间或窗口大小；不证明执行顺序、持续增长或实际上下文占用。压缩、历史模型声明切换及来源断点切断阶段。区间计量、缺输入、历史阶段或位置不明、冲突及越界数量分别排除；精确重放计一次，一个计量出现在不同位置时不任意选序，同一行多个请求不互相排序。至少两个可靠样本才可比较。保留首末量、带符号差值及非零基数的倍数；零基数不产生倍数。完整阶段计数和最大正向增加不受 32 项、32 KiB 编码明细预算影响，省略明细单独说明。没有可比较阶段时不补零；可比较阶段没有正向增加时最大增加为零。`request_input_change_inspection_v1` 以首末增加至少 16,384 Tokens 为检查门槛，这是产品启发式，不是浪费、因果或节省结论。规则、CLI、Web 和分享复用同一统计；规则不重读日志，不写用户决定。

Skill/MCP 对象摘要复用共享的操作分类、规范身份与计数口径。失败操作计入次数；声明与发现不能证明使用，候选仍为候选。缺身份、派发、目标或轮次证据时仍保留已关联次数，完整次数则按缺口解释；目标冲突的规范操作不计入任一对象。已关联次数与来源完整性分别展示，零值仅描述已采集范围。缺操作时间单独保留，不补造派发时间。本地摘要显示前 50 个对象，按已知关联次数与稳定对象键排序；对象和逐次操作分页最多 200 行，整轮总数与覆盖不随分页变化。路径、服务器名、历史项目、操作记录与游标仅限本地；分享只公开数值总计与覆盖。投影最多处理 100,000 个操作和 64 MiB 被检查字符串；完整投影失败时使用指标未知，不返回前缀。使用详情另限 128 KiB；详情超限或整份摘要触及 256 KiB 时，先移除使用详情与游标，保留已验证总计、时间和上下文。原生命令解析读取在同一个规范操作上保留多个候选目标；终态结果不能证明各目标已独立读取，用户 Shell 记录也不能证明模型使用。

操作结果优先使用结构化终态证据：已结束的工具输出带可靠退出码 0 时可确定完成；开始记录带 0、正文中的退出码文字或缺少结果不能证明完成。失败、拒绝和中断不会被后续成功标记覆盖；拒绝作为独立使用结果传给 CLI/Web。同一操作的可靠结果互相矛盾时，持久保留冲突标记及负面证据，并省略无法确定的单一退出码；重放不能清除冲突。解析状态、派生投影与固定快照要求操作观察映射版本 4，缺失或不支持的版本在读取事实前拒绝，保留原数据而不自动迁移。

工作摘要消费同一份有界规范操作，每个可靠身份只计一次，并明确保留缺身份、终态冲突、资源超限和来源覆盖。已闭合观察包含完成、失败、取消、中断和拒绝；失败不扣减候选数。文件变更记录按规范文件操作计数，包含未闭合观察。不同文件路径数包含终态变更映射 的路径和移动端点，也包含失败或拒绝结果；它只描述来源报告范围，不证明落盘或仓库净 diff。拟议变更映射、元数据不完整，或相对路径缺可靠操作 cwd 时，路径数保持未知。绝对路径只作词法规范化，不读取文件系统或解析符号链接；任务项目不能补缺失 cwd。增删行数需要仓库基线，仍不可用。用户输入、注入上下文和推理计数描述精确轮次内的物理安全记录，不是消息数、请求数或注入轮数。用户来源未分类时，用户输入记录数未知；未归属记录及部分来源通过覆盖信息保留。工作投影检查取消，最多处理 100,000 个操作、100,000 次元数据工作和 64 MiB 被检查字符串。必需身份预算超限时省略工作计算；可选元数据预算超限时省略相关工作数值，保留已完成的操作结果统计和独立时间结果。

操作结果统计另有明确的子集口径：成功与失败终态的规范操作数构成分母，失败数构成分子。完成状态且可靠退出码非零计为失败；中断、取消、拒绝、未结束、未判定及结果冲突分别计数，不补为成功。非零退出码但没有可判定终态的操作不进入比例。目标、时间和文件元数据缺口不排除可靠结果；冲突结果不选取任何一份作为比例依据。缺身份按物理记录计数，其他类别按规范操作组计数；声明和未确认调用候选不参与。比例仅描述已采集且结果可判定的记录，零分母不产生比例，来源不完整及结果缺口独立说明。旧失败操作数可保留冲突中的负向观察，不能复用为比例分子。公开耗时响应版本 6、分析方法 `safe_event_turn_v7` 和工作投影方法 2 隔离旧缓存；CLI、Web 和分享使用同一份统计结果，分享不带本地身份。

时间分析方法 `safe_event_turn_v7` 包含命令、压缩、推理和 MCP 四类，交集掩码为 0—15。原生 Item 与安全操作阶段共用起止证据归并入口；call 与 item 身份分域，仅显式别名或同一来源物理行的匹配标识可建立桥接。原生端点优先于记录时间，只有原生时长而缺端点的操作仍保留标量，不用时长倒推时间轴位置。MCP 完成标记只证明闭合，不单独证明调用成功。操作投影与时间阶段使用核心共享关联入口，调用目标或执行结果矛盾不否定一致的时间端点，按独立原因解释。原生条目完成只证明闭合；成功与失败来自结构化操作结果。共用字段观察与分析契约按[架构修订](../decisions/implemented/architecture/2026-10-05-analysis-first-events.md)定义。

Rust 将已验证的生命周期区间投影为相对时间类别轨道，并把相邻的 mask 为 0 的区间合并为未分类间隙，不拉伸原生耗时。轨道保留同域端点及终态的事件引用；间隙引用整轮证据集合。轨道与间隙共用 200 条详情上限，超限时整体省略详情，保留完整汇总和条目数。运行中、缺可靠锚点、数值越界或详情超限时选择列表展示；未定位区间超过具备身份的唯一生命周期区间半数时也以列表为主。缺身份记录保留在独立覆盖计数中。分享使用每次新建的包内别名和相对坐标。本地摘要将每个区间别名绑定到固定证据页游标，同一区间内同页支持引用合并。导航复用已读取的精确事件顺序，最多保留 600 个选中身份，不额外读取事件块。导航编码独立限制为 64 KiB，超限整体省略定位信息，保留已证实的计数。页数按各区间的定位页引用合计，重复页面仍分别计入。缺计算或依据保持未知；分享不含游标。

操作补集 `operation_residual_v1` 复用共享起止归并及现有区间并集算法，按显式轮次窗口减去可靠闭合的操作区间；推理和压缩生命周期单列。它保留候选操作、可靠端点、身份缺口、冲突与部分覆盖；没有可配对操作时不宣称模型等待。明细超过 200 项只省略细节，保留完整计算值。公开耗时响应、CLI 和 Web 展示并集、补集、配对计数、覆盖说明及有界相对区间；重复行为的取舍及来源限制见[指标决定](../decisions/implemented/architecture/2026-10-04-event-metrics.md)。

匹配观察方法 2 保存在共用操作上，与命令工作元数据分开：命令使用受支持的完整原生 argv 与历史 cwd 生成请求指纹，保留来源线程内代理执行归属及已校验的历史词法读取目标。直接 argv 和不含展开、管道或串联的字面 shell 请求可匹配；未知执行参数、插件/脚本上下文和交互输入不建立匹配；命令原文只在内存处理，使用现有 shlex 库解析，参数最多 1,024 项、64 KiB。读取目标还需原生 Read 标签与受支持的 cat/head/tail/数字范围 sed 调用一致，重复目标只保留一次。目标按来源 POSIX/Windows 路径规则处理，不查当前文件；父级路径、远端 URI 及不确定参数保留缺口。指纹仅说明请求相同，不证明二进制、环境、输入版本或效果相同；搜索类预期非零另列。当前[观察映射](../../core/src/observation_versions.rs)与[适配器版本](../../core/src/adapters/codex.rs)拒绝复用旧观察，但保留旧数据。此观察已接入再次调用/重读分析及 CLI/Web 汇总投影；固定轮次检查已消费这些共用结果；确切交付范围及历史版本仍待来源证据。

有明确服务器/工具身份的原生 MCP 条目及旧式 begin/end 调用复用同一匹配观察和归并器。完整参数对象只在内存生成摘要，参数值、资源 URI 与结果正文不落盘。现有 serde_json 对嵌套对象键排序并统一字符串转义，启用任意精度以避免数值舍入造成误匹配。数组顺序、参数是否存在和数值差异仍参与匹配；等价指数写法可能被统一。重复键、库保留的数值标记、未支持的请求上下文字段、损坏参数不建立原生匹配。限制为 64 KiB、4,096 个节点及 32 层；超限时整体省略指纹。完成记录缺参数可以保留派发时的匹配事实，冲突一经记录不会被后续记录消除。必须有明确来源线程执行归属；MCP 不提供文件系统读取目标或命令预期退出码。完整的模型函数请求另保留摘要，包含确切命名空间、调用名称及完整参数对象。旧式编码 MCP 名称、明确 MCP 命名空间及内置资源/发现名称均可使用此路径，不反解原始服务身份。函数请求必须有明确调用 ID 和受支持的完整字段结构；损坏、重复键、未知上下文或超限请求不提供摘要。参数和 URI 仅在内存处理。规范归并优先使用已有原生摘要，否则使用函数请求摘要；不将两种摘要当作相等依据。同一操作任一种摘要发生冲突时保留不可清除的冲突。函数匹配不能补造服务器归属，不能将发现算作用过，也不能将调用结束算作成功；公开的合格命令计数仍只统计命令。

再次调用/重读方法 1 复用同一次操作关联及起止归并，分别统计固定来源顺序中的额外请求记录，以及有可靠执行顺序的确认关联。没有时间或明确成功仍能统计请求记录，但来源顺序不证明执行顺序。失败后再次调用要求最近的相同请求已失败，并在后次发起前完成；重读确认要求此前有同目标读取已成功，并在后次发起前完成；其间的失败或结果不明请求不抹除已观察到的成功。只有相对发起顺序不含歧义时，单独完成记录才能建立前驱。用户输入、压缩、分叉关系和来源连续性缺口切断链；不支持匹配的命令或 MCP 请求也保守切断。跨越上下文、执行归属缺口、元数据矛盾和发起顺序歧义保留覆盖说明。原生时长优先于成对起止计算时长，原生时长冲突不补成计算值；已知小计与缺少时长的次数分开，恢复跨度单列。同一操作的两个标签只进入一次合并区间并集。明细超过 200 个匹配操作或 600 份来源记录依据时只省略细节，保留完整合计；操作/元数据/字符串预算不足则放弃整次计算，不返回截断前缀。耗时响应 6 公开次数、已知耗时小计及原生/计算/缺失次数、恢复跨度、去重覆盖时间与类型化覆盖说明。本地和分享结果分别构造，不序列化匹配键、执行归属、目标路径或原生前驱身份。汇总指标证据指向整轮记录集合；本地前驱导航使用摘要内别名及精确安全记录页游标，分别定位后次调用、前次失败和前次成功读取，始终绑定同一固定数据视图。依据包含匹配、结果、耗时及起止记录，每份最多 16 个事件引用。独立 64 KiB 编码预算超限时整体省略依据明细，保留完整计数与时间总计；摘要输出不足时，先移除这些导航再考虑汇总事实。分享不构造或包含这些定位信息。更强的读取范围/版本，以及未映射的恢复/分支边界仍需来源观察；最终验收保留在指标方案。

共享操作关联按来源、线程和轮次隔离 `Call`／`Item` 身份，显式桥接可合并两个已存在的组并撤回旧派生贡献；文本相同本身不建立关联。来源事件的原始身份不改写，派生操作尽量保留固定来源顺序中最早的操作身份。关联方法独立版本 `operationAssociationVersion=1` 由解析状态、实时投影和固定快照共同校验，缺失或不支持时保留原数据并拒绝复用。每次受影响来源完成采集后执行一次关联，E 个输入观察中有 A 个关联输入时，时间为 O(E + A log A)、附加空间为 O(A)；普通追加只写变化操作，身份撤回时在现有事务内替换该来源的规范操作投影。此处统一计算语义，不承诺减少全源驻留。别名边保存在紧凑向量中，统一排序去重。物理行和图的临时索引按精确的来源、任务和轮次逐组构建并释放；ID 冲突仍按全局来源顺序处理。窗口来源摘要使用单次处理缓存，最多保留 4,096 个文件代次。计量只请求分组，不分配计时阶段投影。

实时索引采用 SQLite schema 9、4 KiB 页和 8 MiB 连接页缓存目标。小型元数据保存在 JSONB 中；安全观察使用带摘要校验的 Zstandard 块，解码目标 256 KiB，每块最多 200 个事件，解码硬限 4 MiB。块按精确任务/轮次、来源文件及代次、256 KiB 来源偏移窗口划分，限定追加重写范围。每来源一个桶链接取代逐事件投影引用。SQLite 表达式索引直接选择精确任务块，取代重复的任务成员表；已提交视图元数据保存块定位、摘要及原生边界归约。已提交统计只恢复查询头，不保留操作定位或事件目录；证据元数据从同一版本按需加载。操作块逐块校验后释放明细；按需读取明细时，每个涉及的块在单次请求中只解码一次。观察仅按选定证据目标解码。只读 SQLite 事务固定每个读取版本，证据视图共享固定版本读取器。小型覆盖索引提供完整块数量、记录数量及编码校验，无需访问压缩正文所在页；校验规则不变。冷操作读取在解码前计算所涉及块的字节数；计时预算同时包含读取块和输出字节。每个读取连接的页缓存目标为 2 MiB，保留视图可能使 WAL 页持续保留到视图释放；这不是硬磁盘配额。规范计量和操作单独分块，每块最多 128 个槽位，小批追加复用末块，更正只替换受影响块。观察行只编码一次，用于大小判断和压缩；每轮写入复用一个压缩上下文，结束后释放；各块仍可独立解码。规范计量和操作只保存一份；解析恢复状态仅保留引用及归并前的例外。SQLite WAL、临时空间及内存事实另占资源，分块边界不是进程内存限制。参见[存储决定](../decisions/implemented/architecture/2026-10-11-packed-live-index.md)和[固定数据资源基准](../benchmarks/rebuild-resources-2026-10-11.json)。

已提交的用量和任务排行查询直接归约带摘要校验的块内聚合，无须加载整个账本。分组键保留来源、Agent、任务、原始模型、推理强度，以及 UTC 小时或日期/未知精度；新计量块按任务、模型、推理强度及时间戳小时聚集，改善压缩和聚合。版本 3 聚合内容保留按轮次的精确槽位成员；精确时间仍保存在规范块中。请求时区将同一组分到不同日期，或在其 UTC 小时内变更偏移时，只读取该组规范成员，每次遍历只解码一次涉及的块。来源总量和替代计算的 Token 分组保留到最终范围归约。更正与受影响块的聚合在同一事实事务内重写；价格变化重建聚合。全局内容寻址 FIFO 缓存只接纳与请求时区最近 30 个自然日相交的组，保守估计的驻留分配不超过 8 MiB，最多 4,096 项。历史、无日期、超大和被淘汰的组仍可从磁盘查询；热窗口不缩小结果范围。读取批次最多接纳 16 组，以 512 KiB 解码大小为目标，允许单个有效块达到 4 MiB。任务排行先用目录定位可能命中的任务，再读取整任务汇总；无关任务的历史保持压缩。连续任务分组先在有界的单任务状态中归约，再接纳到归约表；分开的片段精确合并。精确轮次位图复用固定视图的排序轮次字典，并使用 bitvec。借用字典最多接纳 4 MiB；更大的任务使用可转存的去重关系。任务、匹配轮次关系、维度、时间段和明细归约表各以编码后的保守估计接纳 4 MiB，超过后转存私有 SQLite 临时文件，并自动清理；每个临时文件上限 128 MiB，每条归约记录的编码上限 4 MiB。汇集的响应条目有 48 MiB 的保守工作大小限制。超限返回 `RESOURCE_LIMIT`，不返回截断总量。不同视图之间最多同时进行两次昂贵查询归约；同一视图重复的未命中请求，在结果符合现有响应缓存预算时复用已完成响应。这些接纳限制不是进程 RSS 硬上限。来源解析事实及关联状态、显式全量重放、任务/事件定位、筛选项，以及明细、比较和导出消费者仍有额外成本。旧的内存汇总加速器仍用于非持久快照和合成视图；持久用量和排行没有 250,000 行回退阈值。

实时索引同事务保存事实、游标和投影。截断/替换重建，文件消失保留贡献并标 partial；来源独立回滚，全部失败保留旧版。固定查询及缓存按版本/范围隔离；解析事实从已提交的恢复状态恢复，必需状态缺失时明确失败，不回退到查询投影；读取投影仍是可重建缓存，checkpoint 保留解析上下文与来源诊断，version 1 外部标题观察独立于会话事件保存，可在重放和固定视图中恢复；标题索引成功完整读取时反映标题变更或移除，读取失败则保留仍有对应线程的安全观察并报告缺口。安全事件格式 5 独立保存逐事件采集时间，不补缺失发生时间；追加、重启和同代次校验重读保留既有采集时间。消息观察映射 3 把格式无效的嵌套记录保存为同来源位置和已知范围的缺口，后续已知内容不能补成精确首条延迟。未知类型的嵌套项保留未知内容标记，已知非内容项不算内容候选。解析/投影和固定快照的必需观察版本头拒绝旧格式并保留数据。元数据未变时走快速路径，不读取日志正文；因此不能识别元数据未变但内容被改写后又恢复原时间戳的情况，显式 verify 会重验。变更或显式 verify 的文件使用 64 KiB 缓冲校验已提交前缀，并在解析前后校验本次捕获内容；观察期间来源变化则拒绝发布并重试。变更文件需完整读取两遍作校验并解析新增内容，时间为 O(捕获文件长度)，持续写入可能延迟到获得稳定读取机会；此完整性检查不构成性能提升。首次实时扫描在记录边界按批写入待提交观察，达到 1,024 个事件时或文件读取完成后写入。原始观察写入后不再留在解析缓存。恢复事实和规范事实逐块进入 SQLite 磁盘工作区。大载荷表采用普通 rowid 存储和单独的键索引；窄键关系采用 WITHOUT ROWID。主库和临时库各设置 8 MiB 建议页缓存，按需分配。[SQLite 文档说明了行大小的取舍](https://www.sqlite.org/withoutrowid.html#when_to_use_without_rowid)。变化对话重放其完整归属范围，未变化的归档目标保持关闭。刚写入块复用已编码的计量和关联输入，另以独立校验的压缩帧保存到临时库；较旧的受影响块逐块解码。操作关联每次只保留一个来源、任务、轮次目标，再把准备好的分量写入磁盘。标量锚点全局排序保留跨目标 ID 冲突处理。用量按精确身份归并，每次只保留一个候选及其持续冲突。指纹、分叉关系和直接覆盖键在磁盘排序；区间并集每次保留一个区间，计数使用精确的 u64 大端序键。原生操作重放在磁盘排序类型化别名，仅把已证明的链接保留在紧凑图中，选择并合并规范归属时才读取明细。内存与磁盘消费者复用身份、冲突、结果和证据归并规则。规范用量和操作直接分批写入压缩块，每批最多 128 条，以 256 KiB 编码大小为目标，允许单条更大的有效事实；成员目录只保留键，操作身份仲裁引用已有分量明细。首次解析直接提供有序元数据，替换和显式验证才重放元数据。发布读取目录和使用元数据，不加载完整台账。成员替换把待保留 ID 放在磁盘，每次改写一个过期块。冷证据索引排序块定位信息，不集中观察明细；事务内块元数据提供边界，归约后清除。设候选数为 M、操作分量数为 G、目标 i 的关联输入为 A_i、变化重放输入为 R、已证明分叉链接为 K、冷块数为 B，每次变化发布仍遍历 M+G 条规范输入，并排序所需标量键。内存随线程和轮次目录、最大关联目标、K 和 B 个定位信息、有界块及单条合并事实增长，不再保留全部 M+G 条明细。临时磁盘仍可能随 M+G+R 增长。单个大目标或事实仍可能消耗较多内存，这不是 RSS 或临时磁盘硬限。来源完整性校验、显式快照或明细消费者和查询预算仍有独立成本。

版本 2 解析恢复状态把不含明细的目录、压缩的原始候选与分量块，同规范事实和来源进度一起提交。重启读取目录，逐块进入磁盘工作区，不再解码第二份查询台账。必需计数、来源身份和格式头均需校验；缺块或不支持的版本明确失败，不删除数据，也不做兼容迁移。更新之间不保留整源解析明细缓存或规范事实向量。每个索引批次在有作用域的线程中执行；解析缓存淘汰后，释放闲置 SQLite 语句与页缓存，并结束该线程的分配器状态。常驻协调线程在批次线程退出后构建保留的查询头。常驻发布先丢弃超预算解析状态，再重新打开紧凑查询头，并强制回收 mimalloc 的闲置页。原生内核使用锁定版本的 mimalloc v2 后端，直接向系统申请内存段，避免大分配区，使空闲扫描段可以解除映射；空闲明细缓存于 60 秒后释放。这些措施不构成 RSS 硬限。只有索引线程接收后台调度提示，macOS 请求线程使用交互优先级。事实循环中的连接取消检测共用 1 毫秒系统探测间隔；已观察到的取消始终立即生效。常驻服务暂停时启动，只恢复已提交查询头，不扫描来源。只有来源代次仍匹配时，未共享的最新视图才能在检查点期间重建 SQLite 读取租约。WAL 超过 32 MiB 时触发压力清理：未共享的旧版或已被替代的实时视图保留精确的缓存答案，但释放明细读取租约。需要已释放事实的请求返回 `VIEW_EXPIRED`，已保存快照不受影响。活动读取者仍可能保留 WAL 页，因此这不是磁盘硬限。

快照不含消息正文、完整命令参数或工具输出，来源数据不作为指令。本机内核使用私有 Unix socket 或所有者专用 Windows 命名管道。常驻模式保留单个写入者和索引线程，无需客户端持续连接。显式非驻留模式在没有有效配置读取版本时，仍于最后调用后约 15 秒退出。HTTP 只存在于显式启动的 Web 宿主。常驻索引不执行预算检查、不发送提醒，也不导出 HTML 报告。

安装后的查询验收使用 `corepack pnpm verify:agent-query -- --output-dir /absolute/external/path`，在隔离合成来源和当前平台安装运行时上核对独立真值，并记录首次采集和已缓存查询的时间、响应字节。加 `--agent-bin /absolute/path/to/codex` 执行一次真实、短时的安装 Skill 查询，核对答案与固定身份并记录实际命令调用、结果字节及原生模型 Token；缺失 Token 字段保留未知。不运行 Agent 时只报告运行时通过，不冒充真实 Agent 验收；输出和有界日志均留在仓库外，进程及临时安装自动清理。这是单场景基线，不证明节省、规模性能或其他平台；完整连续任务验收仍归[优化提案](../decisions/proposed/product/2026-10-03-optimization-lifecycle.md)。

## 运行时采集

`collection.rs` 负责版本 1 的事件接收、本机采集偏好、安全缓冲和分页查询。`collection/association.rs` 复用适配器身份函数，按原生来源、任务和轮次身份关联已提交日志。缺少事实时保留未知；索引不可读或版本不支持时标记关联不可用。`sourceEpoch` 是当前已提交的来源投影身份，不是固定查询快照。Hook 观察不新增计量、不分摊工具费用、不改写来源日志。

私有的 `collection-v1/observations.sqlite` 将安全元数据与可重建日志索引、处理决定分开保存。输入最多 64 KiB；正文、工具参数与输出、提示词及凭据在持久化前丢弃。接收时间不替代事件时间。原生事件 ID 或工具身份与阶段去重重复投递；缺身份时保持独立。身份冲突保留首条观察并记录缺口。默认 logs 模式，仅安装资源不会采集 Hooks。

暂停时最多保留 4,096 条待处理观察；恢复使已保留记录可用，不改变身份。存储最多接收 100,000 条观察，之后拒绝新事件并累计已知容量缺口。这些是行数限制，不保证 SQLite 文件字节上限。状态汇总检查所选来源与项目的记录；事件每页最多 200 条。接收通过索引检查身份与最后序号，待处理计数受缓冲上限约束。当前不提供删除、保留轮换或格式迁移入口。持久提交前失败保留既有数据；输入拒绝和运行时不可用只能由桥接入口报告，不计入已存缺口。不能声称无损采集。

## 任务统计与监控

`statistics` 按记录中的线程聚合所选规范计量，返回有计量、总量完整及不完整的任务数，以及 Token 均值、中位数和 P90；无法归属任务的计量单列。默认范围与用量日报的近期范围一致，历史统计使用 `allTime`。项目和模型总体沿用相同筛选；多模型任务可同时计入各模型，任务数不可相加。分位数复用耗时统计的 type-7 线性插值。总量不完整的任务不进入均值和分位数，零仍是有效样本。顶层 `threadId` 将所选任务与总体中的完整样本比较，返回包含并列值的分位排名及是否超过 P90，不据此判定任务质量或浪费。

给出等长、不重叠的周期后，增长统计分别返回任务数量与单任务用量变化。完整且非空总体使用对称拆解：`ΔN × (μ0+μ1)/2` 与 `Δμ × (N0+N1)/2`，两项之和等于可归属任务的 Token 增长；无法归属任务的增长单列。空总体不虚构均值，不完整总体不计算整体贡献。这些是算术描述，不是因果节省。查询优先复用项目账本索引，不读取操作正文。M 条计量、T 个任务的计算复杂度为 O(M log(M + T) + T)，除既有快照外使用 O(M+T) 临时引用。中位数和 P90 通过线性选择计算精确的 type-7 顺序统计量。分页只限制返回的组数，不限制总体计算；未变化的实时结果复用查询缓存。实时基准包括独立分布真值、查询耗时、响应字节和服务峰值内存。

`monitor.rs` 在独立的 `user-v1/monitor.sqlite` 中保存 Token 预算、日历周期与提醒，不混入派生索引或语言偏好。设置指定来源、项目、模型、推理强度和时区，支持日、周一开始的周及月周期，默认预警比例为 0.8。检查需要近期来源观察，过期视图失败。部分小计可以证明越过阈值，不能证明剩余额度。预算提醒按授权来源集合、设置版本、周期和阈值去重；复盘描述最近结束的周期，事实变化会生成新版本；已读标记是独立的用户字段。检查不补发错过的全部周期。宿主必须显式持续检查，保存设置不会安装调度器。最多保存 100 项设置，每次检查最多指定 100 个 ID，每项存储设置最多 16 KiB，返回最近 100 条提醒。操作步骤由 [CLI 指南](../guides/cli.md)拥有。

配置列表同时返回所选范围的扩展使用统计，包括已记录使用次数，以及最近一次使用或窗口起点之后的完整日数。保留来源覆盖，缺失不可证明不存在；这些是无使用记录的时间段，不是确认闲置或删除建议。原生字面文本结果只保存哈希，不保存正文；可信原生 AGENTS 注入元数据可将无歧义的单份规则正文绑定到路径。规则注入按原生消息身份与文档路径去重，同一消息可以加载多个不同文档。后续跟踪区分复查版本的读取、规则加载及版本未知；读取或加载不证明执行使用。复查前后采用同一记录来源和项目范围、等长实际时间窗口，返回任务总体及用量，不分摊工具成本，也不认定修改产生了节省。缺失历史版本、MCP 采用和完整连续观察仍取决于来源证据。

## 对话证据

`conversation.rs` 负责 v1 活动、位置、原文、字面检索及固定基线变化查询。它读取安全事件分区，独立于 Token 账本。筛选组合来源、记录的项目、任务、轮次、消息来源及类型和日历范围。结果按索引来源顺序返回。一条来源记录可产生多个观察，数量不证明任务数或工作已经完成。已有数据块和分区摘要中的消息数量让定位及检索跳过纯控制分区。返回的准确事件偏移可定位一个索引观察，无需扫描整个轮次。

原文定位使用安全事件格式 5、消息映射 3 和文件水位格式 2。受支持的 JSON 文本部分按约 8 KiB 划分为可独立解码的块，保留字节位置和 SHA-256 校验值，不拆开 Unicode 或 JSON 转义。每条消息最多保留 4,096 个块，后续内容明确标为缺口。文件路径和物理身份归属于逐文件水位。正文及媒体不进入索引。读取校验选定块和来源身份，不证明整个当前文件未变化。固定视图范围外的追加内容不进入结果。来源缺失、替换、截断或选定块变化时明确失败。旧格式被拒绝，不迁移或删除数据；派生数据需要单独授权重建。

一次请求最多读取 20 个目标、打开八个来源文件。每个目标默认返回 8 KiB 文本，最多 256 KiB。包含元数据和新鲜度的响应编码预算为 1 MiB。定位及检索每页最多 200 个结果，每次最多检查 2,000 个事件和 10,000 个分区条目，未完成时返回绑定范围的续查信息。每次原文件读取预算默认 8 MiB，最多 16 MiB。检索按受支持文本部分进行字面匹配，可跨块续查；不重组增量文本流或检索非文本内容。来源及读取预算不是进程内存或耗时的硬上限。固定视图可能过期，代次变化也可能包含历史内容的重新观察。CLI 操作见 [CLI 指南](../guides/cli.md)。
