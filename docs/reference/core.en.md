# Rust core

[中文](core.md) | English

`wombat-core` reads local Agent records, creates immutable snapshots, and serves usage and conversation queries from one business model. Codex is the current production source; see the [source acceptance reference](../development/adapters.en.md) for the supported scope.

## Entry points and responsibilities

- `src/adapters/` identifies source facts; `pricing.rs` owns offline prices; `usage_store.rs` writes and reads snapshots; `usage_app.rs` runs shared queries.
- `usage_app_dto.rs` defines requests and results and generates TypeScript and Schema; see the [contracts](../development/contracts.en.md) for field semantics.
- `src/main.rs` accepts one JSON request on stdin and emits one final JSON result on stdout; stage progress goes to stderr.

## Internal business modules

| Business area | Code responsibilities |
|---|---|
| Codex source | `adapters/codex/`: bounded reading, source events, identity facts, direct/cumulative accounting and index titles; the separate incremental entry remains |
| Session relationships | `session_relations.rs`: indexes explicit parent relationships for inherited measurement and operation deduplication; cycles and their descendants establish no trusted ancestry |
| Turn timing | `timing/` and `timing_dto.rs`: fixed-turn analysis, bounded evidence, local/share projections, and a separate per-snapshot result cache |
| Usage queries | `usage_app/`: scope validation, conserved summaries, date/dimension reports and task/turn/step queries; the parent assembles query caching |
| Snapshots | `usage_store/`: immutable generations, exact shard reads and shared live views; each measurement has one ledger attribution |
| Live service | `live/`: incremental collection, revision selection, typed queries and connection/service lifecycle |
| Configuration | `config/`: inventory, scope and evidence queries; scanning separates text/instructions/extensions, while static algorithms separate whole blocks/declared relations/local references |
| Optimization | `optimize/`: deterministic rules, independent outcomes, review service and durable database; user decisions and check facts remain independent |

Only current public contracts and data formats are maintained; unknown formats are rejected without migration. Tests follow the same business groupings and retain independent synthetic expectations.

`operation_association/lifecycle.rs` provides one fold for reliable terminal outcomes and exit codes. Associated phases share one operation identity string. Endpoint reduction also produces an immutable `TerminalResult` and at most four terminal evidence references. Timing and repeated-behavior analyses reuse that result instead of replaying terminal evidence separately. Results distinguish unobserved, known, and conflicting evidence. Later duplicates cannot clear a conflict, and no fabricated state represents it. Each operation retains at most two distinct outcomes and two distinct exit codes. Terminal evidence folding takes O(n) time and O(1) space. This bound excludes complete identity association and endpoint reduction. Temporal closure does not prove tool success; target matching and accounting rules remain independent.

`SessionRelations` accepts only explicit relationships and exact evidence identities. It neither parses source files nor infers parent relationships from paths or times. The relationship index uses iterative traversal and assigns inherited observations to the oldest recorded ancestor. Independent events remain separate. `FilePathChange` provides one traversal of the original path and move target for validation, resource budgets, and change statistics, without querying the current filesystem. Configuration aggregation keeps physical object and source inventory identities separate. It checks version agreement against the first object in linear time. Differences preserve each observation and establish no historical content.

## Limits and verification

Recorded native total input remains available when cache breakdowns are missing. Cache-hit rates use recorded input and cache reads from the same measurements; contradictory categories suppress the ratio, and category sums do not restore conflicting native input.

Measurement observations retain field-specific model, provider, API-provider, and reasoning-effort conflicts through inheritance, append, and replay. Price-relevant conflicts preserve tokens but prevent model-rate selection; reasoning-effort conflicts alone do not prevent pricing. Tiered prices require recorded request input, without reconstructing it from potentially conflicting categories. Parser state, projections, and fixed snapshots require measurement observation mapping version 2; incompatible headers reject reuse while preserving original data.

Default refresh reads source logs without changing them and writes only to the product data directory. Unpriced or missing values, partial source failures, and resource limits remain visible; the [architecture](../development/architecture.en.md) and [core rules](../../core/AGENTS.md) describe ownership and failure boundaries. After algorithm or storage changes, run the relevant synthetic expectations, formatting, and clippy checks; rebuild the core before cross-language tests.

## Runtime collection

`collection.rs` owns version 1 receipt, machine-wide collection preferences, safe buffering and paged queries. `collection/association.rs` binds native source/session/turn identities to committed log facts through the adapter’s shared identity functions. Missing facts remain unknown; unreadable or unsupported indexes make association unavailable. `sourceEpoch` is the current committed source projection identity, not a fixed query snapshot. Hook observations never create measurements, allocate tool costs, or alter source logs.

Private `collection-v1/observations.sqlite` stores safe metadata independently of rebuildable log indexes and handling decisions. Inputs are bounded to 64 KiB; bodies, tool parameters/output, prompts and credentials are discarded before persistence. No event time is synthesized from receipt time. Native event IDs or tool identity plus phase deduplicate repeated delivery; absent identity remains distinct. Conflicting identities preserve the first observation and count a gap. Default mode is logs, so installing resources alone collects no Hooks.

Pause retains at most 4,096 pending observations; resume makes retained records available without changing their identity. The store admits at most 100,000 observations, refusing further events while counting known capacity gaps. These limits are row limits, not SQLite byte-size guarantees. Status aggregates inspect the selected source/project rows; event pages contain at most 200 rows. Indexed ingestion checks identities and the last sequence, while pending-count work is bounded by the buffer. There is no deletion, retention rotation or format migration entry. Failures before durable commit preserve prior data; rejected input or runtime unavailability is observable only through the advisory bridge and is not included in persisted gaps. Do not claim lossless collection.

## Task statistics and monitoring

`statistics` groups selected canonical measurements by recorded thread. It reports measured, complete and incomplete task counts, mean, median and P90 tokens, with unassigned measurements separate. It defaults to the same recent daily range as usage; use `allTime` for history. Project/model populations use the same filters. A multi-model task belongs to each model population, so those task counts are not additive. Quantiles reuse type-7 linear interpolation from timing. Incomplete task totals are excluded from means and quantiles; zero totals remain samples. A top-level `threadId` compares that task with the selected population using the midrank of complete samples and the P90 threshold. This does not classify task quality or waste.

With equal, disjoint period bounds, growth reports task-count and per-task changes. For complete, nonempty populations, symmetric contributions are `ΔN × (μ0+μ1)/2` and `Δμ × (N0+N1)/2`. Their sum equals attributed task-token growth; unassigned growth remains separate. Empty populations have no invented mean, and incomplete populations have no whole-population contribution. These describe arithmetic, not causal savings. Queries reuse project ledger indexes where available and do not read operation bodies. Calculation is O(M log(M + T) + T log T) with O(M+T) temporary references for M measurements and T tasks, plus the existing snapshot. Pagination bounds returned groups, not population work; unchanged live results use the query cache. The live benchmark includes an independent distribution oracle, elapsed query time, response bytes and service peak memory.

`monitor.rs` owns token budgets, calendar periods and durable notifications in `user-v1/monitor.sqlite`, separate from derived indexes and language preferences. A plan selects source/project/model/effort filters and a timezone, with daily, Monday-based weekly or monthly periods. Default warning ratio is 0.8. Recent source checks drive evaluations; stale views fail. Partial subtotals can prove a crossing, but cannot prove remaining allowance. Budget notices are deduplicated by authorized source set, plan revision, period and threshold. Reviews describe the latest closed period; changed review facts produce a new version. Acknowledgement remains a separate user field. A check does not replay missed periods. Hosts must explicitly keep checking; saving a plan does not install a scheduler. Limits are 100 plans, 100 selected IDs per check, 16 KiB per stored plan, and the latest 100 returned notifications. CLI procedures belong to the [CLI guide](../guides/cli.en.md).

Configuration lists include scoped extension-activity statistics with recorded-use counts and elapsed whole days since the latest recorded use or selected-window start. Source coverage stays attached; absence is not observable, so these are no-recorded-use intervals, not confirmed inactivity or deletion recommendations. Native literal text results retain hashes, never bodies. Trusted native AGENTS injection metadata can bind one unambiguous instruction body to its path. Native message identity and document path deduplicate rule injections; one message can load several distinct documents. Follow-up separates checked-version reads, checked-version rule loads, and unknown versions; reads/loading do not establish execution use. Equal elapsed before/after windows return task populations and usage within the same recorded source/project scope, without allocating tool costs or proving edit-caused savings. Missing historical versions, MCP adoption and complete continuous observation remain source-evidence gaps.
