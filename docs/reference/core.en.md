# Rust core

[中文](core.md) | English

`wombat-core` reads local Agent records, updates its internal index, and runs usage and conversation queries from one business model. Codex is the current production source; see the [source acceptance reference](../development/adapters.en.md) for the supported scope.

## Entry points and responsibilities

- `src/adapters/` identifies source facts; `pricing.rs` owns offline prices; `usage_store.rs` writes and reads snapshots; `usage_app.rs` runs shared queries.
- `usage_app_dto.rs` defines requests and results and generates TypeScript and Schema; see the [contracts](../development/contracts.en.md) for field semantics.
- `src/main.rs` accepts one JSON request on stdin and emits one final JSON result on stdout; stage progress goes to stderr.

## Internal business modules

| Business area | Code responsibilities |
|---|---|
| Codex source | `adapters/codex/`: bounded reading, source events, identity facts, direct/cumulative accounting and index titles; the separate incremental entry remains |
| Session relationships | `session_relations.rs`: indexes explicit parent relationships for inherited measurement and operation deduplication; cycles and their descendants establish no trusted ancestry |
| Turn timing | `timing/` and `timing_dto.rs`: fixed-turn analysis, bounded evidence, local/share projections, and a separate per-snapshot result cache |
| Usage queries | `usage_app/`: scope validation, conserved summaries, date/dimension reports and task/turn/step queries; the parent assembles query caching |
| Accounting storage | `usage_store/`: immutable generations, exact shard reads and per-request fact readers; each measurement has one ledger attribution |
| Foreground queries | `live/`: incremental SQLite collection, per-request reads and project composition; no listener or lifecycle manager |
| Configuration | `config/`: inventory, scope and evidence queries; scanning separates text/instructions/extensions, while static algorithms separate whole blocks/declared relations/local references |
| Optimization | `optimize/`: deterministic rules, independent outcomes, stateless comparisons and durable user decisions; user decisions and check facts remain independent |

Only current public contracts and data formats are maintained; unknown formats are rejected without migration. Tests follow the same business groupings and retain independent synthetic expectations.

`operation_association/lifecycle.rs` provides one fold for reliable terminal outcomes and exit codes. Associated phases share one operation identity string. Endpoint reduction also produces an immutable `TerminalResult` and at most four terminal evidence references. Timing and repeated-behavior analyses reuse that result instead of replaying terminal evidence separately. Results distinguish unobserved, known, and conflicting evidence. Later duplicates cannot clear a conflict, and no fabricated state represents it. Each operation retains at most two distinct outcomes and two distinct exit codes. Terminal evidence folding takes O(n) time and O(1) space. This bound excludes complete identity association and endpoint reduction. Temporal closure does not prove tool success; target matching and accounting rules remain independent.

`SessionRelations` accepts only explicit relationships and exact evidence identities. It neither parses source files nor infers parent relationships from paths or times. The relationship index uses iterative traversal and assigns inherited observations to the oldest recorded ancestor. Independent events remain separate. `FilePathChange` provides one traversal of the original path and move target for validation, resource budgets, and change statistics, without querying the current filesystem. Configuration aggregation keeps physical object and source inventory identities separate. It checks version agreement against the first object in linear time. Differences preserve each observation and establish no historical content.

## Artifact observations

`artifacts` inspects current files without session indexing, account reads or price downloads. Rust owns discovery, ownership, observations and guarded rechecks; Codex owns authorization and project edits. The original structured result is passed back as data instead of being retained in a service. No automatic cleanup report database or execution receipt is created.

Discovery uses actual project manifests and fixed output names, not path substrings or arbitrary cleanup scripts. Supported regeneration evidence is conservative: a tagged Cargo target with a valid manifest and no detected target override, or a direct TypeScript compiler script with an explicit output directory. Other outputs require review. Native Git checks protect tracked content and expose untracked material. User assets, nested repositories, symbolic links and positive open-file observations block a candidate. An unavailable Git or use probe remains unknown. Open-file observations do not establish historical inactivity, accepted delivery or absence of future consumers. Pending Wombat stages additionally check the existing refresh lock and always require recovery review.

Traversal checks an eight-second budget, 100,000 steps and 8 MiB of accumulated queued path bytes. Native probes have at most two seconds and monitored output bounds. Scans do not hash file contents; two bounded metadata traversals compare file identities, sizes and change times. Hard links count once in total logical bytes. Allocated bytes, when available, are observations rather than reclaim estimates; shared extents, other links, Trash and concurrent activity prevent a freed-space claim. Reaching a limit or observing changes makes coverage partial. These checks cannot make an external deletion atomic.

Each artifact response is limited to 256 KiB. Recheck accepts the original plan and selected IDs without a time lease. It validates policy, scope, project identity and observations; results distinguish unchanged, changed, gone and unavailable. The [CLI guide](../guides/cli.en.md) owns syntax. Unix open-file probes use `lsof`; unavailable probes and Windows observations remain unknown. Native removal has only been exercised locally on macOS.

Codex mode uses six product-specific rules rather than scanning arbitrary home caches. Fixed desktop cache leaves are rebuildable; Sparkle stages compare verified bundle identifiers and decimal build numbers, with the orphan retention window when versions are unavailable. Marketplace stages require known installer prefixes and age. Daemon releases retain the current and pending versions and require the existing installer lock. Runtime caches retain complete runtime/dependency pairs and classify only incomplete entries as disposable. Crashpad selects only old direct regular-file children of `pending`; sibling state and nested directories remain protected. The orphan window is 30 days. Codex state, sessions, credentials, complete runtimes and unrecognized paths are not cleanup targets.

`apply` accepts only explicit candidate IDs from the supplied original Codex plan; it has no arbitrary-path or force input. It rechecks selection, complete item evidence, policy, parent/object identities, process status, open files and version evidence before removal. The daemon install lock stays held through removal. Unknown, changed or newly active conditions stop the batch; individual outcomes distinguish removed, already absent, skipped and failed. Removals are permanent, with no automatic restore or persistent execution receipt. Bundled internal links are measured without following their targets and removed as links; linked candidate roots or ancestors are rejected. General project output cleanup remains owned by Codex native tools. Concurrent changes outside the installer lock cannot be made universally atomic; a missing final observation never establishes success.

Discovery and removal use bounded batches. Incomplete discovery can expose complete candidates from the observed batch without claiming a complete inventory; incomplete item or version evidence cannot authorize that item. The next inspection finds remaining candidates. Codex mode supports macOS layouts; other platforms return partial coverage without deletion. No source indexing, price fetch or account read is needed. This is an independent Rust implementation informed by [Mole's Codex rules](https://github.com/tw93/Mole/blob/85162c24071d98560749e5c0a192876a252d7733/lib/clean/dev.sh), not a bundled copy of its implementation.

## Limits and verification

Recorded native total input remains available when cache breakdowns are missing. Cache-hit rates use recorded input and cache reads from the same measurements; contradictory categories suppress the ratio, and category sums do not restore conflicting native input.

Measurement observations retain field-specific model, provider, API-provider, and reasoning-effort conflicts through inheritance, append, and replay. Price-relevant conflicts preserve tokens but prevent model-rate selection; reasoning-effort conflicts alone do not prevent pricing. Tiered prices require recorded request input, without reconstructing it from potentially conflicting categories. Parser state, projections, and fixed snapshots require measurement observation mapping version 2; incompatible headers reject reuse while preserving original data.

Default refresh reads source logs without changing them and writes only to the product data directory. Unpriced or missing values, partial source failures, and resource limits remain visible; the [architecture](../development/architecture.en.md) and [core rules](../../core/AGENTS.md) describe ownership and failure boundaries. After algorithm or storage changes, run the relevant synthetic expectations, formatting, and clippy checks; rebuild the core before cross-language tests.

`investigate`, `trajectory`, `resources`, `review` and `context` execute in `usage_app/inspection.rs` over one committed view, without source synchronization or price refresh by default. Inspection method 3 returns fixed thresholds, source coverage, complete candidate counts and bounded details; signals do not establish waste, causes or efficiency. Pure checks in `usage_app/inspection/rules.rs` consume aggregated candidates and shared parameters. The query continues to own statistics and evidence reads; rules obtain no separate snapshot, clock, or source. Task summaries reuse the canonical ledger. Failure statistics reuse determinate work outcomes. Identical requests count additional observations only within one turn and receiver with a complete callable fingerprint; they do not establish retries or equal effects.

Opportunity method 1 adds 17 independent checks to `investigate` and `review`: unpriced usage; project estimate concentration, task estimate outliers and period increase; cache creation/reuse and model-choice review; sensitive read/change paths and changes outside the recorded project; risky command patterns, possible credentials, sensitive reads followed by same-path outbound requests and repeated risky declines; explicit permission requests, missing returned answers, long request/response intervals and recurring short empty polling. Rust owns the fixed policy, whole-scope statistics, hit/miss/insufficient status, gaps, complete finding counts and up to three findings per check. Amount checks use complete API-equivalent prices and the same preceding disjoint period; they never allocate amounts to operations. Model review compares the complete participating tasks’ operation-count median and requests human evaluation, without inferring task difficulty or savings. Paths use historical lexical boundaries, with proposed/reported changes distinct from actual disk state. Runtime checks inspect bounded supported source fields in memory and retain only classifications, native associations and required paths. A same-path outbound request does not prove transfer. Explicit returned answer IDs can establish an omitted answer; no reply cannot establish an unanswered question. Round-trip intervals do not isolate user waiting. Polling needs native running-turn boundaries, empty input/output, short consecutive intervals, sufficient tasks/dates and recent observations; gaps, new input and nonempty output break chains. Unsupported fields, oversized payloads and missing associations remain coverage gaps. Safety pattern matches invite review and do not establish execution or harm. These checks reuse one bounded event read per selected task, with indexed associations rather than pairwise searches; they add no persistent issue model, source writes or execution receipts.

`investigate` and `review` also return workflow findings under activity method 1: at least 2 identical requests with durations of 30 seconds or more; at least 5 current determinate operations and 3 failures, with a failure rate of at least 20% and 3 times the baseline rate (at least 20 baseline outcomes; a zero rate uses a 1% comparison floor); a current maximum duration of at least 30 seconds, at least 10 times the median of 8 or more baseline durations and at least 20 seconds longer (baseline median at least 2 seconds); at least 5 identical requests across 2 or more tasks in one project; at least 3 failures or 2 declined results for one request within one task. Rust returns the parameters and combines multiple signals into one request group. The baseline is the preceding, disjoint period of equal length, with source, project, task, model, effort and timezone filters preserved. All-history, undated and incomplete date selections run only checks that need no history.

Groups use the source instance, recorded project and complete command request/historical cwd or callable/parameter fingerprint. Unknown projects group only within one task; requests with unreliable receivers are excluded. Findings export no fingerprints, bodies, commands or output. Equal requests do not establish equal environments, effects or waste. Confirmed search, test and difference requests with exit code 1 are not failures. Conflicting and nonterminal outcomes contribute neither failure denominators nor duration samples. Repeated declined operations do not count permission prompts; complete approval exchanges remain unavailable; additional checks use explicit question results when present. Activity aggregation reuses one canonical-operation read and counts current and baseline observations. Additional space is O(N); request-group sorting and duration medians take O(N log N), with N limited by the operation work budget. No persistent domain entity is added. At most 30 groups are shown, with complete matching group counts, request/outcome/duration coverage and evidence bound to each window. Narrow the query when more groups exist. No finding does not prove that the source has no problems.

Input trajectories use canonical request measurements and safe-event physical order. Points retain raw input, uncached input, cache reads and signed changes. Compaction, source file/generation, context declarations, model/effort, turn, scope gaps and source discontinuities end consecutive comparisons. Missing model/effort, multiple requests on one physical line, nonunique measurement positions or missing order supply no consecutive delta. A separate compaction comparison returns adjacent before/after inputs and their signed difference when both records share the selected scope, physical source, context and turn. It does not join continuous deltas or establish a causal saving. Input does not establish context occupancy or a capacity ratio. Resources group by source instance, historical project, path and identity basis, separating verified lexical read targets from change reports with unverified aliases. They retain proposed/reported changes, duration subtotals and operation coverage, and unlocated operations. Actual disk changes remain unavailable; tokens and costs are never allocated. Operations with multiple targets cannot be added across resources as a distinct-operation total.

Period review combines same-view, same-scope period contributions, top tasks, models, tools, investigation signals and resources. Without dates, it selects the view cutoff's week starting Monday. End dates are exclusive; open periods remain partial. Top tasks, models and resources each retain at most 10 rows; remaining model usage reconciles separately. Concentration uses complete canonical totals for the top one, five and ten tasks. Remaining task usage includes unassigned measurements and reconciles with the top ten. Missing totals or a zero denominator leave shares unavailable. Pages and evidence bind complete task/turn/operation identities, original scope, method and snapshot. Expiry returns an error; reacquire the original scope and locate identities rather than replacing them with current ranking positions. Whole-task inspection retains the view ledger for accounting, prunes canonical operation turns by their complete timestamp bounds, and reads only event blocks intersecting the requested calendar window. Activity comparisons also select the original baseline window. Body-free measurement order, compaction, model and gap observations in the block index preserve full-thread trajectory boundaries without reopening historical payloads; blocks containing source gaps remain required. These summaries use actual fact timestamps, not turn start times, and retain undated observations separately. Metadata reduction remains proportional to the selected threads' index, not just the returned page. The limits remain: at most 250,000 view measurements, 10,000 selected tasks and resource groups each, and 100,000 operations and event work units each, with a shared 64 MiB budget for touched event block encodings. The encoded result including live metadata is limited to 256 KiB; excess fails the whole query and requires narrower scope. Pagination does not establish index-bounded calculation or verified scale performance. Explicit `investigate` scope with `threadId` and `turnId` reads only that turn’s measurement/operation slice and bounded events with relevant source controls, using the existing timing reader. It does not traverse unrelated ledger rows or event partitions. Its limits are 100,000 touched facts, 64 MiB of encodings and 100,000 metadata inspections; a large selected turn can still fail. Results mark selected-turn scope and retain original filters and evidence identities. Inspection hydrates evidence metadata from the same committed revision before reading the selected scope.

Native account observations persist separately in private `account-history.sqlite`, with storage format and interval method each at version 1, independent of rebuildable usage indexes and user decisions. Stored fields are normalized observation time, hashed account identity, windows and percentages; email, credentials and native bodies are excluded. Native failures retain gap observations; equal values remain separate observations. `account history` reads the latest 20 rows and complete observation count, without a native process or historical backfill. Percentage-point changes require adjacent valid observations with the same account, bucket, window duration and reset period. Unknown identity, failure, resets, expiry and reversed time break intervals. Each stored observation has a 128 KiB budget; the complete history response has a 256 KiB budget. Unknown storage versions fail before payload decoding or writing while preserving data. History-write failures report independently without hiding valid current allowance. History does not establish local-task attribution, tokens per percentage point or exhaustion predictions.

Resource hotspots omit the thread event-history read and use canonical operation facts. A query for one turn retains the existing turn-evidence read. Inspection operation reads do not select and clone turn measurements again; the query already owns its scoped ledger. Operation and response budgets still apply. Analyses that need event order or context keep their event budgets; this change does not omit their evidence or widen their limits.

## Foreground queries and internal storage

Each CLI request starts one bounded core child and waits for its response and exit. There is no Wombat listener, endpoint discovery, service registration, automatic startup or retained view queue. Capability discovery does not open the index or scan sources. Cancellation terminates this caller's process tree; a completed write can still have taken effect.

SQLite remains an internal, rebuildable index. Incremental collection commits source cursors, observations and accounting facts together. One private file lock serializes collection and generation publication across callers; a caller waits at most 600 seconds. Read transactions keep one request internally consistent without exposing a lease or selector. They close with the request. This does not freeze results across independent commands.

The current index retains compressed source facts, shared metadata, accounting projections and source positions. Original message bodies and tool output stay in read-only source files. Headers restore accounting without decoding all event frames; conversation queries read selected partitions and chunks. Source identities, format versions, opaque cursor bindings and original-text checks still apply.

Automatic usage, task ranking and statistics reports read original records when no current reuse data matches. Direct and reused accounting feed the same report reducers, including the same price-status rules. Recent reports can defer older source files and disclose `historyDeferred`; modification time is a preparation hint. Older ranges and all-time queries include available history. Explicit `fresh`, verification, rebuild and evidence operations still use the full SQLite index. Explicit `cached` reads committed full-index data and reports its last check time.

On macOS, Linux and Windows, two slow historical reads of the same local inventory can admit one low-priority worker after the second result is flushed. Each source read must take at least one second. The worker accepts one source, 256–512 MiB of input and at most 256 rollout files, with a 45-second work deadline and a 384 MiB sampled peak-memory cancellation threshold. A single writer lock prevents concurrent workers. It keeps one compressed ledger cache of up to 16 MiB, with a 64 MiB decoded limit. The cache holds canonical measurements and required report metadata. It never stores message bodies, tool output or priced totals. A change in file identity, size, modification or change time invalidates reuse. A worker rechecks the captured inputs before atomic publication and exits after the attempt. A failed or obsolete build leaves any previously committed cache in place. A build is skipped if the OS cannot report worker memory or verify file change times.

A usage batch accepts at most eight additional queries under one source scope and read transaction. Additional queries cannot choose roots, request another revision or refresh. The complete batch is bounded to 2 MiB. Ordinary JSON presentation remains compact; full-scope accounting does not depend on page size or presentation.

An explicit rebuild scans into a new current-format SQLite generation and publishes its pointer only after durable completion. Failure preserves the previous index. User decisions, grants, identities and handling records remain separate. Unknown formats fail without migration or deletion. No public saved-view export or fixed-view query is provided.

Configuration checks read current inventory. Rechecks accept the original selected finding, scope and rule inputs as data, then inspect current conditions. Cleanup rechecks and apply accept the original inspection plan and selected IDs. Plans do not expire with a process. They are not authorization or trusted current facts: apply rediscovers supported objects, checks project identity, file observations, active consumers and protected state, and retains the installation lock where required. Changed, incomplete or protected objects are not removed. Inspections and rechecks do not create an automatic report history.

## Runtime collection

`collection.rs` owns version 1 receipt, machine-wide collection preferences, safe buffering and paged queries. `collection/association.rs` binds native source/session/turn identities to committed log facts through the adapter’s shared identity functions. Missing facts remain unknown; unreadable or unsupported indexes make association unavailable. `sourceEpoch` is the current committed source projection identity, not a fixed query snapshot. Hook observations never create measurements, allocate tool costs, or alter source logs.

Private `collection-v1/observations.sqlite` stores safe metadata independently of rebuildable log indexes and handling decisions. Inputs are bounded to 64 KiB; bodies, tool parameters/output, prompts and credentials are discarded before persistence. No event time is synthesized from receipt time. Native event IDs or tool identity plus phase deduplicate repeated delivery; absent identity remains distinct. Conflicting identities preserve the first observation and count a gap. Default mode is logs, so installing resources alone collects no Hooks.

Pause retains at most 4,096 pending observations; resume makes retained records available without changing their identity. The store admits at most 100,000 observations, refusing further events while counting known capacity gaps. These limits are row limits, not SQLite byte-size guarantees. Status aggregates inspect the selected source/project rows; event pages contain at most 200 rows. Indexed ingestion checks identities and the last sequence, while pending-count work is bounded by the buffer. There is no deletion, retention rotation or format migration entry. Failures before durable commit preserve prior data; rejected input or runtime unavailability is observable only through the advisory bridge and is not included in persisted gaps. Do not claim lossless collection.

## Task statistics and monitoring

`statistics` groups selected canonical measurements by recorded thread. It reports measured, complete and incomplete task counts, mean, median and P90 tokens, with unassigned measurements separate. It defaults to the same recent daily range as usage; use `allTime` for history. Project/model populations use the same filters. A multi-model task belongs to each model population, so those task counts are not additive. Quantiles reuse type-7 linear interpolation from timing. Incomplete task totals are excluded from means and quantiles; zero totals remain samples. A top-level `threadId` compares that task with the selected population using the midrank of complete samples and the P90 threshold. This does not classify task quality or waste.

With equal, disjoint period bounds, growth reports task-count and per-task changes. For complete, nonempty populations, symmetric contributions are `ΔN × (μ0+μ1)/2` and `Δμ × (N0+N1)/2`. Their sum equals attributed task-token growth; unassigned growth remains separate. Empty populations have no invented mean, and incomplete populations have no whole-population contribution. These describe arithmetic, not causal savings. Queries reuse project ledger indexes where available and do not read operation bodies. Calculation is O(M log(M + T) + T) with O(M+T) temporary references for M measurements and T tasks, plus the existing snapshot. Median and P90 use exact type-7 order statistics through linear selection. Pagination bounds returned groups, not population work; unchanged live results use the query cache.

`monitor.rs` owns token budgets, calendar periods and durable notifications in `user-v1/monitor.sqlite`, separate from derived indexes and language preferences. A plan selects source/project/model/effort filters and a timezone, with daily, Monday-based weekly or monthly periods. Default warning ratio is 0.8. Recent source checks drive evaluations; unavailable evidence fails. Partial subtotals can prove a crossing, but cannot prove remaining allowance. Budget notices are deduplicated by authorized source set, plan revision, period and threshold. Reviews describe the latest closed period; changed review facts produce a new version. Acknowledgement remains a separate user field. A check does not replay missed periods. Hosts must explicitly keep checking; saving a plan does not install a scheduler. Limits are 100 plans, 100 selected IDs per check, 16 KiB per stored plan, and the latest 100 returned notifications. CLI procedures belong to the [CLI guide](../guides/cli.en.md).

Configuration lists include scoped extension-activity statistics with recorded-use counts and elapsed whole days since the latest recorded use or selected-window start. Source coverage stays attached; absence is not observable, so these are no-recorded-use intervals, not confirmed inactivity or deletion recommendations. Native literal text results retain hashes, never bodies. Trusted native AGENTS injection metadata can bind one unambiguous instruction body to its path. Native message identity and document path deduplicate rule injections; one message can load several distinct documents. Follow-up separates checked-version reads, checked-version rule loads, and unknown versions; reads/loading do not establish execution use. Equal elapsed before/after windows return task populations and usage within the same recorded source/project scope, without allocating tool costs or proving edit-caused savings. Missing historical versions, MCP adoption and complete continuous observation remain source-evidence gaps.

## Conversation evidence

Direct visible-message search streams original Codex logs without opening the analysis index. It uses the recorded session project, the message timestamp, and the original row byte range. A context request makes one bounded pass over each file containing returned hits and shares repeated neighboring messages across the page. Limits bound input, time and output. Resuming requires the same observed log inventory. Introduce an index for this search only if a real workload shows a substantial end-to-end gain over direct reads with the same evidence and filters. Include initial build cost, repeated queries and disk use in the comparison.

`conversation.rs` owns activity, location, original-text and literal-search queries. It reads safe event partitions independently of the Token ledger. Selection combines source, recorded project, task, turn, message origin/kind and calendar scope. Results use indexed source order. A source row can yield several observations; counts do not establish distinct tasks or completed work. The current event index is version 3; internal manifests are version 5. Older formats are rejected without migration or deletion. Existing frame summaries retain message counts and UTC time bounds, including undated-message presence. Location/search skip frames outside the selection and borrow non-message payloads while decoding only message facts. Each query reads a selected frame at most once; a later page can reopen it. No message bodies, second text index or whole-history cache are added. Exact returned event offsets locate one indexed observation without scanning its entire turn.

Original text uses safe-event format 5, message mapping 4 and file watermark format 2. A user-role record whose complete declared content kinds identify Codex app page context is injected context. Default message selection excludes it; explicit origin selection can still read it. Literal user quotations, mixed user/context kinds and unknown kinds retain their original classification. Each supported JSON text part has independently decodable blocks of about 8 KiB, with byte positions and SHA-256 checksums; Unicode and JSON escapes stay intact. At most 4,096 blocks are retained per message; further parts remain explicit gaps. File path and physical identity belong to the per-file watermark. Bodies and media stay outside indexes. Historical message and event reads open only the immutable evidence directory and selected frames, without restoring accounting or operation directories. Later detail queries share the same directory partitions. Its metadata stays with the request lifetime; message bodies are not cached. Reads verify the selected blocks and source identity, not the complete current file. Live browsing can include committed appends. Fixed export scopes use a fingerprint of selected event partitions, filters and source status. This checks the selected evidence across requests without retaining a process or view. A change in a selected partition can require a restart even if the changed event is outside the exact date or message filters. Missing, replaced, truncated or changed selected blocks fail explicitly. Old formats are rejected without migration or data deletion; derived data needs a separately authorized rebuild.

Record listing includes conversations without Token measurements and returns one matching activity per recorded task, ordered by last activity. Pagination binds source targets and filters. Global literal search requires both calendar bounds unless a project or task is selected. A search hit carries a cursor at the matching text. A read can use up to 512 UTF-8 bytes of preceding text within its total byte limit, and reads forward from the match. It does not replay the message prefix. Each fragment keeps its message origin, time and evidence location. Neighboring events return their own metadata for separate reads.

One request admits up to 200 read targets and eight open source files, defaults to 8 KiB of text per target, and caps a target at 256 KiB. Responses, including metadata and freshness, have a 1 MiB encoding budget. Location/search pages admit up to 200 results, inspect at most 2,000 message facts and 10,000 partition/frame entries per call, and return bound continuation when scanning remains. Original-file reads default to 8 MiB per request, maximum 16 MiB. Search is literal within supported text parts and can resume across block boundaries; it does not reconstruct delta streams or search non-text content. Source/reader budgets are not a hard process-memory or elapsed-time ceiling. Changed sources can invalidate a cursor and include re-observed history. CLI procedures belong in the [CLI guide](../guides/cli.en.md).

An extended search uses a cooperative five-second slice with at most 50,000 inspected events and 100,000 metadata entries. It keeps one reader and uses the same source byte and response budgets. Visible context reads within one thread and physical source generation. It uses message frame bounds, caches up to 192 frames or 16 MiB of frame encodings, and inspects at most 10,000 frame metadata entries. It returns up to 128 shared neighbor bodies, each capped at 1 KiB. Tool events and message deltas do not count toward the window.

Search compiles up to 16 literal terms of at most 4,096 UTF-8 bytes each. All terms share a source scan and each verified text block. The longest term bounds the retained tail for cross-block matches. A resumed message can reread boundary blocks. Batch reads combine repeated targets with the same evidence, cursor and byte limit before opening the source. Independently located excerpts are verified before grouping exact text within the response. Context and continuation stay with each occurrence. Groups are limited to the current batch and do not affect event or usage counts. A batch returns readable fragments with issues for failed targets. The response budget defers targets that do not fit. A single-target read returns its error directly.

Foreground operations share a file lock before loading indexed facts, so concurrent calls wait without multiplying full query heaps. An interrupted rebuild removes only marked, unpublished directories; complete generations and recovery copies remain. Cleanup item IDs bind the original scope, physical project identity and reviewed conditions.
